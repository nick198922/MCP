# Рев'ю: прискорення `range_events` / `atr` і повільного тесту сита (08.11)

Режим C (код). Дифф: `course_basics.range_events`, `course_s14_ema.atr`, `tests/test_strategy_sieve.py` (workers), `docs/changes/2026-11-08-slow-sieve-test.md`, рядки в `BACKLOG.md` / `HANDOFF.md`.

**Вердикт: approve.** Блокерів нема.

## Що перевірено мною

1. **Еквівалентність читанням.**
   - `range_events`: `lr`/`tr` через `sliding_window_view(...)[:n-w].min/max(axis=1)` дають ті самі значення, що зрізи `[s-w:s]` (min/max лише вибирають значення, NaN поширюється так само). `atr[w-1:n-1]` дорівнює `atr[s-1]` для `s=w..n-1`. Умова пропуску `~(tr-lr > width*a)` лишає рядки з NaN, як стара `if ... : continue`. Умова `(low<lr & c>=lr) | (c<lr)` — це точно «sweep або close<lr» зі старого циклу. Решта (sweep, відхилення, `kmin/kmax`, `pos`-безперервність) перенесена без змін. `n <= w` повертає `[]`, як старий порожній `range(w, n)`.
   - `atr`: два кроки `np.where(x > tr, x, tr)` відтворюють builtin `max(a, b, c)` (перший лишається, заміна лише при строгому `>`). `np.roll(c, 1)` дає `pc[0] = c[-1]`, як старий `b.c[i-1]` при `i=0`. Рекурсія Вайлдера та сама, на Python-float.
2. **Диференційний тест** (`/home/tradedesk/.cache/tradedesk-agents/tmp/difftest.py`, старий код вставлено дослівно з HEAD, `warnings` як помилки): 1500 випадкових рядів (довжина 1..400, NaN у h/low/c, нічиї через округлення, розриви сегментів, дзеркальна сторона, `atr` n = 1/3/14, `w` у {1, 5, 10, 30, 40, n+3}, різні `width_atr/kmin/kmax`). `atr` збігається побайтно (порівняння через `int64`-вигляд, включно з бітами NaN); `range_events` — 18 000 порівнянь `repr`, 47 930 подій, усі однакові. Додатково: `atr`-вхід із NaN/0/inf, `atr` як список, порожні Bars. Нових `RuntimeWarning` нема.
3. **Інваріанти.** Функції чисті, без I/O, без часу; `np.errstate` не змінює результат. Причинність збережена: рішення на барі `s` використовує лише бари ≤ `s` (вікно `s-w..s-1`, `atr[s-1]`) і, як і раніше, `s+1..r` для вирішального бару `r` (події з `r` не відомі раніше за `r`); `cands` і відсів по `r` не чіпали. Існуючі тести причинності проходять.
4. **`make lint`** чисто.
5. **Тести:** 413 passed (62 с) на 20 файлах, що імпортують `range_events` / `atr` (`test_course_basics`, `test_setup_signals`, `test_strategy_sieve`, `test_course_s14_ema`, `test_s14/16/17/28/39/40_modules`, `test_short_setups`, `test_stop_management`, `test_markup`, `test_course_pob`, `test_course_fvg_ob`, `test_sieve_batch13`, `test_deviation_weekly_trend`, `test_ny_midnight_open`, `test_smt_divergence`, `test_analytics_direct_9`) з `-k "not s3_known_result"`. Сам повільний тест я не запускав (≈ 22 с за словами автора).

## Зауваження (не блокують)

1. **Низька.** Опис змін чесно визнає, що знак NaN у `atr` може відрізнятися, коли вхідна ціна вже NaN; у моїх випадках біти збіглися, у реальному кеші NaN нема. Формулювання «біт у біт» у `docs/changes` варто читати з цією поправкою (вона там є).
2. **Низька.** `workers=os.cpu_count() or 4` у тесті: на машині з обмеженою афінністю чи в контейнері `cpu_count()` може завищити число воркерів. Результат від них не залежить (насіння на символ), тож лише ризик повільнішого запуску; за бажанням `len(os.sched_getaffinity(0))`.
3. **Низька.** Нового юніт-тесту на еквівалентність немає (доказ — одноразові скрипти в `/tmp`, у репозиторій не додані). Існуючі тести та `test_s3_known_result_in_sample` покривають результат, але не NaN/нічиї; для регресій на майбутнє можна додати малий тест `atr` / `range_events` проти еталонних значень з NaN. Не вимога цього кроку.
4. **Інформація.** Коментарі в коді довгі, але пояснюють, чому векторизація безпечна; специфікацію `s3_range_sweep.py` (її хеш у реєстрі) не змінено.
