# Запити запису ↔ схема SQLite (пункт 215, продовження 157, 175, 200)

- `scripts/sql_schema_check.py` тепер бере й літерали запису: `INSERT [OR …] INTO`, `REPLACE INTO`, `UPDATE [OR …] t SET`, `DELETE FROM`. Кожен готується `EXPLAIN` на схемі з міграцій у пам'яті (запит не виконується), тож SQLite сам перевіряє таблицю, список колонок `INSERT`, частину `SELECT` в `INSERT … SELECT`, колонки `SET` і `WHERE` (усі, не лише прості), `ON CONFLICT`, `RETURNING`. Повідомлення `table t has no column named c` теж іде як «нема колонки». Нова чиста функція `write_target(sql)` дає (дію, таблицю); у звіті окремий рядок про запис з розбивкою INSERT / UPDATE / DELETE. Динамічні рядки, як і раніше, пропускаються з причиною.
- Тест `tests/test_sql_schema_check.py` (+2, усього 13): норма (`INSERT OR REPLACE` з колонкою пізнішої міграції, `UPDATE … WHERE`, `DELETE`, `INSERT … SELECT`), нема таблиці (`INSERT`, `DELETE`), нема колонки в `INSERT`, у `SET` і `WHERE` `UPDATE`, у частині `SELECT` в `INSERT … SELECT`, різна кількість колонок і значень (інша помилка, не збій), динамічні (f-рядок, `+`, `%`) пропущено, проза «update … set …» не береться; розбір `write_target`.
