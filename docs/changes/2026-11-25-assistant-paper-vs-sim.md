- Картка [асистента](../ideas/IDEA-20261018-assistant.md), рядок 16: паперовий журнал рекомендацій порівнюється з історичною симуляцією. Чиста `analytics.rec_paper.paper_vs_simulation` (правила — в коментарі над нею), поле `vs_simulation` в `assistant_paper_status`, підблок «Порівняння з симуляцією» з «i» у «Паперові рекомендації асистента» на `/journal` (stdlib-копія `rec_sim_compare` у `scripts/dashboard.py`, тест звіряє її з аналітикою). Панель читає `rec_paper` лише для читання.
- Правила зафіксовано 25.11, коли порівнянних угод ще 0 (розрахованих угод методу за ланцюгом нема; перша, id 1, — експірація 27.11), і не підганялися під угоди за тригером чи ручні. Того ж дня їх виправлено за рев'ю критика ([рев'ю](../reviews/2026-11-25-assistant-paper-vs-sim.md)), порівнянних угод так само 0:
  - порівнянні — лише `source = 'method'` з `trigger` NULL або `chain`, статус `settled`; угоди за зміною режиму / подією, ручні й рядки з іншим `source` лише рахуються (`excluded`, зокрема `other`), у статистику не входять;
  - метрика — P&L на 1 BTC структури в частці спота входу (`pnl_pct_spot`), як у звіті 18.10;
  - (а) проти симуляції методу на вході: `method_mean_pct` / `method_q05_pct` — частки ФОРВАРДА входу, переводяться у спот множенням на forward / spot; на угоду — факт мінус очікування і чи факт нижче 5 % квантиля (номінально 5 %). Симуляція бере 0.03 % F на ногу на вході й виході без стелі, тож її очікування нижче приблизно на 0.06 % спота для двох ніг. Це перевірка конвеєра (запис, розрахунок, одиниці), а не методу: очікування завищене відбором;
  - **квантиль на повній втраті:** у купленого стренглу понад 5 % минулих вікон закінчуються нулем, тож q05 симуляції = −(премія + її комісії), а це нижче за найгірший досяжний P&L угоди −`max_loss_per_btc` / spot (премія + вхідні комісії Deribit). Тому «факт нижче q05» для такої угоди неможливий. Такі угоди мають `q05_at_floor` = true, `below_q05` = null, рахуються в `n_q05_at_floor` і не входять у частку. Живцем 25.11 так у всіх чотирьох рядків методу (id 1, 2, 4, 5: q05 на 0.06 п.п. спота нижче дна; id 1 — −1.44 % проти −1.38 %). Стреддл ATM майже ніколи не закінчується нулем, тож його q05 вище дна і перевіряється. Рядок з `risk_basis` `stress_up_30pct` дна не має; рядок без читабельної максимальної втрати рахується в `missing_fields.max_loss`;
  - (б) проти walk-forward H1 зі звіту [2026-10-18](../verification/2026-10-18-assistant-recommendations.md): −0.59 % спота за угоду, 95 % CI [−2.43; +1.51] (блоковий бутстреп), n = 27, у плюсі 30 %, −0.12 R (CI [−0.63; +0.22], медіана −1.0 R); R — `r_study`, та сама формула. Це не той самий експеримент:
    - календар ланцюга: тест вирішував лише в день експірації 40-денного стреддлу, хоч би що обрав метод (`put_skew.chain` по `recs[d]["expiry"]` = експірація `long_straddle` у `scripts/verify_assistant_recs.py`; у сирому виводі угода 2021-04-01 «стреддл ≈ 14 д» має наступне рішення 2021-04-30). Після «без угоди» чи 14-денної угоди тест пропускав ≈ 40 днів. Паперовий ланцюг заходить одразу після експірації своєї угоди й щодня перевирішує, доки метод нічого не обирає (`rec_method.decide`). Тож у папері більше 14-денних угод на одиницю часу, а дні входу обумовлені тим, що вибір є. Через це `by_horizon` показує угоди ≈ 14 і ≈ 40 днів окремо. Межа — смуги експірацій самого методу: тримання ≤ 21 д — смуга [7; 21], ≥ 28 д — [28; 56]. Нового порогу немає; середні в групі — теж від 28. Еталона H1 окремо за строком у звіті немає, тож групи порівнюються лише між собою;
    - інтервал: еталон — блоковий бутстреп, папір — t; на тих самих 27 угодах t-межа +2.35 % проти бутстрепних +1.51 %. `mean_minus_reference` — точкова різниця без власного інтервалу;
    - період і режими: 2021-04…2026-10 проти 2026-10 і далі;
    - премія: Black-76 на форварді тут, інверсні марки на споті в тесті (≈ базис, ~1 %);
    - комісії між H1 і папером НЕ відрізняються: тест рахував ті самі комісії Deribit (`vrp_marks.hedged_book`: вхід 0.03 % спота зі стелею 12.5 %, поставка 0.015 % лише ITM-ніг). Різниця комісій є між симуляцією методу (а) і фактом, вона описана вище;
  - рядок без потрібного поля або зі значенням поза розумними межами (|P&L| > 10 спотів, |R| > 1000, ціни > 1e9 USD, час поза 1970…9999) рахується в `missing_fields` і випадає лише з цього числа;
  - до 28 угод у числі — статус `too_few`: лише кількості й сирі числа по угодах, без середніх, часток, інтервалів і вердиктів;
  - від 28 — **лише опис, не висновок**: середні, частка нижче q05 проти 5 % · n, t-інтервал 95 % лише коли строки угод не перекриваються й усі відомі (інакше `ci_withheld` з причиною). Угоди однаково ділять режими волатильності, а очікування методу завищене відбором (він бере найкращу структуру; H3 у тесті: ρ +0.02), тож це не доказ переваги.
- **Що можуть виявити 28 угод** (потужність 80 %, двобічно 5 %: z = 1.96 + 0.84 = 2.80). SD — зі звіту: t-межа +2.35 % навколо −0.59 % на n = 27 дає SD = (2.35 + 0.59) · √27 / 2.056 = 7.4 % спота (апріорне — 11 %); R-інтервал [−0.63; +0.22] дає SD = 0.425 · √27 / 2.056 = 1.07 R. Звідси:
  - одне середнє проти фіксованого числа (0 або очікування симуляції, парно): 2.80 · SD / √28 = 3.9 % (SD 7.4) … 5.8 % (SD 11) спота, 0.57 R;
  - папір проти H1, обидві вибірки з похибкою: 2.80 · SD · √(1/28 + 1/27) = 5.6 % … 8.3 % спота, 0.81 R;
  - відкрите питання тесту, перевага ≈ +0.2 R: n = (2.80 · 1.07 / 0.2)² ≈ 225 угод ланцюга, тобто ≈ 18 років за сумішшю тесту. Журнал цього за розумний час не розв'яже;
  - частка нижче q05: при p = 5 % і 28 перевірних угодах до 3 нижче — шум (P(X ≤ 3) = 0.95). Від 4 нижче справжню частку 20 % видно з потужністю 84 %, частку 10 % — лише з потужністю 31 %.
  - Числа критика (5.6–8.3 %, ≈ 0.57 R, ≈ 225) перераховано й підтверджено. Уточнення: 0.57 R — це MDE одного середнього; для «папір проти H1» у R виходить 0.81 R.

- **Коли буде опис від 28 угод** (не висновок). Угоди ланцюга не перекриваються: наступна відкривається лише тоді, коли попередня вже експірувала (`rec_method.decide`). Перша (id 1) експірує 27.11.2026, тож потрібно ще 27 циклів. Короткий цикл не буває коротшим за 14 днів. Далі ніж за 3 дні Deribit має лише п'ятничні експірації (перевірено на живому ланцюгу 25.11: щоденні до 28.11, далі 04.12, 11.12, 25.12 …). Коротку експірацію метод бере найближчою до 14 днів у смузі [7; 21] (`collector/assistant_paper.py`, `SHORT_DTE_BAND`). Після поставки в п'ятницю о 08:00 наступна п'ятниця вже < 7 днів, отже береться ≈ 14. З пізнішого входу цикл «поставка → поставка» теж ≥ 14 днів. Довгий цикл триває ≈ 40 днів (смуга [28; 56]). Звідси:
  - щонайраніше — усі 27 угод по 14 днів і жодного дня без вибору: 27.11.2026 + 27 × 14 = **10.12.2027**;
  - за сумішшю тесту (11 з 27 угод ≈ 14 днів, 16 ≈ 40 днів, у середньому 29.4 дня на угоду) і без днів без вибору: 27.11.2026 + 794 дні ≈ **29.01.2029**. Дні без вибору (у тесті 13 з 40 рішень) відсувають дату далі. Центральна оцінка ≈ 2029, діапазон — від 12.2027.
  - Пункт картки лишається відкритим до того. Прочитання на 28 угодах вирішить лише, чи немає грубої розбіжності паперу із симуляцією (≥ ≈ 4–6 % спота) чи з H1 (≥ ≈ 6–8 %). Чи є перевага ≈ +0.2 R, воно не вирішить.
