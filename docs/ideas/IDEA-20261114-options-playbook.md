## Дані — через наш MCP (власник 14.11: «МСР потрібно також використовувати для ідей по опціонам»)
Кожна умова плейбуку має назву **інструменту MCP tradedesk**, яким вона вимірюється (і поле його відповіді), щоб власник міг перевірити ідею тим самим інструментом у чаті, а генератор і MCP ніколи не розходились у числах. Основні: `deribit_dvol`, `deribit_vrp` (DVOL проти RV, рівень DVOL), `iv_rank`, `deribit_atm_term` / `deribit_skew_term` / `deribit_vol_surface` (строкова структура, скью), `skew_percentile` (z-score 25Δ / 10Δ), `deribit_expected_move`, `prob_from_options` / `touch_probability`, `deribit_gamma_exposure` (GEX — евристика), `deribit_max_pain` / `deribit_oi_by_strike` / `calendar_expiries` (експірації, пін), `macro_calendar` (подія до експірації), `cycle_regime` / `market_regime` (тренд, фаза), `perps_funding_compare` / `funding_zscore`, `liquidations_summary`, `deribit_largest_trades` (великі угоди), `strategy_iron_condor` / `strategy_payoff` / `strategy_scenario_matrix` (профіль конструкції). Генератор (пункт 2) викликає ці інструменти в процесі (`build_server()`, як `scripts/calls_check.py`), а не рахує їхні числа заново; умова, якої жоден інструмент не міряє, — кандидат на новий інструмент (окремий пункт BACKLOG з посиланням сюди), а до того правило має статус «не вимірюється».

#### 4.1. P3 (200-денний тренд → вертикальний дебетовий спред): попередня реєстрація (14.11, до будь-якого P&L)
Код: `src/tradedesk/analytics/trend_spread.py` (чисті функції), `scripts/verify_p3_trend_spread.py` (`--stage coverage` — лише покриття, без P&L; `--stage full`). Пороги правила (SMA200, нахил 20 д, |Δ| 0.40 / 0.15, 7–24 д) — із дизайну генератора 14.11, на історії **не підбираються**; варіюються лише наші параметри як чутливість.
- **Гіпотеза H1 (первинна):** правило P3 так, як його надсилає генератор, має додатне очікування після витрат: середній R > 0, де R = P&L / дебет (дебет з комісіями входу = капітал під ризиком; на Bybit маржа купленого дебетового спреду = дебет, тож R — дохідність **на капітал**; додатково — у % спота, тобто на номінал).
- **Вибірка:** BTC (кеш поверхонь `put_skew/snapshots_v2.json` має лише BTC; ETH **не покрито** — для ETH потрібен форвард `option_legs` або окреме завантаження угод Deribit ETH). Входи — щосуботи о 09:00 UTC (поверхня дня; розсилка йде в суботу) від 2021-01-02 до останньої суботи, чия експірація ≤ 2026-10-13 08:00 UTC і має ціну поставки в кеші.
- **Тренд:** рівно `option_ideas.trend(closes, sma=200, slope_days=20)` на денних закриттях Binance BTC/USDT 1d **до п'ятниці включно** (закриття п'ятниці = 00:00 суботи, відоме о 09:00); «bear» → bear put spread, «bull» → bull call spread, «neutral» → угоди нема.
- **Конструкція:** експірація `choose_expiry(snap, 14, 7, 24, rule="nearest")` (від суботи 09:00 — п'ятниця через ≈ 12.96 д); цільові страйки `strike_for_delta` за посмішкою дня: куплена нога |Δ| = 0.40, продана |Δ| = 0.15 далі OTM; кожна нога — найближчий страйк зі свіжою маркою в межах ±1.5 % спота від цілі (правило options-modules), продана строго далі OTM за куплену; інакше угоди нема (рахується в покритті). 1 спред = 1 BTC на ногу.
- **Ціни й витрати:** Bybit історичних цін нема → марки Deribit (поверхня 09:00) з поправкою на спред: куплена нога за mark IV + 1.5 в.п., продана за mark IV − 1.5 в.п. (припущення половини спреду Bybit; Black-76, r = 0, на форварді поверхні, USD); комісії Bybit: тейкер 0.03 % спота, не більше 7 % ціни опціону, на ногу (`option_ideas.fee`) на вході і на достроковому виході; поставка 0.015 % ціни поставки, не більше 12.5 % внутрішньої вартості, на кожну ногу в грошах. Розрахунок — за ціною поставки Deribit (Bybit історично недоступна; обидві — середнє індексу перед 08:00).
- **Вихід:** H1 — до експірації. **H2 (вторинна):** перший денний зріз 09:00 після входу і до експірації, де вартість закриття (куплена за mark − 1.5 в.п., продана за mark + 1.5 в.п., мінус комісії) ≥ дебет + 0.70 × (ширина − дебет) **або** спот пройшов продану ногу → вийти; інакше до експірації. **H3 (вторинна, чи додає щось напрям тренду):** парна різниця R(спред за трендом) − R(дзеркальний спред проти тренду) тієї ж суботи й експірації.
- **IS / OOS (фіксовано):** IS — входи до 2024-01-01, OOS — від 2024-01-01. Параметри на історії не обираються, тож уся вибірка — поза підбором; поділ — перевірка стабільності.
- **Статистика:** середній R по угодах; 95 % CI — кластерний бутстреп, кластер = **трендовий епізод** (найдовша серія сусідніх субот з тією самою міткою; нейтральний тиждень або розворот обривають епізод), 10 000 вибірок, seed 20261114; p — двобічний з бутстрепу. Робастність: блоковий бутстреп по тижнях (блок 4), неперекривна підвибірка (кожен другий вхід). **Холм** — на H1–H3 цього прогону (партія пункту 4 поповнюватиметься; поправка перераховується з кожним новим правилом). **MDE** = 2.8 × SE (кластерна).
- **Ворота покриття:** частка трендових субот (є поверхня, експірація в межах кешу, є ціна поставки), де план спреду знайдено, ≥ 60 %; менше → ◯ UNVERIFIABLE, P&L лише розвідувально.
- **Вердикт H1:** ✓ — CI нижня межа > 0 і p за Холмом < 0.05, OOS-середнє > 0 і середнє при половині спреду 3 в.п. > 0; ≈ — середнє > 0 у всій вибірці, IS і OOS, але CI містить 0; ✗ — CI верхня межа < 0, або середнє ≤ 0 і верхня межа < +0.15 R (перевагу, вартую зусиль, виключено); ◯ — інакше (CI містить 0, верхня межа ≥ 0.15 R: замало даних). Статус правила в плейбуці / `RULES` змінюється, лише якщо вердикт змінює мітку.
- **Чутливість (усі варіанти у звіті, заздалегідь):** половина спреду 0 / 1.5 / 3 в.п.; модель «сторона» (IV тейкерських угод Deribit sell / buy, без принта — mark ± 1.5 в.п.); |Δ| купленої 0.35 / 0.40 / 0.45 × проданої 0.10 / 0.15 / 0.20; ціль експірації 7 / 14 / 21 д (вікно 7–24); вхід у п'ятницю замість суботи; H2 з порогом 0.60 / 0.80; по роках; без 5 найкращих угод. Сторони (bull / bear) — таблиця n, середній R, CI, різниця сторін з CI (гетерогенність) і знак IS → OOS по сторонах (стійкість). Підгрупа, що виглядає добре, — нова картка з механізмом, не висновок цього прогону.
- **Перевірки до прогону:** рівень цін (закриття Binance проти спота поверхні, |різниця| ≤ 2 %), одиниці (IV десяткові, T у роках), фактичні дельти ніг проти цілей, дебет у (0; ширина), мітка тренду на останньому дні проти `option_ideas.check_trend`.
- **Очікувана потужність:** ≈ 150–200 трендових субот, але лише ≈ 10–20 епізодів → MDE, імовірно, ≥ 0.2–0.3 R; імовірний результат ◯.

#### 4.2. P1′ (залізний кондор, умова — рівень DVOL): попередня реєстрація (14.11, до будь-якого P&L)
Код: `src/tradedesk/analytics/condor_dvol.py` (чисті функції; повторно використано `option_condor.strike_for_delta` / `exec_legs`, `option_ideas.fee`, `trend_spread` — константи поставки, `episodes`, `cluster_bootstrap`, `holm_adjust`; `vrp.trailing_percentiles`), тести `tests/test_condor_dvol.py`, `scripts/verify_p1_condor_dvol.py` (`--stage coverage` — лише покриття, без P&L; `--stage full`). Пороги правила (перцентиль 0.8 — з P2; |Δ| 0.15, крило 3 % спота, 7–24 д, ціль 14 — з дизайну генератора 14.11, `option_ideas.iron_condor`) на цій історії **не підбираються**; варіюються лише як чутливість. **Чи вимірюється (перевірено до реєстрації, без P&L):** кеш поверхонь 09:00 (`put_skew/snapshots_v2.json`) тримає на кожну суботу 8–13 експірацій; фронт ≤ 8 д є щосуботи (щоденні 0.96 / 1.96 / 2.96 / 3.96 д і п'ятнична 5.96 д), експірація 21–45 д — у 210 / 302 субот (у решті найближчі до 30 д строки 19.96 і 47.96 д — поза смугою, бо тижневі на 27 д без принтів до 09:00). Застереження: поверхня містить лише страйки зі свіжою маркою (принт ≤ 6 год до 09:00), тому і ATM, і ноги — з угод Deribit.
- **Гіпотеза H1 (первинна):** у суботу 09:00 UTC, коли умова P10 виконана (FOMC / CPI у найближчі 8 д; фронт — перша експірація після події з DTE ≤ 8 д; місяць — експірація з DTE у 21–45 д, найближча до 30; ATM IV фронту − ATM IV місяця ≥ +0.015), **календарний стреддл** — продати 1 стреддл фронту, купити 1 стреддл місяця на тому самому страйку K — і тримати до експірації фронту має додатне очікування після витрат: середній R > 0, R = P&L / дебет (дебет = вартість купленого місячного стреддла − кредит проданого фронтового + комісії входу на 4 ноги; це капітал під ризиком: на дату експірації фронту куплений стреддл коштує не менше за внутрішню вартість проданого, тож збиток ≈ дебет + витрати виходу). Дохідність **на капітал під ризиком**; Bybit маржує проданий стреддл окремо (календар не неттується), тож дохідність на фактичну маржу нижча. Додатково — P&L у % спота (на номінал 1 BTC на ногу).
- **ATM IV (як `deribit_atm_term` → `atm_iv` = посмішка в точці форварду):** `iv_at_strike(x, x["F"])` поверхні (лінійно за ln K/F між свіжими страйками), той самий розрахунок, що `weekly_straddle.atm_iv` / `radar.atm_iv`. Події — `docs/verification/2026-10-15-us-macro-events.csv`, види `fomc`, `cpi`, усі рядки, крім `cancelled`; час ET → UTC з урахуванням літнього часу (`America/New_York`). Подія враховується, якщо 0 ≤ час події − 09:00 суботи < 8 д (як `hours_ahead ≥ 0` у `check_front_inversion`).
- **H2 (вторинна, чи додає щось інверсія):** різниця середніх R(інверсія ≥ +0.015) − R(інверсія < +0.015) того самого календаря на всіх суботах з подією, де умова виміряна (контроль — «подія є, інверсії нема»); `condor_dvol.cluster_bootstrap_diff`, кластер = угода (угоди не перекриваються: кожна живе ≤ 6 д до експірації фронту, а наступний вхід — через 7 д; 4-тижневі блоки перетинали б обидві групи).

Об'єм 0.5 і |Δ| 0.25 — наш вибір із «½–¾» та «кол або стренгл» плейбуку (джерело конструкцію чисельно не задає); 0.75 і |Δ| 0.40 — чутливість.
- **Вибірка:** BTC (кеш поверхонь має лише BTC; ETH не покрито). Суботи 09:00 UTC 2021-01-02 … остання субота, чий фронт ≤ 2026-10-13 08:00 з ціною поставки в кеші. Угоди не перекриваються.
- **Конструкція H1:** K — страйк, свіжий **в обох** експіраціях, найближчий до форварду фронту, у межах ±1.5 % спота від нього; інакше угоди нема (рахується в покритті). Обидві ноги стреддла на K мають ту саму марку IV (одна марка на страйк у поверхні).
- **(а) Статичний арбітраж марок (вимога з рев'ю P12; зареєстровано до P&L):** для кожної марки, що входить у ціну (кожна нога на вході; куплені місячні ноги на виході), на її експірації беруться найближчі свіжі страйки K⁻ < K < K⁺ (крім самого K) і ціни колів Black-76 C(K⁻), C(K), C(K⁺) на марках; умови: (1) монотонність C(K⁻) ≥ C(K) ≥ C(K⁺); (2) вертикаль не більша за ширину (цифрова межа ≤ 1 при r = 0): C(K⁻) − C(K) ≤ K − K⁻, C(K) − C(K⁺) ≤ K⁺ − K; (3) опуклість на кожній трійці сусідніх свіжих страйків, що містить K ((K⁻⁻, K⁻, K), (K⁻, K, K⁺), (K, K⁺, K⁺⁺)): середня ціна ≤ λ · ліва + (1 − λ) · права, λ = (права K − середня K) / (права K − ліва K) (ловить і завищену, і занижену марку K); допуск 1e-6 × F. Пути через паритет на тій самій IV і тому самому форварді дають ті самі умови. **Порушення на вході → заміна марки K лінійною інтерполяцією IV за ln K/F між K⁻ і K⁺ і повторна перевірка; якщо порушення лишається або сусіда з одного боку нема → день пропускається** («арбітраж у марках», у покритті). **На виході** (місячні ноги) — та сама заміна, а якщо вона не допомагає, марка лишається сирою з позначкою «raw» (пропуск за даними виходу був би відбором за результатом); кількість «raw» звітується. Якщо сусід є лише з одного боку, перевіряються умови з ним, опуклість у K — ні («перевірено однобічно», у покритті). `calendar_p10.arb_check` / `clean_iv`. **Календарна умова:** повна дисперсія на K σ²_місяць·T_місяць ≥ σ²_фронт·T_фронт; порушення → день пропускається. Чутливість: «порушення → пропуск дня» без заміни. Покриття звітує: перевірено марок, порушень, замін, пропусків, однобічних.
- **Ціни й витрати:** як 4.1–4.3: марки Deribit (поверхня 09:00), куплені ноги за mark IV + 1.5 в.п., продані за mark IV − 1.5 в.п. (Black-76, r = 0, форвард своєї експірації, USD); комісії Bybit `option_ideas.fee` на кожну ногу (× об'єм) на вході й на виході; поставка проданих фронтових ніг 0.015 % ціни поставки, не більше 12.5 % внутрішньої вартості, на кожну ногу в грошах; розрахунок фронту за ціною поставки Deribit (Bybit історично недоступна). Дебет ≤ 0 → угоди нема (у покритті).
- **Вихід (H1–H3):** фронт — поставка о 08:00 у день експірації; куплені місячні ноги продаються на поверхні 09:00 того самого дня за mark IV − 1.5 в.п. (`iv_at_strike` + перевірка (а)), з комісією. #### 4.5. P5′ (IV rank ≤ 10 % → купівля 60–90-денного ATM-стреддла, H1 LIB DataHawks): попередня реєстрація (14.11, до будь-якого P&L)

Поріг 10 % і строк 60–90 д — з LIB (автор радару), не з нашого прогону; на історії **не підбираються**, варіюються лише як чутливість.
Код: `src/tradedesk/analytics/straddle_p5.py` (нове, чисті функції: `iv_rank_at`, `overlap_clusters`, `plan_straddle`, `settle_straddle`, `hedge_pnl`, `sell_early`, `two_sided_tail_gate`, `verdict`); перевикористано `calendar_p10.clean_iv` / `exec_ivs` / `entry_cost` / `settle_at_front` / `batch_raw_p` / `verdict`, `radar.iv_rank`, `put_skew.choose_expiry`, `condor_25d.tail_gate` / `parametric_tail` / `block_clusters`, `condor_dvol.cluster_bootstrap_diff`, `trend_spread.cluster_bootstrap` / `holm_adjust`, `option_condor.block_bootstrap_mean`; тести `tests/test_straddle_p5.py`; `scripts/verify_p5_straddle.py` (`--stage coverage` — лише покриття, без P&L; `--stage full`).
- **Умова (рівно як `iv_rank` радару, `radar.iv_rank`):** IV Rank денного закриття DVOL BTC = (x − min) / (max − min) по денних закриттях за 365 д, що закінчуються днем x (включно), щонайменше 330 закриттів (`IV_RANK_MIN_DAYS`); x — **останнє закрите** денне закриття на момент входу (свічка попереднього дня: о 09:00 суботи — п'ятнична, закрита о 00:00), без зазирання вперед. ## Механізм
Картка-черга, не гіпотеза: механізм — у кожному правилі плейбуку.

## Очікувана величина і витрати
Апріорі скромно: VRP (IV > RV) у нас ✓, але торгована форма після спредів поки ◯; більшість курсових опціонних тверджень ще не перевірена. Цінність — у тому, що власник щотижня бачить ідеї з чесним статусом доказів, а журнал ідей накопичує форвард-результат.

## Ризики
Підгонка порогів під історію (поріг у плейбуці — з джерела, не з нашого прогону; змінювати — лише через пункт 4 з реєстрацією); множинні правила (Холм на партію); ризик-нейтральні ймовірності — не прогноз.

## Критерій «вбити»
Власник каже «досить», або через 30 розрахованих ідей жодне правило не показує плюс після витрат (тоді повідомлення лишається описом ринку, без «що відкрити»).
