# Код ↔ заявлена версія Python (пункт 158)

- `pyproject.toml`: `requires-python = ">=3.11"`, ruff `target-version = "py311"`. Тест бере межу з `pyproject.toml` і падає, якщо вона розійдеться з ruff або зсунеться з 3.11 (тоді треба переглянути таблиці).
- Новий `tests/test_python_compat.py` (лише stdlib, без мережі, 705 тестів, з них 626 — по одному на файл, щоб xdist ділив розбір; ≈ 12 с на 6 воркерах). Охоплює всі `src/tradedesk/**/*.py` (393) і `scripts/**/*.py` (233, разом із `research/` і `server/`).
  - **Синтаксис:** `ast.parse(..., feature_version=(3, 11))` відкидає `type X = …` і `def f[T]`, але не відкидає f-рядки PEP 701 (перевірено на 3.12 і 3.13). Тому на 3.12+ додано прохід токенізатором: повтор лапок f-рядка всередині `{…}`, `\` у полі заміни, коментар, перенос рядка в полі однолапкового f-рядка. На 3.11 це перевіряє сам парсер.
  - **Імена stdlib, нові після 3.11:** 47 атрибутів і модулів 3.12/3.13 (`itertools.batched`, `Path.walk`, `typing.override`, `copy.replace`, `warnings.deprecated`, `dbm.sqlite3`, `PythonFinalizationError` тощо) і 8 нових іменованих аргументів (`shutil.rmtree(onexc=)`, `Path.relative_to(walk_up=)`, `itertools.batched(strict=)` …). Псевдоніми імпорту розв'язуються через AST. Чотири характерні методи `pathlib` (`walk`, `is_junction`, `with_segments`, `full_match`) ловляться за назвою на будь-якому нерозв'язаному об'єкті, а `os.walk` / `ast.walk` ні. `datetime.UTC` — це 3.11, у список не внесено.
  - **Версії не взято на віру.** Тест звіряє кожен рядок таблиць із поточним інтерпретатором: на 3.11 імені немає, на своїй версії воно є. CI на 3.11/3.12/3.13 перевіряє таблиці щоразу. Локально файл прогнано на 3.11.17, 3.12.3 і 3.13.16, на всіх версіях 705 passed. Фікстури «валідне в 3.11» на 3.11 перевіряє справжній парсер.
