# 2026-11-13 — `positions_close` і `journal_list` на зіпсованих `tags` (пункт 353)

Інваріант 1 `CLAUDE.md`; відкрите з пункту 352 ([зміни](2026-11-13-positions-list-tags.md)).

- **Помилка:** `tags`, вкладений на 300 рівнів (`[[[...]]]`), валив серіалізатор MCP: у `positions_close` уже після запису закриття, у `journal_list` для всього списку. Не-список (`5`, `{}`, `"x"`) і списки з не-рядками поверталися як є.
- **Виправлено:** нормалізацію з `positions_list` перенесено в `tools/_util.py` (`clean_tags`, без змін поведінки) і застосовано в обох інструментах. NaN / Infinity у `tags`: `journal_list` пропускає угоду з попередженням (як і раніше), `positions_close` закриває позицію, але не повертає рядок (попередження тепер прямо називає «NaN / Infinity in tags»). Будь-що інше, крім списку рядків, показується як його рядкові елементи (`"x"` → `["x"]`, решта → `[]`) з попередженням; `ok` не змінюється. Правильні `tags` і `null` без змін і без попереджень.
- Новий `tests/test_tool_failure_extra_20.py` (45 тестів: 11 видів нормалізації, 6 видів NaN / Infinity, 5000 рівнів, правильні та широкі теги без змін, збій сховища — для обох інструментів; для `journal_list` ще «лише нормалізовані рядки → ok» і «лише NaN → ok=false»).
- **Відкрите (пункт 354):** той самий `tags` на 300 рівнів валить `journal_close` після запису закриття (перевірено пробним запуском, не виправлено: поза пунктом).
