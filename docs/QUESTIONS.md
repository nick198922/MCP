# Питання до власника

Агенти додають сюди питання, коли рішення може ухвалити лише власник (напрям, ризик, гроші, нові джерела даних). Відповідайте прямо в полі «Відповідь власника» і змініть статус на `answered`. Поки питання `open`, пов'язана робота стоїть.

Формат:

```
## Q-РРРРММДД-N: коротка назва
Статус: open | answered
Контекст: що з'ясували і чому потрібне рішення.
Варіанти: 1) … 2) …
Рекомендація агентів: …
Відповідь власника:
```

## Q-20261111-1: Wikimedia (перегляди Wikipedia) відмовляє серверу: який контакт дати в User-Agent
Статус: open
Контекст: картка [`wikipedia-attention-xs-spread`](ideas/IDEA-20261111-wikipedia-attention-xs-spread.md), крок 1. Обидва хости Wikimedia (`wikimedia.org/api/rest_v1` Pageviews і `en.wikipedia.org/w/api.php`) відповідають серверу HTTP 403 «Please respect our robot policy» (https://w.wiki/4wJS) на загальний User-Agent `tradedesk-mcp/0.1 (read-only research client; pageviews)`. Їхня політика вимагає в User-Agent контакт (сайт або e-mail); особистих даних без вашого дозволу ми туди не пишемо, обходити не пробували. Провайдер `providers/wikimedia.py` і скрипт готові; без мережі не можна ні скласти мапу монета → стаття (ID сторінок), ні вивантажити перегляди. Попередні ворота потужності за цінами вже пораховано (MDE 0.73 п.п./тиждень за оптимістичного універсуму ≈ 100 монет; поріг 0.8, точка беззбитковості ≈ 84 монети).
Варіанти: 1) дати контакт для User-Agent (наприклад, URL репозиторію або окрему пошту), агент додасть його в `providers/wikimedia.py` через змінну оточення; 2) вивантажити дані самому (один скрипт на вашій машині, якщо там 403 немає) і покласти кеш на сервер; 3) закрити картку як `inconclusive` (дані недоступні).
Рекомендація агентів: 1, через змінну оточення `TRADEDESK_WIKIMEDIA_CONTACT`, щоб контакт не потрапив у git.
