# Ключі API не потрапляють в `evidence`, health і тексти помилок (пункт 162)

- Новий `tests/test_evidence_no_secrets.py` (без мережі, фейкові ключі-маркери `SECRET-MARKER-xyz-…`, не з оточення): Runtime з ключами Coinalyze, CoinGecko і The Graph, `httpx.MockTransport` вимагає ключ у заголовку й не в URL. Перевіряє, що маркера немає в `Fetched.evidence`, у `HealthRegistry.snapshot()` і в `str`/`repr`/`detail` `ProviderError` за відповідей 400/401/402/403/404/429/500, не-JSON 200 і мережевої помилки, коли біржа повертає ключ назад (речення, JSON, дамп заголовків, URL, `Bearer …`); окремо — ключ у query-параметрі (`apikey=`).
- **Знайдено витік:** Coinalyze і CoinGecko підключені без `secrets=`, тому тіло помилки на кшталт `Invalid API key <ключ>` потрапляло в `system_health` (`last_detail`) і в текст `ProviderError` (`redact` ловить лише `api_key=`/`api_key:`). Виправлено в `core/http.py`: `Http` сам додає до секретів значення своїх заголовків із назвами key/token/secret/signature/pass та `Authorization` (токен після схеми, від 6 символів). The Graph і Telegram уже передавали `secrets=` явно, для них нічого не змінилось.
- Перевірка: `make lint`; `uv run pytest -q tests/test_evidence_no_secrets.py tests/test_core.py` — 183 passed.
