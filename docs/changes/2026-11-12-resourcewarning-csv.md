# 2026-11-12 — набір знову без `ResourceWarning` (пункт 351)

Пункт 351 [постійної картки](../ideas/IDEA-20261102-standing-improvements.md), джерело «технічний борг: попередження в тестах».

- **Що знайшли.** Повний прогін 12.11 (`uv run pytest -q -n auto -m "not slow" -W default -r w`: 9686 пройшло, 3 пропущено) дав 1 попередження, хоча з пункту 135 (06.11) їх було 0: `ResourceWarning: unclosed file` у `tests/test_pm_sharp_clv.py:85`. Цей рядок читав фікстуру через `csv.DictReader(path.open(...))` і не закривав файл. Такий самий шаблон знайшовся в чотирьох скриптах: `scripts/calls_hourly.py` (`main`) і `load_events` у `verify_weekend_vol.py`, `verify_event_straddle.py`, `verify_pre_event_vol.py`.
- **Що змінено.** Ці п'ять місць тепер читають файл через `with`. Решта коду не змінювалась: `src/` і `execution/` не чіпали, асерти наявних тестів ті самі.
- **Тест.** Новий `tests/test_scripts_events_csv_closed.py`: усі три `load_events` на справжньому `docs/verification/2026-10-15-us-macro-events.csv` не дають `ResourceWarning`. До правки скриптів тест падав (3 failed), після неї проходить. Вихід `load_events` до і після правки той самий: sha256 від `repr` збігся для всіх трьох.
- **Як перевірити.** `uv run pytest -q -W default tests/test_pm_sharp_clv.py tests/test_scripts_events_csv_closed.py` дає 0 попереджень. Зачеплені файли тестів (`test_scripts_events_csv_closed`, `test_pm_sharp_clv`, `test_trade_replay`, `test_pre_event_vol`, `test_common_helpers`, `test_scripts_import_safe`) пройшли з `-W default` так: 166 пройшло, 0 попереджень. `make lint` чистий.
- **Що свідомо не зроблено.** Правило `filterwarnings = error::ResourceWarning` у `pyproject.toml` не додано. На Python 3.13 (одна з версій CI) з'явилися `ResourceWarning` для незакритих з'єднань SQLite, і без повного прогону на 3.13 таке правило може зламати CI. Ruff `SIM115` цей шаблон не ловить: перевірено, `ruff check --select SIM115` (зокрема з `--preview`) на старому коді показав «All checks passed».
