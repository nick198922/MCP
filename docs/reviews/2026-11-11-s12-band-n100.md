## Зауваження

1. **(низька, процес) Реєстрація і прогін в одному кроці, ще без окремого коміту.** З 03.11 реєстрацію комітять окремим прогоном. Тут обидві частини потраплять в один коміт. Звіт (розділ «Метод», «Порядок») і реєстрація відхилення чесно називають. За суттю воно нешкідливе: усі параметри вже були закомічені раніше (Q-20261109-1, CHECKPOINT 02.11, код n 30), тож блокером я це не вважаю. Виправлення: у тексті коміту написати, що реєстрація пункту 318 закомічена разом із результатом за завданням координатора, і послатися на ці два коміти як на фактичну реєстрацію. Надалі координатору не ставити кванту реєстрацію й прогін в один крок, навіть коли вільних параметрів немає.

2. **(низька, точність формулювання) Числа «i.i.d. звужується лише в 0.60 раза: 0.462 → 0.278» не виводяться з таблиці звіту.** З надрукованих перцентилів для i.i.d. маємо: p50 − p5 = 0.418 → 0.240 (0.574), p95 − p50 = 0.518 → 0.278 (0.537), півширина (p95 − p5)/2 = 0.468 → 0.259 (0.553). Усе це близько до √0.3 = 0.548, тож i.i.d.-смуга поводиться майже як √n. Пояснення «частина — асиметрія R» тоді не підтверджене, і все повільніше звуження ковзної (0.645) лягає на кореляцію сусідніх угод. Ковзні числа 0.735 → 0.474 (0.645) правильні. Виправлення: замінити речення на перевірні числа (наприклад, «i.i.d.: p50 − p5 0.418 → 0.240, у 0.57 раза, ≈ √0.3») і позначити пояснення про кореляцію як гіпотезу (дослідницьке). На число порогу це не впливає.

3. **(низька, повнота) Нова смуга n 100 у `DEMO` змінює і загальне правило демо для S12, а не лише блок «S12: правило зняття».** `decision_band` для рядка S12 (лише v9) при n ≥ 100 тепер бере −0.524 … +0.652 замість −0.827 … +1.095. Так і має бути за CHECKPOINT («смуга найбільшого порахованого n′ ≤ n»). Але change-запис пише «Вплив зараз: жодного» тільки про вхід v4 і цього не згадує. Виправлення: одне речення в `docs/changes/2026-11-11-s12-v4-band-n100.md` про те, що рядок S12 загального правила при ≥ 100 угодах v9 також звіряється зі смугою n 100. За бажання додати тест на `demo_forward` для S12 на n 100 (`n_ref == 100`, межі −0.524 / +0.652).

4. **(інфо) Таблиця «Смуги n 50 / 100» у CHECKPOINT не має рядка S12.** n 50 для S12 не рахували. Між 50 і 99 угодами загальне правило бере ширшу смугу n 30, тобто консервативну. Нічого не ламається, а абзац над таблицею відсилає до звіту. Дописувати не обов'язково.

5. **(інфо) Похибка самого p5.** Звіт чесно каже, що незалежних вікон по 100 лише ≈ 88 (8829 / 100) і p5 має похибку в кілька сотих R. Різниця з оцінкою −0.50 (0.024R) лежить у межах цієї похибки. Тому заміна стосується не точності, а того, що число тепер узято з бази за зареєстрованим правилом. Так і сформульовано, вердикт «≈» доречний.
