# 2026-11-20 · Звірка S3 з паспортом: тіньові плани на cutoff (пункт 428)

Пункт 428 [постійної картки](../ideas/IDEA-20261102-standing-improvements.md), зауваження 2 [рев'ю s38-cutoff-counters](../reviews/2026-11-20-s38-cutoff-counters.md).

- **`scripts/verify_s3_demo_vs_passport.py`: нові `--cutoff YYYY-MM-DDTHH:MM` і `--db`.** З `--cutoff` розділ «Невиконані сигнали … на cutoff» рахується з БД (лише читання, `demo_vs_backtest.load_not_executed`) так само, як у `verify_s12_…`: рішення на cutoff і після нього відкинуто, `demo_shadow` отримує `now_ms = cutoff`, тож план, закритий після cutoff, рахується відкритим. Повтор на тому самому cutoff дає той самий розділ, хоч би коли зроблено JSON і прогін.
- **Без `--cutoff` нічого не змінилось:** розділ береться з JSON `demo_vs_backtest.py` на час його прогону. Закриті угоди й решта звіту в обох режимах беруться з JSON. Cutoff на них не діє, про це сказано в `--help`.
- Тести: новий `tests/test_verify_s3_demo_vs_passport.py`. Два JSON з різним часом прогону, а між прогонами в БД план закрито після cutoff і додано рішення після нього. Розділ однаковий: `n 2, з R 1, відкрито 1`. Пізніший cutoff рахує план закритим. Окремий тест перевіряє, що без БД розділ друкує причину й не падає. `execution/` не чіпано.
