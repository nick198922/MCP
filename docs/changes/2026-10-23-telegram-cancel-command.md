- Скасування угоди з Telegram: `/cancel 12` або `/cancel #12 note …` (`нотатка`) у темі «💬 Claude» (лише власник, та сама перевірка групи, теми й `from.id`) позначає відкриту угоду журналу скасованою — так само, як `journal_close cancelled=true`: статус і результат `cancelled`, без виходу, P&L і R. Скасовані угоди не входять у статистику журналу й у відкритий ризик правила 2.
- Запис умовний (`WHERE id = ? AND status = 'open'`, перевірка кількості змінених рядків): невідомий id, уже закрита чи скасована угода, рядки демо-бота (теги `auto`, `demo-paper`, `bybit-demo`) — відмова, журнал не змінюється. Нової бази не створює.
- Розбір — чиста `analytics/cancel_command.py`, сувора: після id дозволено лише нотатку, тож `/cancel 12 86000` (сплутаний з `/close`) — відмова з форматом. Нотатка без керівних і bidi-символів, до 1000 знаків, у відповіді екранована.
- Міст `scripts/tg_bridge.py` запускає `scripts/journal_cancel_tg.py` через `uv run --frozen`, текст — одним аргументом без shell; `/cancel` у `/help`. Відповідь `/trade` підказує й `/cancel ID`. Жодних ордерів: лише один рядок локального журналу.
