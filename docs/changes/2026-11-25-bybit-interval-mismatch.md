# 2026-11-25 — розбіжність двох джерел інтервалу funding Bybit у журналі циклу carry B (пункт 462)

- **Що записується.** У паперовому carry B фід (`collector/carry_paper_feed.interval_mismatches`) порівнює для кожного символу, який B справді використовує (всесвіт разом з утримуваними, і рядок дійшов до рушія), інтервал ccxt (`interval`, «8h», зі списку ринків на старт процесу) з власним полем тікера Bybit `info.fundingIntervalHour` («8», рядок годин) у тій самій bulk-відповіді. Якщо обидва валідні й різні, у payload циклу з'являється поле `interval_mismatches`: `[{"symbol", "venue": "bybit", "ccxt_hours", "ticker_hours"}]` (години). Порожнього поля немає, тож цикли без розбіжності записуються так само, як раніше.
- **Що ігнорується.** Відсутнє поле, `bool`, NaN, ±inf, 0, від'ємні, нечислові значення, «8h» у полі тікера, значення поза 1 хв – 24 год (з будь-якого боку) не порівнюються й не записуються. Символ поза всесвітом і не утримуваний, рядок, якого рушій не отримав (ставку відкинуто), Binance і стратегія A не перевіряються.
- **Чому не прапорець.** Рушій ставить `complete = not flags`, а частка повних циклів — зареєстрований критерій (д). Розбіжність не заважає циклу пройти на звичному вході: рушій, як і раніше, отримує інтервал ccxt (пріоритет у `current_funding` не змінено). Прапорець зробив би такі цикли неповними посеред форварду й змінив би те, як міряється (д). Тому запис іде окремим діагностичним полем, а не в `flags`.
- **Рушій.** Змінено лише передачу: нове поле `FeedData.interval_mismatches` (за замовчуванням порожнє) і один рядок, що кладе його в payload, коли воно не порожнє. Рішення, `flags`, `complete`, `intervals`, позиції, записи журналу, правила, параметри, `params.hash()`, реєстрацію й минулі цикли не змінено. Міграції схеми немає: payload — JSON у наявній колонці.
- **Як читати.** Окремого лічильника в `paper_carry_status` не додано: це змінило б вихід інструмента разом з описом, README і PARITY, тобто не кілька рядків. Читати з бази (лише читання): `SELECT cycle_ts, json_extract(payload, '$.interval_mismatches') FROM cp_cycle WHERE strategy = 'B' AND json_extract(payload, '$.interval_mismatches') IS NOT NULL ORDER BY cycle_ts;`.
- **Жива перевірка 25.11 (лише читання; скрипт поза клоном через `Runtime` і код фіду).** Свіжий процес: всесвіт B — 458 символів, рядок Bybit у рушія є для всіх 458, обидва джерела валідні на всіх 458, розбіжностей 0. Свіжий процес завантажує свіжий список ринків, тож розбіжність тут і не очікувалася: вона можлива лише в процесі колектора, що працює довше, ніж минуло від зміни інтервалу. Останній цикл B у базі (`mode=ro`, 25.11 16:00 UTC, git d26b6931, повний): записані ним Bybit-інтервали 5 символів (утримувані й кандидати) збігаються з живим полем тікера, розбіжностей 0.
- **Тести:** `tests/test_carry_paper_live.py`. На реальному зразку `bybit_funding_rates_stale_markets_2026-11-25.json`: рівні джерела → нічого; тікер «4» при ccxt «8h» → запис `8.0 / 4.0`; символ поза всесвітом і рядок, якого рушій не отримав → нічого; сміття в полі тікера чи в інтервалі ccxt → нічого. Повний цикл B через `run_cycle` з різним і рівним полем тікера: payload відрізняється лише полем `interval_mismatches`, а вхід рушія (`current`, інтервал 8.0), `flags`, `complete` (True), позиції й записи журналу ідентичні. Мутаціями перевірено, що тест падає, якщо запис іде в `flags` або якщо рушій отримує інтервал тікера. На старому коді тести падають (немає `interval_mismatches`).
- **Сторож «годинникових бомб».** Назва нового зразка з датою зробила файл тестів підозрюваним для `test_clock_bombs`; у двох старих тестах того ж файла годинник тепер зафіксовано (`now = lambda: NOW`).
- **Користь для 30.11:** від деплою журнал циклу B показує поіменно, коли інтервал ccxt, за яким рушій рахує очікувані виплати, розходиться з живим полем Bybit. Минулих циклів це не покриває: чи пов'язані прапорці IRYS 20–21.11 із застарілим інтервалом, звідси не встановлено. Якщо до розбору з'являться записи, буде видно, які прапорці пропущених виплат припадають на символи з розбіжністю, а які ні; сам збіг прапорця з розбіжністю ще не доводить причину, а прапорець без розбіжності не доводить дірки в даних біржі. Відсутність записів означає лише, що в записаних циклах серед використовуваних символів із двома валідними значеннями розбіжності не було: між циклами, у пропущених циклах і без поля тікера запису так само не буде.
