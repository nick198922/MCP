# Питання до власника

Агенти додають сюди питання, коли рішення може ухвалити лише власник (напрям, ризик, гроші, нові джерела даних). Відповідайте прямо в полі «Відповідь власника» і змініть статус на `answered`. Поки питання `open`, пов'язана робота стоїть.

Формат:

```
## Q-РРРРММДД-N: коротка назва
Статус: open | answered
Контекст: що з'ясували і чому потрібне рішення.
Варіанти: 1) … 2) …
Рекомендація агентів: …
Відповідь власника:
```

## Q-20261106-1: який поріг «великого збитку» для правила «48 год перерви»
Статус: answered (10.11, тема «💬 Claude»)
Контекст: правило 4 (`docs/knowledge/trading-strategy.md`) каже «після дня з великим збитком — 48 год перерви», порогу не називає. Реалізовано буквально: день UTC із закритим P&L ≤ −2 % депозиту, перерва з 00:00 UTC наступного дня на 48 год ([зміни](changes/2026-11-06-rule-48h-break.md), [рев'ю](reviews/2026-11-06-rule-48h-break.md)). На журналі це 21 такий день, порушень правила 4 стало 134 замість 60.
Варіанти: 1) лишити −2 %; 2) інший поріг (параметр `big_loss_pct`); 3) інший початок перерви (від моменту збитку).
Рекомендація агентів: 1, поки власник не назве свій поріг.
Відповідь власника: Варіант 1

## Q-20261109-1: що робити з S12 на демо після звірки з паспортом
Статус: answered (10.11, тема «💬 Claude»)
Контекст: звірка 09.11 ([звіт](verification/2026-11-09-s12-demo-vs-passport.md)): 35 закритих угод S12. Вхід v4 (v4 + v9, 31 угода): середнє −0.086R [−0.58; +0.36] — ✓ усередині смуги бази v4 (−0.44 … +0.50), переваги не показує; без топ-5 угод −0.61R. Сама v9: 26 угод, +0.052R [−0.48; +0.53], поріг 30 ще не досягнуто. Виконання відтворює бектест (рівні й виходи збігаються, вхід не гірший за закриття свічки). Зареєстрована умова для зміни виконання спрацювала на комісіях: демо платить на 0.013R [0.007; 0.018] на угоду більше за модель (35 угод, разом 0.44R), майже все через 13 запасних тейкерних входів (мейкер за 2 год не заповнився). Зміну не пропоную, бо ціна мала (≈ 0.36R на 35 угод), а альтернатива запасному входу — пропуск угоди, і її вигоди не виміряно (тейкерні угоди: демо −0.40R, бектест −0.55R, n 13 — шум); це рішення, а не результат тесту. **BEAM (v9) відкрита 02.11 08:06 UTC, утримання S12 4h (168 год) минуло 09.11 ≈ 08:06, а запис досі `open` без `exit_ts`: вихід за часом не спрацював або запис застарів.** Власнику — перевірити позицію BEAM на демо-рахунку; розробнику — чому не спрацював вихід за часом (`execution/`, агенти не чіпають). Окремо: у POWR 01.11 P&L журналу (+0.26R) не узгоджується з ціною виходу (−0.90R) — часткове закриття, ціна виходу з першого рядка closed-pnl (рекомендація 1 звіту 02.11, `execution/`).
Варіанти: 1) тримати S12 v9 на демо як контроль виконання з правилом зняття: на 30 угодах v9 середнє нижче −0.83R (нижня межа ковзної смуги бази v4 для n 30) → зупинити й розібрати виконання; на 100 угодах із входом v4 середнє нижче нижньої межі ковзної смуги бази v4 для n 100 (≈ −0.50R, перерахувати до перегляду) → зняти; інакше тримати (перевагу так не довести); 1а) те саме, але вимкнути для S12 запасний тейкерний вхід (без заповнення мейкером — пропуск); 2) зняти S12 з демо (на історії база v4 ≈ 0, OOS −0.009R); 3) повернути v7 (лімітка на середині FVG) — на історії теж ≈ 0 (OOS −0.004R), підстава не підтвердилась.
Рекомендація агентів: 1.
Відповідь власника: Варіант 1
