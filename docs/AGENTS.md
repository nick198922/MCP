# Команда агентів

Агенти розвивають проєкт уночі без участі власника: по одному кроку за ніч, кожен результат — окрема гілка `agent/…` і PR, який приймає лише власник. Власник задає напрям і відповідає на питання.

## Ролі

| Агент | Модель | Що робить | Чого не робить |
|---|---|---|---|
| `scout` (скаут) | Sonnet | Шукає ідеї стратегій для опціонів і ф'ючерсів крипти (дослідження, біржі, наші дані) і розбирає матеріали з бібліотеки власника (`docs/library/`), пише картки в `docs/ideas/` | Не кодує, не тестує |
| `quant` (квант) | Opus | Тестує прийняту ідею: попередня реєстрація гіпотези, бектест, звіт у `docs/verification/` | Не робить інструментів MCP |
| `builder` (розробник) | Sonnet | Робить один пункт `BACKLOG` або інструмент на підтвердженому результаті | Не вирішує, що варте уваги |
| `critic` (критик, вето) | Opus | Тріаж ідей, рев'ю досліджень і коду, звіти в `docs/reviews/` | Не пише код і ідей |
| координатор | Sonnet (`TRADEDESK_AGENTS_COORDINATOR_MODEL`) | Обирає один крок за прогін, видає завдання агентам, пише підсумок | Не приймає PR |
| лікар (`.claude/doctor.md`) | Opus (`TRADEDESK_DOCTOR_MODEL`) | Запускається сам при збої і щодня о 09:00: шукає причину в логах, виправляє код і віддає PR `agent/…-fix-…`; що потребує root — скриптом у `scripts/server/` | Не послаблює запобіжників, не зливає PR |

Визначення агентів: `.claude/agents/*.md`, інструкція координатора: `.claude/nightly.md`.

## Конвеєр

ідея (`proposed`) → тріаж критика (`accepted` / `rejected`) → тест кванта → рев'ю критика (`confirmed` / `rejected` / `inconclusive`) → інструмент від розробника → рев'ю коду критиком → PR → власник. Картка з рядком `Пріоритет: власник` іде першою в черзі (власник: «дай агентам … першим»). Крок, що чекає на час (наступний замір форвард-спостереження), агенти **відкладають** (`.agent/next` = `park` і час у `.agent/not_before`): лаунчер зберігає гілку, бере інші кроки, а коли час настає — продовжує відкладений. Чекати в сесії довше ~30 хв не можна (16.10 крок negRisk простояв так понад 6 год, блокуючи чергу).

Порядок вибору кроку: новий матеріал у бібліотеці власника (`docs/library/`: пости, статті, відео) → скаут робить з нього картки; прийнята ідея → тест кванта (спершу ідеї з бібліотеки); підтверджена ідея → інструмент; менше двох ідей у роботі (з урахуванням ще не прийнятих гілок) → скаут; інакше пункт `BACKLOG` → розробник → критик → PR. У роботі одночасно не більше двох гілок агентів: поки власник не розібрав PR, нова робота не починається.

## Роль власника

1. **Візія і пріоритети** — розділ нижче; агенти читають його щоночі.
2. **Питання** — `docs/QUESTIONS.md`: агенти пишуть туди, коли рішення лише ваше; ви відповідаєте, коли зручно. Пункти, що чекають відповіді, пропускаються.
3. **PR** — ранковий підсумок лежить у `docs/agents/runs/РРРР-ММ-ДД.md` у гілці агента і в лозі; ви приймаєте PR або закриваєте його з коментарем.

Нижче — запуск на Mac (історичний варіант, вимкнено після переносу):

- Вручну: `scripts/nightly_agents.sh` (повний крок) або `scripts/nightly_agents.sh --dry-run` (лише план, без змін).
- За розкладом: `scripts/install_nightly_agents.sh` ставить launchd-задачу на 02:30 щоночі. Вимкнути: `launchctl bootout gui/$(id -u)/com.tradedesk.agents`.
- Агенти працюють в окремій копії репозиторію `../tradedesk-agents` (git worktree), ваша робоча тека не зачіпається.
- Логи й підсумки: `~/Library/Logs/tradedesk-agents/`.
- Розмова агентів (що координатор доручив, що кожен агент робив і відповів, рішення критика): `uv run python scripts/agents_transcript.py` (останній прогін) або з id сесії; сирі записи — `~/.claude/projects/-Users-nick-MCP-tradedesk-agents/`.
- Git-доставку робить скрипт, а не модель: агенти лише індексують зміни і пишуть у `.agent/` назву гілки й повідомлення; скрипт приймає лише гілки `agent/РРРР-ММ-ДД-…`, ще раз проганяє lint і тести, комітить і пушить. Так ваші глобальні правила «питати перед `git commit`/`git push`» лишаються недоторканими.
- PR створюються через `gh`, якщо він встановлений і авторизований (`brew install gh`, `gh auth login`); інакше в підсумку є посилання «створити PR».
- Кожен прогін витрачає ліміт вашого плану Claude.
