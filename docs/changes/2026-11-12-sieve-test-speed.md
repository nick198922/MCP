# 2026-11-12 · Повільний тест сита S3: виграшу ≥ 15 с у межах `tests/` немає (пункт 350)

Пункт 350 [постійної картки](../ideas/IDEA-20261102-standing-improvements.md). Код тестів, `src/` і `scripts/` не змінено. Пункт закрито записом заміру.

- **Замір** `uv run pytest -q tests/test_strategy_sieve.py --durations=5 -k s3_known` (6 ядер, без xdist): **28.5 с до, 28.5 с після** (змін немає). 59.9 с у повному `pytest -n auto` 12.11 — це конкуренція: 6 воркерів xdist і пул сита з 6 процесів ділять 6 ядер.
- **Де йде час:** `run_all` займає 29.3 с, обидва bootstrap-підсумки з `n_boot=2000` — 0.24 с. Зменшення `n_boot` нічого не дає. Профіль `run_symbol` на 30 символах в одному процесі: перевірка причинності 45 %, читання JSON 1h-кешу 24 %, симуляція угод 23 %. Усе це код `scripts/sieve.py` і `src/`, не тесту.
- **Спільної фікстури нема з чим ділити:** повний `run_all` по `s3_range_sweep` рахує лише цей тест. `test_s3_trades_equal_the_stop_management_study` бере тільки BTCUSDT, з прихованим періодом і без фандингу. У `tests/test_sieve_*.py` ні `s3_range_sweep`, ні `run_all` не трапляються (перевірено grep).
- **Відкинуті варіанти:** кеш результату на диску чи вимкнення причинності прискорили б тест, але послабили б перевірку: `n_bad == 0` на реальних даних і перерахунок після змін у коді. Порядок «великі символи першими» дає ≤ 1.5 с: хвіст пулу короткий, 14 останніх символів займають 3 с.
- **Довідково:** тест має маркер `slow` і вже не входить у `make test` (`-m "not slow"`). 59.9 с бачить тільки простий `pytest -n auto`. Результат IS без фандингу: n = 12228, середнє −0.060R (межа ±0.03 від −0.046 тримається із запасом 0.016), верхня межа CI −0.027 < 0.
- Якщо тест таки треба прискорити, це робиться лише в `src/` / `scripts/` (дешевша перевірка причинності, бінарний 1h-кеш). Це окремий пункт, не тестовий.
