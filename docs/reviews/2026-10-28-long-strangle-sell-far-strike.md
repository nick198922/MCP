## Вердикт: `request changes`

Статус картки має бути **`inconclusive`**, не `confirmed`.

Розрахунки чисті й відтворюються. Але `confirmed` читається як «безкоштовна нога працює», а дані цього не показують:
- H2 ✓ на колах дає правило тригера (денне закриття ловить медіанний рух 4.3 %), а не механізм із тези. Зареєстрована модель при незмінній IV сама дає 1.024.
- На путах ✓ виконано лише за буквою правила: CI [0.846; 0.984] містить поріг 0.90. Після витрат, без 5 найбільших і у 2024–26 R нижче 0.90.
- Сценарій автора (рух 3–4 %) дає 0.77 / 0.69. Це дослідницький результат, але саме він стоїть у назві картки.
- H1 ◯.

Зареєстровані маркери у звіті лишаються. Змінюються статус картки, рядок статусу і формулювання в базі знань (блокери 1–3).

## Знахідки

### Блокери

1. **Статус `confirmed` не відповідає змісту результату (висока).**
   - Картка до тесту сама писала (рядок «Гіпотеза»): «H2 підтверджується лише за реальної реакції IV». Зареєстрований контроль цю логіку спростував. На колах R_mod при незмінній IV = 1.024 [0.955; 1.083], а Δ = +0.016 [−0.010; +0.044]. Тобто ✓ на колах виникає без IV-реакції: тригер по денному закриттю відбирає рухи 4.3 % у медіані, і у 21 з 166 рядків рух ≥ 7 % (там R = 1.85).
   - Отже H2 у такому вигляді перевіряє не «безкоштовність» на рівні, а розподіл розміру руху на день тригера.
   - На путах IV-реакція справжня (+3.1 вп, Δ +0.071 [+0.045; +0.100]), але мала.
   - **Виправлення:** статус картки `inconclusive`. Рядок статусу переписати приблизно так: «H2 за буквою реєстрації ✓ (1.04 / 0.91), але це наслідок розміру руху на день тригера (модель без IV дає 1.02 / 0.84). На путах поріг 0.90 у межах CI, після витрат 0.84. Сценарій автора (3–4 %): 0.77 / 0.69, дослідницьке. IV-реакція лише на путах, +3 вп. H1 ◯».

2. **Путовий бік: ✓ лише за буквою правила, і правило слабке (висока).**
   - Зареєстроване правило ✓ (середнє ≥ 0.90 і нижня межа ≥ 0.75) ставить ✓, навіть коли CI містить 0.90. Отже воно доводить лише «не нижче 0.75», а не «≥ 0.90». На путах середнє 0.913 лише на 0.013 вище порогу при MDE 0.095.
   - Кожна зареєстрована перевірка стійкості опускає пут нижче 0.90:

     | Перевірка | R пут |
     |---|---|
     | без 5 найбільших | 0.859 [0.801; 0.914] (за тим самим правилом це ≈) |
     | R_net 1.5 вп | 0.844 |
     | 2 вп | 0.822 |
     | 3 вп | 0.781 |
     | FOMC | 0.867 |
     | 2023 / 2024 / 2026 | 0.83 / 0.85 / 0.85 |
     | медіана | 0.825 |

     R ≥ 0.9 має лише 33 % епізодів.
   - Звіт усе це чесно показує («✓ крихкий»), але в картці й базі знань лишилося «✓».
   - **Виправлення:**
     - У «Коротко» і таблиці вердиктів звіту біля путового ✓ дописати: «за буквою правила; CI містить 0.90; після 1.5 вп 0.84».
     - Рядок `docs/knowledge/README.md` змінити: `картка confirmed` на `картка inconclusive`, а «✓ за реєстрацією» на «✓ за буквою реєстрації (кол), пут ≈ на практиці».

3. **H1 сформульовано сильніше, ніж дозволяють дані (середня; блокер, бо потрапляє в базу знань).**
   - Тексти, яких дані не підтримують:
     - картка: «очікування не змінюється, edge немає»;
     - звіт: «Правило змінює форму, а не очікування»;
     - `options.md`: «продаж у нетригерний день дає те саме».
   - Що кажуть дані:
     - На путах (г) − (а) = +0.86 % S_T [−0.30; +1.67].
     - Коротка нога проти контролю: +1.09 % [−0.28; +2.15].
     - MDE контролю ≈ 1.5–2 % спота.
   - Тобто тест нічого не розрізнив, а не показав «те саме». Натяк на путах збігається за знаком з IV-реакцією +3 вп.
   - **Виправлення:** скрізь замінити на «різниця в очікуванні не розрізнена (◯; MDE ≈ 1.5–2 % спота); на путах точкова оцінка +0.86 % S_T, CI через 0».

4. **`docs/knowledge/setups.md`: дослідницькі числа без позначки, і для путів вони неточні (середня).**
   - Рядок «≈ 0.9–1.0 купленої лише після руху на 4–5 %+; на 3–4 % ≈ 0.7–0.8» взято з розбивки за рухом, яку додано після перегляду середніх. Для путів кошик 4–5 % дає 0.81, а ≈ 0.94 (медіана 0.89) з'являється лише при 5–7 %.

   - Те саме позначення додати до «При русі 3–4 % … 0.77 / 0.69» в `options.md`.

### Не блокери

5. **Час реєстрації з git не перевірити (середня, процес).** Розділ «Попередня реєстрація» не закомічено: у git є лише коміт тріажу `1b63f49`. Хеш доводить лише, що текст не змінювався між прогоном стадії 0 (04:02) і повним прогоном (04:04). Він не виключає незбережених ранніх прогонів. Код (`strangle_manage.py`, скрипт) змінено о 04:07, уже після `result.json`, але мій перезапуск дав ідентичні числа, тож на результат ця зміна не вплинула. **Виправлення на майбутнє:** координатор комітить розділ реєстрації окремим комітом до стадії 1 (або квант кладе хеш у закомічений файл до прогону).

6. **Витрати: марки, а не виконувані ціни (середня).** Bid/ask немає, 1.5 вп на крилі ±8 % при DTE ≈ 15 д — лише припущення. Власник торгує на Bybit, де спред на крилах ширший. Тому практична відповідь для путів — R_net 0.78–0.84, тобто «безкоштовно» не виходить. **Виправлення:** у рядку статусу і в `options.md` наводити R_net поряд з R.

7. **Варіант (в) H1 продає страйк, якого немає в лістингу (низька, описове).** `ks2 = S_T·1.12` не прив'язано до сітки страйків, ціна йде з інтерпольованої IV. Купівля K_s у вертикалі йде за `iv_at_strike(eD, ks)`, а не за свіжою маркою `iv_s`. Варіант описовий, на вердикт не впливає. **Виправлення:** `pick_strike` для ks2 і `ep["iv_s"]` для K_s, або згадати це в застереженнях.

8. **Покращення CVaR 5 % механічне (низька).** Продаж OTM-опціону з премією піднімає нижній хвіст на розмір премії майже за побудовою. «✓ (форма)» у таблиці вердиктів не є доказом цінності правила. Звіт це визнає («очікувано»). У базі знань варто подати як властивість конструкції, а не як результат тесту.

9. **Вибір K_s серед свіжих страйків у смузі ±1.5 % (низька).** Звіт це вже згадує. Медіанна відстань 7.9 % від S_T, тому зсув малий. Перевірку на фіксованій moneyness (`iv_at_strike` на 0.92 / 1.08 S_T) можна додати, якщо картку колись відкриють знову.

## Пункти чекліста

1. Реєстрація: хеші збігаються (перевірено), але коміту до результатів немає (п. 5).
2. Lookahead: немає, є тест (перевірено).
3. Всесвіт: один актив, історичні експірації. Survivorship немає.
4. Дані: днів без пропусків (скрипт падає на пропуску), delivery на 08:00, одиниці правильні (перевірено за кодом і тестом `test_leg_value_is_black76_usd`).
5. Множинність:
   - Чутливості зареєстровані, розбивка за рухом позначена як дослідницька.
   - Два боки без поправки, і як вони разом дають статус картки, не визначено. Через це путове ✓ ще слабше.
6. Витрати: п. 6. Номінал проти капіталу у звіті вказано правильно; маржу не моделювали.
7. Стійкість: зроблено повністю. Вона й показує крихкість путів (п. 2).
8. Числа звіту = сирий вивід (перевірено перезапуском).
9. Формулювання: п. 1–4.
