# Безпека

Поточна версія (0.1.0) читає лише публічні дані й не потребує ключів. Нижче правила, які діють з появою ключів і ордерів.

## Ключі

- Секрети лише в змінних оточення або менеджері секретів. `.env` у `.gitignore`, у репозиторій не потрапляє нічого з ключами.
- Для бірж створювати **окремі ключі під цей сервер**: дозвіл на торгівлю, **без права виведення коштів**, з **IP allow-list** (IP вашого сервера).
- Для аналітики (Фази 1–3) обходитися ключами «read-only» або зовсім без ключів.
- Логи й `evidence` не містять секретів: `redact()` прибирає `api_key/token/secret/signature` з тексту помилок, а аргументи з такими іменами не потрапляють у `evidence`.

## Запобіжники виконання (Фаза 4)

1. **Вимкнено за замовчуванням.** Інструменти ордерів реєструються лише за `TRADEDESK_EXECUTION=paper|testnet|live`.
2. **Двокроковий потік.** `order_propose` повертає план, перевірки ризику й одноразовий токен (діє ~60 с). `order_confirm(token)` виконує. Ніякого «купи одразу».
3. **Ліміти в `guard.yaml`:** дозволені інструменти, макс. нотіонал ордера й позиції, макс. плече, макс. денний збиток, макс. ордерів на хвилину, режим `reduce_only`.
4. **Kill-switch:** прапор у базі й інструмент `trading_halt` зупиняють нові ордери та за потреби скасовують відкриті.
5. **Журнал аудиту:** кожна пропозиція, підтвердження й відповідь біржі пишуться у незмінний журнал.
6. **Етапи:** paper → testnet → live з мінімальними лімітами → поступове підвищення.

## Недовірені дані

Назви ринків Polymarket, новини, поля токенів, будь-який текст із зовнішніх API можуть містити спробу ін'єкції. Правило: **такі дані ніколи не запускають ордер без підтвердження** і не змінюють ліміти.

## Віддалений режим

Режим `streamable-http` поки без автентифікації. До Фази 6 слухати лише `127.0.0.1` і виходити назовні через Tailscale або Cloudflare Tunnel із авторизацією. Не публікувати порт у відкритий інтернет.

## Telegram-міст до Claude

`scripts/tg_bridge.py` (служба `tradedesk-tgbridge`) передає Claude на сервері лише текстові повідомлення творця групи (`TELEGRAM_OWNER_ID`) з теми «💬 Claude»; пересланих і чужих повідомлень не бере, усе записує в `tg-bridge.log`. Claude працює в окремому клоні `~/tradedesk-chat` з правами користувача `tradedesk`: без sudo, без force-push і пушу в `main` (його ще й закриває ruleset), без читання ключів, токенів і `/etc/tradedesk-mcp.env`; зміни йдуть гілками `chat/…` через PR власника. Хто заволодіє Telegram-акаунтом власника, отримає цей доступ, тому в Telegram обов'язкові хмарний пароль (двоетапна перевірка) і регулярний перегляд активних сеансів. Коли з'явиться `execution/`, місток не отримає доступу до ключів бірж: вони житимуть в окремого користувача.

## Токен GitHub для PR агентів

Лаунчер агентів і лікар самі відкривають pull request (`scripts/gh_pr.py`). Для цього на сервері лежить fine-grained токен у `~/.config/tradedesk/github.env` (0600, записує `scripts/server/11-github-token.sh` з Mac): лише репозиторій MCP, права Pull requests: read and write і Contents: read-only. Пушити, зливати чи міняти налаштування він не може; гілки й далі пушаться deploy key, а злиття в `main` лишається за власником. Агентам читання `~/.config/tradedesk/` заборонено.
