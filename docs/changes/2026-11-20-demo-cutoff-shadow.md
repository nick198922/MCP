# 2026-11-20 · Звірка демо з паспортом: тіньові плани на cutoff і closed без часу закриття (пункт 420)

Пункт 420 [постійної картки](../ideas/IDEA-20261102-standing-improvements.md), зауваження 1–2 [рев'ю s38-cutoff-counters](../reviews/2026-11-20-s38-cutoff-counters.md).

- **Тіньові плани рахуються на cutoff, а не на час прогону.** `analytics/demo_shadow`: план, який у БД `resolved`, але з `resolved_ts` пізніше за `now_ms`, вважається відкритим. План `resolved` без `resolved_ts` датувати не можна, тож він лишається закритим, як записано. `verify_s38_demo_vs_passport.py` і `verify_s12_demo_vs_passport.py` передають у `demo_shadow` `now_ms = cutoff`, тож повтор на тому самому cutoff дає той самий розділ «Невиконані сигнали … на cutoff». Інші виклики (`demo_vs_backtest.py`, панель) передають поточний час, і для них нічого не змінилось. Лишається обмеження: статус missed не має часу зміни. Вхід, скасований протягом 10-хвилинного вікна мейкера, що перетинає cutoff, при повторі видно як missed.
- **`verify_s3_demo_vs_passport.py` не змінено.** Годинника він не читає: це читач готового JSON `demo_vs_backtest.py`, а `summary` бере `now_ms` з цього JSON (рядок 163). Тому той самий JSON уже дає той самий звіт. Cutoff у ньому немає, і повтор S3 на cutoff робить `verify_s38_… --setup S3`.
- **`at_cutoff`: угода closed без `closed_ts` більше не рахується «open».** Вона може бути закрита ще до cutoff, тож лишається в «other», як її поклав `load_s12` до появи `at_cutoff`. Коментар у коді це пояснює.
- Тести: у `tests/test_demo_shadow.py` додано `test_plans_resolved_after_now_count_as_open` (стан БД на cutoff і пізніший стан, де план закрито після cutoff, при `now_ms = cutoff` дають ті самі числа; межа `resolved_ts == now`; план без `resolved_ts`). У `tests/test_verify_s38_demo_vs_passport.py` додано `test_shadow_plans_repeat_at_the_cutoff_whatever_the_run_time`: два прогони з різним `now` і тим самим cutoff дають однаковий звіт (без заголовка й рядка RSS). Якщо повернути в скрипт `now`, тест падає. До тесту класифікації `at_cutoff` додано рядок closed без часу закриття.
