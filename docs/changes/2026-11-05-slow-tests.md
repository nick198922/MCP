# 2026-11-05 — найповільніші тести: спільний прогін carry-двигуна, один скан `src/` на процес

Пункт 116 [IDEA-20261102-standing-improvements](../ideas/IDEA-20261102-standing-improvements.md). Змінено лише `tests/test_architecture_imports.py`, `tests/test_carry_paper_engine.py`, `tests/test_paper_carry_report.py`; `src/`, `execution/`, колектори не чіпали. Жодне твердження не послаблено й не прибрано.

- **Заміри.** `pytest --durations=25 -n auto` на всьому наборі (сервер спільний, по одному прогону). Без `slow`-тесту найповільніші: `test_tools_bad_input::test_no_tool_raises_on_absurd_input` 9.3 с, `test_paper_carry_report::test_report_renders_from_a_db_copy` 8.9 с, частини `test_setup_signals` 7–8 с, `test_carry_paper_engine` (`no_lookahead[A/B]`, `engine_a/b`) 7–7.6 с, `test_sieve_batch14::test_causal[...]` 7.4 с, `test_architecture_imports` 4.4–5.8 с на тест. Реальних `sleep` і пауз ретраю серед них немає (`http_retry_backoff=0.0` уже стоїть у фікстурах, решта `sleep` 0.01–0.05 с).
- **`test_paper_carry_report`.** Тест сам проганяв двигун карі A на 110 днях (307 циклів, ≈ 5 с), хоча `test_carry_paper_engine` уже робить рівно той самий прогін (той самий `markets_a(days=110)`, `PARAMS_A` зі `slots=3, entry_apr=0.10`, та сама сітка) і зберігає знімок (`VACUUM INTO`) раз на процес. Код знімка винесено у функцію `full_run_snapshot`, якою користуються і фікстура `full_run`, і звіт: він копіює знімок у свій `tmp_path` і читає копію. Збіг сценарію тест тепер перевіряє явно (`params == replace(PARAMS_A, slots=SLOTS, entry_apr=0.10)`).
- **`test_architecture_imports`.** Два тести (`import_boundaries_hold`, `allowed_entries_are_still_real`) кожен окремо сканували весь `src/` (≈ 390 файлів, ≈ 4.4 с). Тепер `all_violations()` кешовано (`functools.cache`, один скан на процес; `src/` під час прогону не змінюється), а дерево кожного файлу обходиться один раз замість двох (імпорти й «нечисті» виклики читають той самий список вузлів).
- **Час до → після** (три файли разом, без xdist, 40 passed і до, і після): **60.7 → 44.7 с**. `test_engine_a_equals_backtest` 8.0 → < 0.7 с (знімок уже зробив звіт), `test_allowed_entries_are_still_real` ≈ 4.4 → < 0.7 с. Під `-n auto` виграш залежить від того, чи потрапить пара тестів на один воркер: три файли разом тривали 34.6 с.
- **Лишилось як є, бо це сама суть перевірки.** `test_no_tool_raises_on_absurd_input`: 616 викликів інструментів по ≈ 8 мс, жоден не домінує (найдовший `range_setup.lookback_bars=10000` 0.7 с). `test_setup_signals` (живий скан на кожному префіксі, вже розбитий на частини пунктом 99), `test_sieve_batch*::test_causal`, `test_sfp_backtest::test_walk_forward_*`, `no_lookahead[A/B]` у carry: увесь час іде в аналітику `src/`, тож прискорити їх можна лише зменшивши вибірку, тобто послабивши тест. `test_stage0_condor_forward_*` один раз свідомо запускає справжній підпроцес (код виходу, без traceback). `test_strategy_sieve::test_s3_known_result_in_sample` (234 с під навантаженням) уже позначено `slow` і поза `make test`.
