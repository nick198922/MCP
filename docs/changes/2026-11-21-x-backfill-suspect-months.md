- Картка [standing-improvements](../ideas/IDEA-20261102-standing-improvements.md), пункт 443: `--stat` збирача архіву X (`scripts/x_backfill.py`) попереджає про підозрілі «зроблені» місяці. Джерело — рев'ю [x-backfill-month-truncation](../reviews/2026-11-20-x-backfill-month-truncation.md) (зауваження 2) і [x-backfill-coverage](../reviews/2026-11-20-x-backfill-coverage.md) (зауваження 1).
- `coverage_report` має нове поле `suspect_months`: місяці зі статусом `done`, де `oldest` зі `state.json` пізніше за початок місяця більш ніж на 1 добу (`SUSPECT_GAP_DAYS`), з полями `month`, `oldest`, `gap_days`. Це ознака, що API обрізав сторінки й місяць позначено повним без перших днів. Застереження: трейдер міг просто не писати на початку місяця; перший місяць запуску з `--since` теж починається пізніше. Місяці без `oldest` (старий `state.json`) лишаються `unverified` і в список не потрапляють; `done`-місяць без твітів (`oldest: null`) теж.
- Нове поле `ignored_future`: скільки твітів датовано пізніше `today` (зсув годинника). Вони не входять у жоден підрахунок, і в поточному місяці теж: раніше такий твіт поточного місяця входив у `tweets` і `last`.
- Лише читання локальних файлів, без мережі; нічого не дозавантажувалось. Реальні архіви (`stat()`, 21.11): Trader_XO, btc_charlie, docXBT, KillaXBT — `ignored_future` 0, `suspect_months` порожній, бо всі зроблені місяці ще `unverified` (106 / 106 / 72 / 72, завантажені до правки 430). Тож для Q-20261115-2 список запрацює лише після перезавантаження місяців новою версією.
- Тести (`tests/test_x_backfill.py`): новий `test_coverage_report_flags_suspect_done_months_and_counts_future_tweets` (місяць з `oldest` 15-го — підозрілий, з `oldest` у першу добу — ні, `unverified` і порожній `done` — ні; два твіти з майбутньою датою в `ignored_future`); порожній звіт у `test_coverage_report_empty_days_first_last_and_status` тепер має обидва нові поля. На коді до правки обидва тести падають.
