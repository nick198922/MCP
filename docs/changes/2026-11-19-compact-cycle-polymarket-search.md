# 2026-11-19 · Стислі типові відповіді `cycle_regime` і `polymarket_search`

Пункт 405 постійної картки, BACKLOG «З тижневого аудиту 2026-11-14» → «великі відповіді за замовчуванням» (восьмий і дев'ятий інструменти; попередні — [379](2026-11-18-compact-default-responses.md), [381](2026-11-18-compact-funding-spread-scan.md), [382](2026-11-18-compact-carry-scan-markets.md), [390](2026-11-19-compact-gap-ohlcv.md)).

- `cycle_regime`: новий параметр `include_details` (типово `false`). Без нього `history` — останні 10 днів (з `history_days` ≤ 10 — усі), а `transitions` — без списку `changes` (лишаються `state`, `state_ua`, `n_changes`, `score`, `reaches`; `closest` зберігає `changes` повністю). Нове поле в обох режимах: `history_summary` по всіх `history_days` днях — дні по станах (`undecided` для дня без стану), кількість змін стану між сусідніми визначеними днями (так само рахує повідомлення брифу), поточна серія (днів і з якої дати). Чиста функція `analytics.cycle_regime.history_summary`. Стан, складові, правила, `closest`, `line_ua` і всі застереження (контекст, не сигнал; не перевірено на історії) — однакові в обох режимах. Попередження «compact answer: …», коли щось обрізано.
- `polymarket_search`: новий параметр `include_details` (типово `false`). Без нього — перші 10 знайдених ринків (у порядку Gamma) без `slug` і `token_id` у виходах, питання ≤ 160 символів; ціни, де-віг, обсяг, ліквідність, дата й прапорці ті самі. Нове поле `shown` поруч із `count`. `token_id` для `polymarket_history` — з `include_details=true` або з `polymarket_market`. Опис виправлено: з запитом Gamma віддає ринки у власному порядку, «за обсягом» — лише без запиту (провайдер `search`, `/public-search` проти `/markets?order=volume`).
