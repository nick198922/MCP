# `funding_spread_scan`: неповна історія funding ноги тепер видна (пункт 212)

- `funding_spread_scan` (`tools/perps.py`, `leg`) читає `complete` з `funding_history_range` для ccxt (`Exchanges.funding_rate_history_range`) і Hyperliquid. Якщо `complete=false` (ліміт сторінок, збій пізнішої сторінки або відкинуті рядки з поганим часом), нога отримує позначку `incomplete`, а у `warnings` з'являється рядок із біржею й символом (`bybit BTC/USDT:USDT: funding history incomplete …`).
- `analytics/carry.spread_snapshot` (чиста функція): новий необов'язковий ключ ноги `incomplete`. Якщо він стоїть у short- або long-ноги пари, у `flags` додається `incomplete_history`, і `tradable_now=false`. Неповна нога поза парою дає лише попередження, без прапора.
- На повній історії вихід не змінюється: ключ `incomplete` у ногу не додається, прапора й попередження немає. Паперовий carry (`carry_paper_*`) цей ключ не передає, тож для нього нічого не змінилось.
- Опис інструмента (англ.) доповнено прапором `incomplete_history`; `tradable_now` тепер «above entry with no price, reversal or incomplete_history flag».
- Тести: `tests/test_carry.py::test_spread_snapshot_incomplete_history_blocks_tradable` (аналітика); `tests/test_funding_spread_incomplete.py` через MCP-клієнт: повна історія без прапора, неповна нога ccxt (bybit) і Hyperliquid → прапор, `tradable_now=false`, попередження; неповна нога поза парою → лише попередження; збій провайдера → `missing`, без винятку.
- Наживо 07.11 (сервер, `build_server()`, binanceusdm + bybit + okx + hyperliquid, BTC / ETH / SOL): `ok=true`, `missing` порожній, історія повна скрізь, тож прапора `incomplete_history` і попереджень про неповну історію немає; пари (ETH hyperliquid/bybit 7,0 %, SOL binanceusdm/okx 2,6 %, BTC hyperliquid/bybit 1,9 %).
