# 2026-11-04 — Polymarket v1: грубі кошики замість min–max при n < 5

Постійна картка `IDEA-20261102-standing-improvements`, п. 49; джерело — [рев'ю 24h-gaps](../reviews/2026-11-03-pm-gap-24h-gaps.md), «Залишкове» п. 1.

- `scripts/verify_pm_gap_24h_gaps.py`: рядок «+24 h missing, aggregate ranges (min-max)» тепер іде через нову функцію `agg_range`. Коли значень менше 5 (`SMALL_N`), замість точних меж друкуються лише кошики мінімуму й максимуму: для годин `<24 h` / `24-48 h` / `>=48 h` (напр. `entry->end h (n<5) all >=48 h`), для лічильника моментів колектора `0` / `1-2` / `>=3`. На n = 3 точні межі були значеннями двох конкретних позицій.
- При n ≥ 5 вивід байт у байт той самий, що й раніше (`ключ мін-макс` з одним знаком).
- Тести: `tests/test_verify_pm_gap_24h_gaps.py` (n = 3 → кошик без точних чисел; n = 6 → як було; поріг рівно 5; лічильники).
- Інших місць, що друкують межі min–max по позиціях, немає: `scripts/pm_gap_paper_report.py` їх не друкує, а `g_min`/`g_max` у `analytics/pm_gap_report.py` (блок v2-g) — межі g по всіх придатних знімках ринку, не по позиціях, тому не змінювались.
- Реєстрації, пороги, вердикт, колектор і `execution/` не змінено.
