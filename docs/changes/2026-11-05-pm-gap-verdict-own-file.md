# 2026-11-05 — вердикти Polymarket не пишуться у файл тижневого звіту

Джерело: рев'ю [2026-11-01-pm-v2g-verdict-report](../reviews/2026-11-01-pm-v2g-verdict-report.md), зауваження 3 («обидва вердикти пишуть у той самий файл, що й тижневий звіт»); картка [постійних покращень](../ideas/IDEA-20261102-standing-improvements.md), пункт 93.

- `scripts/pm_gap_paper_report.py`: без `--out` одноразові вердикти тепер пишуться в окремі файли поряд із тижневим звітом — `pm_gap_VERDICT.md` (`--verdict`) і `pm_gap_VERDICT_v2g.md` (`--verdict-v2g`). Раніше обидва затирали `pm_gap_REPORT.md`, який недільний таймер `tradedesk-pm-gap-report` переписує: вердикт, що рахується один раз, зник би за кілька днів.
- Тека береться з `$TRADEDESK_PM_GAP_REPORT` або типового шляху, як і раніше; явний `--out` має перевагу. Тижневий режим, ворота вердиктів, правила реєстрації, розрахунки — без змін.
- Тест `test_runner_verdicts_default_to_their_own_files_not_the_weekly_report`: тижневий файл після обох вердиктів не змінився, вердикти лягли у свої файли, `--out` діє.
- `docs/AGENTS.md`: назви файлів вердиктів у рядку про тижневий звіт.
- Інші зауваження того рев'ю: 1 закрито раніше (запис у `docs/changes/` є), 4 закрито раніше (тест «4 тижні після T0 v2-g»: числа стадії 0 є, середнього й SE немає), 2 і 5 — інформаційні, без змін.
