**Вирівнювання часу.** День = торговий день COMP. Ціна крипти — о 16:00 America/New_York того дня (з урахуванням DST), у дні скороченої сесії (п'ятниця після Дня подяки; 24.12 і 03.07, якщо це пн–чт) — о 13:00 ET. Зміна кожного ряду = між двома сусідніми торговими днями COMP (лог-дохідність для COMP, SPY, UUP, BTC, ETH; різниця для 2Y/10Y). Ніколи не рівні. **Вихідні:** у головному розрахунку дохідність крипти з п'ятниці до понеділка охоплює вихідні так само, як і дохідність акцій (одне й те саме вікно); стійкість — лише пари, що охоплюють одну календарну добу (вт–пт). Якщо дати немає в ряді (свята облігацій при відкритій біржі), зміна цього ряду в цій парі пропущена (попарне видалення). Пропущена година крипти → пара без крипти.

**Статистика.** Пірсон і OLS-бета на денних змінах; 95 % CI — бутстреп рухомими блоками по 20 торгових днів, 2000 повторів, seed 20261018. Кожен актив (BTC, ETH) — окремо, без об'єднання.

**H1 (описова, режими).** Ковзна 60-денна кореляція (лише минулі 60 пар, без зазирання вперед) BTC/ETH ↔ COMP, SPY, UUP, Δ2Y, Δ10Y: для кожного року — медіана, мін, макс, частка вікон > 0.3 і < 0. Кореляція й R² за роками з CI. Тест тези власника «у 90 % випадків рух біткойна дає макро»: R² багатофакторної OLS BTC на всі п'ять рядів за кожен рік. ✗, якщо верхня межа CI R² < 0.9 у кожному році; ✓, якщо нижня межа ≥ 0.9 хоча б в одному році; інакше ≈. Додатково друкується максимум ковзного 60-денного R² (описово).

**H2 (стресові дні).** Стрес = лог-дохідність COMP ≤ ln(0.98). (a) Середня дохідність BTC у стрес-день < 0: ✓, якщо верхня межа CI < 0. (b) Бета BTC до COMP у стрес-дні вища, ніж в інші дні: ✓, якщо нижня межа CI різниці β_стрес − β_інші > 0; ✗, якщо верхня < 0; інакше ≈ / ◯ за знаком. Порівнюються бети, а не кореляції: кореляція на відборі за великими |X| завищена (Forbes–Rigobon), OLS-бета при відборі за X — ні. Контроль симетрії: β у дні COMP ≥ ln(1.02) (описово). Кореляція в стрес-дні друкується лише описово.

**H3 (фаза ФРС).** Фаза на день t визначається лише за змінами з датою чинності ≤ t_попер (початок вікна дохідності — без зазирання вперед): «підвищення», якщо остання зміна — підвищення і вона не старша за 120 днів; «зниження» — аналогічно; інакше «пауза». Стійкість: вікно 90 і 180 днів. Гіпотеза картки: у фазі підвищень бета BTC до COMP вища, ніж у паузі. ✓ лише якщо нижня межа CI β_підв − β_пауза > 0 **і** знак тримається окремо в кожному епізоді підвищень довжиною ≥ 60 пар; інакше ≈ (знак сходиться) або ✗ (верхня межа < 0); при менш ніж 2 таких епізодах — найвище ≈. Таблиця по епізодах (окремі безперервні відрізки фаз) з β і кореляцією друкується вся.
- **Потужність:** епізодів підвищень у вікні ≈ 2 (2018, 2022–2023; 2026-09 — короткий), знижень ≈ 4 (2019, 2020-03, 2024, 2025). Денних пар тисячі, але незалежних режимів — одиниці, тож CI бутстрепу занижує невизначеність щодо «режиму»; фаза ФРС сплутана з часом (ETF з 2024, інтеграція з 2020). Вердикт H3 — найвище ≈, якщо ефект не тримається в обох епізодах.

**H4 (lead-lag, денні).** (a) Nasdaq веде BTC: кор(r_COMP[t−1], r_BTC[t]) ≠ 0 — ✓, якщо CI виключає 0; обернений напрям кор(r_BTC[t−1], r_COMP[t]) — описово. (b) Вихідні (пари, що охоплюють ≥ 3 календарні доби, тобто вихідні й довгі вихідні): BTC від закриття останнього торгового дня до 09:00 ET першого дня після вихідних (остання повна година до відкриття, годинні свічки) проти гепу COMP (open першого дня / попередній close; одночасна кореляція, описово) і як передбачення денної сесії COMP понеділка (open → close; ✓, якщо CI виключає 0). Open індексу COMP з Nasdaq API перевіряється спершу (частка днів, де open = попередній close); якщо > 5 % — H4b ◯. (c) Торгове правило з H4a: позиція BTC = знак r_COMP[t] від закриття t до закриття наступного торгового дня, витрати 0.05 % нотіоналу за кожну одиницю зміни позиції (taker Binance), на нотіонал. Успіх: нижня межа CI середньої денної дохідності net > 0 **і** середнє net > 0 у 2024-01-01 … 2026-10-16 (друга половина). Годинний lead-lag — ◯: безкоштовної годинної історії індексу немає.

Уже відомо до реєстрації: (1) B1 — денні кореляції BTC зі ставками ≈ 0, з UUP −0.11; фаза ФРС на бету не впливає (◯); (2) популярна теза «BTC іде за глобальною M2 з лагом ≈ 10–12 тижнів» (графіки рівнів або річного приросту, підігнані на 2020–2024), тож очікуваний знак M2 «+», а 2020 рік — головне джерело цієї тези; (3) проба доступності 2026-10-18 (лише статус, розмір, назви рядів і діапазон дат): Fed Data Download Program без ключа віддає пакет H.6 (`M2.M`, M2 SA, місячні середні, 1959-01 … 2026-08) і H.10 (`JRXWTFB_N.B`, широкий номінальний індекс долара, денний, з 2006); Мінфін США — CSV реальних дохідностей (`daily_treasury_real_yield_curve`, TIPS par, 5–30 років); Nasdaq API для UUP раніше 2017-12 віддає 0 рядків; Bitstamp `BTC/USD` 1d через `rt.exchanges` — з 2014-01-01. FRED у цьому кроці не запитувався (у B1 — тайм-аут). DDP оголошено до виведення з листопада 2026 — для повторних прогонів кеш. Код: `src/tradedesk/analytics/macro_slow.py`, `scripts/verify_macro_slow.py`; хеш цього розділу друкує `--stage prereg` у `~/.cache/tradedesk-agents/macro_slow/registration.txt` до завантаження даних; коміт робить координатор. Усе, що змінено після першого прогону, у звіті позначено як дослідницьке.

**Дані.** Місяць m — календарний місяць.
- BTC: Bitstamp `BTC/USD` денні свічки (`rt.exchanges`, пагінація по 1000), ціна місяця = close останньої доби місяця (00:00 UTC першого дня наступного). ETH: Bitstamp `ETH/USD` так само (вторинний актив, 2018-01 …).
- Ставки: par yield curve Мінфіну, 2Y, 10Y (номінальні) і 10 YR real (TIPS), десяткові; значення місяця = останній торговий день ≤ кінця місяця; зміна — різниця.
- Долар: H.10 broad index (`JRXWTFB_N.B`), значення місяця = остання дата ≤ кінця місяця, лог-зміна. H.10 публікується щотижня із запізненням, але індекс — детермінована функція публічних курсів того дня, тож інформаційного зазирання вперед нема (застереження у звіті). UUP (кеш B1, 2018+) — стійкість.
- M2: H.6 `M2.M` (SA, середнє за місяць), g1(m) = ln M2(m)/M2(m−1), g3(m) = ln M2(m)/M2(m−3). Публікація H.6 — приблизно на 4-му тижні наступного місяця, тож g(m−2) відомий до початку m. **Ревізії:** це поточна версія ряду, не реальний час (історичних версій без ALFRED/ключа FRED нема) — застереження. Глобальна M2 (ЄЦБ, НБК, Банк Японії в USD) — ◯, немає безкоштовного зведеного джерела без ключа.
- Ставка ФРС: таблиця `openmarket.htm` (кеш B1). Фаза на місяць m — `fed_phase` B1 (вікно 120 днів) на останній день m−1 (лише минулі зміни).
- **Період:** дохідності BTC 2015-01 … 2026-09 (141 місяць; початок — після краху Mt.Gox 2014, Bitstamp як головна USD-біржа). ETH 2018-01 … 2026-09 (105). Половини: 2015-01 … 2020-12 і 2021-01 … 2026-09 (друга — OOS для знаку). Описово: 2024-07 … 2026-09 — після популяризації тези M2.

**Лише зміни, не рівні.** Кореляція рівнів (ln BTC проти ln M2 зі зсувом 2 міс.) друкується одним рядком як ілюстрація хибної кореляції трендових рядів, вердикту не отримує.

**Статистика.** Пірсон; 95 % CI — бутстреп рухомими блоками по 6 місяців, 2000 повторів, seed 20261018; додатково 99 % CI (поправка на множинність). Потужність: MDE = 2.8 × SE бутстрепу.

**C (описово, одночасні місячні зміни; опис ризику, без торгового вердикту).** кор(r_BTC(m), x(m)) для x ∈ {Δ2Y, Δ10Y, Δreal10Y, Δln долар, g1 M2} з CI; R² OLS на всі п'ять разом — порівняння з денним R² B1.

**P (головні, передбачувальні — сигнал відомий до початку місяця).** Очікуваний знак у дужках.
- P1 M2: кор(g1(m−2), r_BTC(m)) (+). Лаг 2 — найменший, що торгується з урахуванням публікації, і відповідає ≈ 6–11 тижням тези.
- P2 ставки: кор(Δ2Y(m−1), r_BTC(m)) (−).
- P3 реальні ставки: кор(Δreal10Y(m−1), r_BTC(m)) (−).
- P4 долар: кор(Δln долар(m−1), r_BTC(m)) (−).
- **Правило для P1–P4:** ✓ — 95 % CI виключає 0 з очікуваним знаком **і** знак той самий в обох половинах (друга — OOS); ≈ — CI виключає 0 з очікуваним знаком, але в другій половині знак інший; «✗ протилежний знак» — CI виключає 0 з протилежним знаком; ✗ (не виявлено) — CI включає 0 і MDE ≤ 0.30; ◯ — CI включає 0 і MDE > 0.30, або даних нема.
- P5 фаза ФРС: різниця середньої місячної лог-дохідності BTC у місяцях «зниження» мінус «підвищення» (+). ✓ — нижня межа CI > 0 **і** ≥ 2 епізоди кожної фази (≥ 3 міс.) **і** знак тримається в обох половинах; ✗ (не виявлено) — CI включає 0 і MDE ≤ 0.05 на місяць; «✗ протилежний знак» — верхня межа < 0; ≈ — CI > 0, але решту умов не виконано; ◯ — інакше. Очікуємо ◯: епізодів по 3, місяців знижень ≈ 25.
- **R1 (торгове правило з тези M2).** Місяць m: BTC спот на весь капітал, якщо g3(m−2) > медіани g3 за 60 попередніх відомих місяців (m−62 … m−3, мінімум 36), інакше кеш (0, без відсотків за T-bills — консервативно щодо правила). Витрати 0.1 % (taker спота) за кожен вхід і вихід. Статистика — альфа відносно експозиції: середнє net правила − f × середнє «купив і тримай» за ті самі місяці (f — частка місяців у ринку), прості дохідності, на капітал без плеча. ✓ — нижня межа CI > 0 і альфа > 0 в обох половинах; ✗ — інакше (з MDE); ◯, якщо MDE > 3 % на місяць.

**Потужність (чесно).** n ≈ 139 пар → SE кор. ≈ 0.085, MDE ≈ 0.24 (R² ≈ 6 %). Для правила за знаком сигналу це відповідає річному Sharpe ≈ 0.65; слабші, але економічно цікаві зв'язки (кор. 0.1, Sharpe ≈ 0.3) тест не бачить. ETH (n ≈ 104) MDE ≈ 0.27. Незалежних епізодів: циклів ставок у вікні 3 (підвищення 2015–2018, 2022–2023; знижень 2019–2020, 2024–2025), епізод M2 2020 — один, тож «підтвердження» може триматися на одному році — обов'язкова стійкість без 2020.

**Критерій «вбити» B3.** Теза про M2 (US M2, у формулюванні змін із лагом) — `rejected`-кандидат, якщо P1 — ✗ (не виявлено) або протилежний знак **і** R1 не ✓. Глобальна M2 — окремо ◯. Статус картки лишається `testing` (рішення про статус — після рев'ю критика й частини «Практичні правила»).

**Стійкість (друкується вся, без вибору найкращого).** Половини; без 2020-03 … 2020-12; без 3 місяців з найбільшим |r_BTC|; лаг M2 = 1 (не торгується, описово) і 3; P1 на g3(m−2); Δ10Y замість Δ2Y; лаг 2 для P2–P4; UUP замість H.10 (2018+); 2018+ з точним вирівнюванням (BTC Binance о 16:00 ET останнього торгового дня місяця, годинний кеш B1); ранговий Спірмен; блоки 3 і 12 місяців; R1 з витратами ×3, медіана 36 місяців замість 60; ETH. Описово — 2024-07 … 2026-09.

**Перевірка 5a.** Активів два: різниця ETH − BTC для P1–P4 і R1 на спільних місяцях з CI; тест неоднорідності й стійкість «топ-активів» на двох активах сенсу не мають.

**Санітарні перевірки (до звіту).** Рівні: M2 2020-02 ≈ 15.4 трлн і 2021-02 ≈ 19.4 трлн, річний приріст M2 у лютому 2021 ≈ 26–27 % (відомий пік); 10Y real 2020-08 ≈ −1.0 %; 2Y 2026-10 з кешу B1; broad dollar восени 2022 ≈ 125–129 (пік); BTC Bitstamp кінець 2017-12 ≈ 13–14 тис., 2021-11 ≈ 57 тис.; Bitstamp проти Binance BTCUSDT (00:00 UTC, 2018+) — медіана розбіжності < 0.5 % (колізії тікерів нема); пропуски днів; кількість місяців; фази ФРС за місяцями.

**Множинність.** Головні: P1–P5, R1 (BTC) — шість тестів; при шести незалежних тестах імовірність хоча б одного хибного ✓ ≈ 26 %, тож ✓ без 99 % CI позначається «не стійке до множинності». Це п'ята спроба навколо макро в цій картці (лічильник у звіті).

2026-10-18, quant. Записано до будь-якого прогону: дані GLD і USO цим кодом ще не завантажувались, жодної дохідності, кореляції чи середнього для GLD/USO на цих даних я не рахував. Уже відомо до реєстрації (і **для вибору порогів не використовується**): (1) нотатка `docs/knowledge/macro.md` (замір Claude 2026-10-18): одночасні кореляції BTC з UUP −0.11, USO +0.08, GLD +0.13 (+0.34 у 2026); після 10 % найсильніших днів росту золота BTC +0.8 % наступного дня, n = 110, без CI і поправки на множинність; (2) B1: BTC ↔ UUP −0.11 [CI у звіті B1], правило «BTC за знаком учорашнього Nasdaq» ✗; (3) B2/B3 — переваги наперед не виявлено. Поріг сильного дня нижче обрано з міркувань «≈ 5–8 % днів за нормального розподілу і досить подій для потужності», а не за заміром Claude; поріг Claude (повновибірковий топ-10 %, із зазиранням уперед) лише відтворюється описово. Код: `src/tradedesk/analytics/macro_crossasset.py`, `scripts/verify_macro_b1b.py`; хеш цього розділу (від заголовка до наступного заголовка другого рівня) друкує `--stage prereg` у `~/.cache/tradedesk-agents/macro_b1b/registration.txt` до завантаження даних; коміт робить координатор. Усе, що змінено після першого прогону, у звіті позначено як дослідницьке.

**Дані й період.**
- GLD (золото), USO (нафта), UUP (долар, ф'ючерси на DXY) — ETF з `api.nasdaq.com/api/quote/{SYM}/historical?assetclass=etf`, close 16:00 ET (13:00 у дні скороченої сесії); COMP і UUP — кеш B1 (`~/.cache/tradedesk-agents/macro_regimes/`, лише читання). Ціни без поправки на дивіденди (GLD і USO не платять; UUP — раз на рік, ≈ 0–2 %).
- **USO:** зворотний спліт 1:8 (чинний 2020-04-29). Якщо ряд Nasdaq не скоригований (|лог-зміна| > ln 4 того дня), дохідність цього дня виключається (None), рівні не переписуються. Будь-яка |лог-зміна| ETF > 0.25 друкується в санітарних перевірках.
- BTCUSDT і ETHUSDT спот Binance, годинні свічки — кеш B1 (`…/macro_regimes/klines/`, лише читання), ціна в момент x = close годинної свічки, що закінчується в x.
- День = торговий день COMP, 2018-01-02 … 2026-10-16 (як у B1); сигнальні дні — до 2026-10-15 (останній день, для якого в кеші є BTC через 24 год).

**Сигнал (лише минуле).** r_X(t) = ln close_X(t) / close_X(t_попер), t_попер — попередній торговий день COMP. σ_X(t) = вибіркове SD r_X за 60 попередніх пар (t−60 … t−1, мінімум 40 наявних). z_X(t) = r_X(t) / σ_X(t). **Сильний день росту золота:** z_GLD(t) ≥ 1.5 (≈ 6.7 % днів за нормального розподілу, очікуємо ≈ 120–170 подій).

**Відповідь BTC.** Вхід о закритті Нью-Йорка дня t (x0 = 16:00 ET, 13:00 у скорочені дні), Y_h(t) = ln P_BTC(x0 + h) / P_BTC(x0), h = 24 год (головний; крипта торгується щодня, тож вікно — календарна доба, у п'ятницю — до суботи) і 72 год. Вікна по 24 год від сусідніх сигнальних днів не перекриваються.

**Статистика.** D_h = середнє Y_h у дні події − середнє Y_h в усі інші сигнальні дні (різниця, щоб прибрати дрейф BTC). 95 % CI — бутстреп рухомими блоками по 20 торгових днів (рядки — сигнальні дні; індикатор події і Y перевибираються разом), 2000 повторів, seed 20261018. p-значення (двобічне) — нуль кругових зсувів: ряд сигналу (індикатор або r_GLD) зсувається відносно Y на k = 20 … n − 20 рядків, p = частка |стат. зсуву| ≥ |спостережене|. Потужність: MDE = 2.8 × SE бутстрепу (стадія 0 друкує лише n подій, SD Y і MDE до будь-якого середнього).

**Головна сім'я (поправка Холма, m = 3; очікуваний знак «+»).**
- **G1 (головний):** D_24 для z_GLD ≥ 1.5.
- **G2:** D_72 для z_GLD ≥ 1.5 (вікна перекриваються; блоковий бутстреп це враховує).
- **G3:** кор(r_GLD(t), Y_24(t)) по всіх сигнальних днях (неперервна форма, без порогу).

**Правило вердикту (для кожного G).** OOS = останні 25 % сигнальних днів за часом (поріг — індекс 0.75·n, друкується датою), IS — перші 75 %. Параметрів, підігнаних на IS, нема, тож OOS — перевірка стабільності знаку на пізніших даних.
- ✓ — p Холма < 0.05 **і** нижня межа 95 % CI > 0 **і** оцінка > 0 і в IS, і в OOS;
- ≈ — нижня межа CI > 0, але Холм не пройдено або знак в OOS інший;
- «✗ протилежний знак» — верхня межа CI < 0;
- ✗ (не виявлено) — CI включає 0 і пройдено ворота потужності: MDE ≤ 1.0 % (G1), ≤ 1.5 % (G2), ≤ 0.10 кор. (G3);
- ◯ — CI включає 0, ворота не пройдено.
