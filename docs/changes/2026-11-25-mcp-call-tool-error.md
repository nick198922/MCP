# 2026-11-25 — `scripts/mcp_call.py`: помилка інструмента без трейсбека (пункт 459)

- **Відповідь-помилка інструмента** (`isError`, напр. `perps_oi_history` з `{"period": "bogus"}`): скрипт друкує текст помилки (повідомлення pydantic про допустимі значення) і виходить з кодом 4. Трейсбека немає, на локальний сервер скрипт не переходить. Так само з `--local`.
- **Перехід на сервер у процесі** тепер буває лише тоді, коли служба справді не відповіла, тобто не вдалося з'єднання або рукостискання. Примітка називає причину, напр. `ConnectError: All connection attempts failed`. Збій уже після з'єднання (виняток у виклику, помилка протоколу, нечитна відповідь) повідомляється з кодом 5, і повторного виклику немає. Причина старого збою: SDK 2.x загортає виняток із тіла `async with Client(...)` в `ExceptionGroup` при закритті сесії. Через це `JSONDecodeError` у живій сесії виглядав як «служба не відповіла».
- **Відповідь простим текстом, а не JSON**, друкується як є, з кодом 0.
- **Коди виходу** описано в docstring скрипта: 0 відповідь; 2 використання, аргументи не JSON-об'єкт або нема інструмента; 3 відмова для інструмента запису; 4 інструмент відповів помилкою; 5 збій після з'єднання або локальний сервер не стартував.
- **Тести** (`tests/test_mcp_call.py`, без мережі):
  - відхилені аргументи: через «службу», яка насправді є сервером у процесі, і з `--local`;
  - виняток у `call_tool` після з'єднання: код 5, без переходу на локальний сервер;
  - текстова відповідь, що не є JSON;
  - примітка про недосяжну службу називає `ConnectError`.
