## Зауваження

1. **[блокер] Напрям «папір трохи оптимістичний» залежить від тих самих 5 угод, які звіт сам називає ненадійними.** У висновку стоїть «Напрям для B: папір трохи оптимістичний (−0.12 % на угоду за mid)», і там само сказано, що для 5 угод першого дня (BLUR, BMT, ERA, SAND, WAL; книга відкриття знята через 8 783 с) «Δ ненадійна». Розрахунок із JSON:
   - 10 угод зі свіжими книгами (969–1 255 с): Δ **+0.004 %** [−0.50; +0.51];
   - 5 угод першого дня: Δ −0.364 % [−0.81; +0.09], причому від'ємна в них переважно частина закриття (Δ_close −0.347 %, книга закриття свіжа), а Δ_open ≈ −0.006 %;
   - без 5 угод першого дня і без BIRB №1: −0.197 % (n = 9).

   Отже, знак середнього Δ визначає склад вибірки, а не стійкий зсув. «Без топ-1 / топ-2 знак той самий» знімає лише викиди за |Δ|, а розбиття за затримкою книги знак змінює. **Виправлення:** додати розбиття «свіжі книги (n = 10) / книга відкриття 8 783 с (n = 5)» для Δ, Δ_open і Δ_close з позначкою «дослідницьке», а у висновку замінити «напрям: папір трохи оптимістичний» на «напрям не встановлено: −0.12 % на всіх 15 угодах, +0.00 % на 10 угодах зі свіжими книгами». Також уточнити, що для 5 угод першого дня ненадійна лише Δ_open (вхід), а Δ_close в них порахована за свіжою книгою.

2. **[блокер] Δ_vwap порівняно з неправильним еталоном.** Реєстрація вимагала порівнювати Δ_vwap із модельним прослизанням 0.05 % на ногу й сторону, «а не з нулем». У звіті натомість стоїть «гірше за закриття бару приблизно на 0.5 % номіналу на угоду (≈ витрати однієї сторони B 0.205 % ×2.4)». У `fees` рушія вже закладено 4 × 0.05 % = 0.20 % прослизання на угоду (плюс `stop_penalty` 1 % на стопах, їх 5 з 15). Тому незмодельований надлишок становить −0.493 + 0.20 = **−0.29 % на угоду, t-ДІ [−0.65; +0.06]**, тобто ДІ містить 0. Число «×2.4» порівнює повну дорогу VWAP з однією стороною витрат і перебільшує незмодельовану частину. Крім того, дійсний вимір реальних витрат уже є: критерій (б) B, фактичні / модельні 1.48. Грубий перерахунок Δ_vwap на слот прослизання дає приблизно ×1.4–1.9, що з ним узгоджується. **Виправлення:** переписати пункт Δ_vwap так: «−0.49 % проти бару, з них 0.20 % уже в комісіях рушія; надлишок −0.29 % [−0.65; +0.06] (дослідницьке), узгоджується з (б) 1.48». Прибрати «×2.4». Окремо: `stats()` записує в JSON `"verdict": "✓"` для `delta_vwap`, хоча за реєстрацією це описова величина з іншим нулем. Звіт цього ✓ не цитує, але в тексті варто сказати, що поле `verdict` у JSON для Δ_open / Δ_close / Δ_vwap не є вердиктом (або в наступній правці скрипта не писати його для описових ключів).

3. **[середнє] Δ_open «збігається з механізмом» лише завдяки BIRB.** Без 4 угод BIRB (один епізод, 22.10–01.11) Δ_open = **−0.029 %** [−0.14; +0.08] (n = 11), а Δ без BIRB −0.201 %. Звіт називає це «не висновок, лише напрям», і це правильно, але треба прямо написати, що напрям Δ_open дає один символ і один епізод. Інакше 23.11 його прочитають як властивість входу B загалом. **Виправлення:** одне речення з числом без BIRB.

4. **[середнє] Неправильний підпис суми P&L.** «сума P&L B (ціни) рушія +5.133 % → за mid +3.349 %». Але +5.133 % — це сума повного `pnl` (ціна + funding − комісії), а сума лише цінової частини `p_model` дорівнює +3.636 %. Саме твердження «знак сумарного P&L не змінюється» від цього не страждає. **Виправлення:** «сума повного P&L B (ціна + funding − комісії), частки номіналу: +5.133 % → +3.349 % (≈ +103 → +67 USD на слот 2 000 USD)».

5. **[середнє] Число n ≈ 149 подано як «щоб відрізнити зсув 0.10 % від нуля».** (1.96 · sd / δ)² дає n, за якого півширина ДІ дорівнює δ, а це приблизно 50 % потужності. Для 80 % потрібно (2.8 · 0.623 / 0.10)² ≈ **304**. За темпом B (15 закритих угод з 20.10, ≈ 0.6 на день) це ≈ 8 і ≈ 17 місяців. Для рішення 23.11 важливо сказати прямо, що форвардне накопичення цього питання найближчим часом не закриє. **Виправлення:** уточнити формулювання й додати обидва числа та строки.

6. **[низьке] Фактичні помилки в описі вибірки.** «переважно 5 символів: BIRB ×4, DOOD ×2» не так: у 15 угодах **11 символів**, повторюються лише BIRB ×4 і DOOD ×2. «див. колонку lat_s»: у звіті немає таблиці з такою колонкою, вона є лише у stdout скрипта. «970–1 255 с»: насправді 969–1 255 с. **Виправлення:** виправити кількість символів і або додати потрібну таблицю (символ, вихід, Δ, Δ_open, Δ_close, Δ_vwap, lat_s), або посилатися на вивід скрипта.

7. **[низьке] Відкриті угоди: показано не ту величину, що зареєстрована.** Реєстрація: «Відкриті угоди — лише Δ_open описово». Скрипт рахує `open_gap_delta`, тобто відносне відхилення пари `(x_mid/r_mid)/(x_model/r_model) − 1`, і його знак не дорівнює знаку P&L (так сказано в докстрінгу). Для B з `dir = −1` (лонг b, шорт a) додатний розрив INIT +0.83 % означає вхід гірший за модель, тобто ≈ −0.8 % для P&L. **Виправлення:** назвати величину й відхилення від реєстрації, вказати знак для P&L.

8. **[низьке] A/TST: затримка книги спот-ноги невідома** (`latency_s` = `[null, 665, null, 674]`). Вердикт A ◯ від цього не залежить, але слід дописати, що час знімка спот-книги для TST не перевірено.

9. **[низьке] Дата зрізу `as_of` = кінець 19.11 UTC, а прогін зроблено протягом цього ж дня.** Якщо до 23:59 закриється якась угода B (наприклад, INIT), повторний прогін з тим самим `--date` дасть інші числа. Мій перезапуск збігся. **Виправлення:** записати у звіт фактичний UTC-час прогону або в наступних прогонах брати `--date` минулого дня.
