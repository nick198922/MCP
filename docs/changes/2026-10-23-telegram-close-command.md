- Закриття угоди з Telegram: `/close 12 86000 fees 4.5 note …` (або `ціна`, `комісія`, `нотатка`) у темі «💬 Claude» (лише власник, та сама перевірка групи, теми й `from.id`) закриває відкриту угоду журналу тим самим шляхом, що `journal_close` (`journal_get` → лише статус `open` → `analytics.journal` для P&L, R і результату → ті самі колонки, що `journal_update_close`). Запис умовний (`WHERE id = ? AND status = 'open'`, перевірка кількості змінених рядків): рядок, який тим часом закрив інший процес (демо-трейдер, `journal_close` у Claude), не перезаписується, відповідь — «уже закрита». Відповідь: що закрито, P&L, R (якщо є стоп), «жодних ордерів, ліміти не змінюються». Нової бази не створює.
- Рядки демо-трейдера (теги `auto`, `demo-paper` або `bybit-demo`) не закриваються: відповідь «це позиція демо-бота, вона закривається ботом», журнал не змінюється.
- Комісія віднімається від P&L і записується в нотатку рядка; R — за ціною, без комісії. Для опціону R не рахується (стоп стосується базового активу), для купленого показано результат до премії; вихід опціону менший за 1 без `$` — відмова. Опціон, що згорів, закривається `/close ID 0` (або `$0`): P&L = −премія, «−100 %» для купленого; для лінійної угоди нуль — відмова.
- Розбір — чиста `analytics/close_command.py`, сувора, як у `/trade`: незнайоме слово, `86,000`, `nan`, від'ємне число, не-ASCII цифри, нецілий id — відмова з поясненням. Невідомий id, уже закрита чи скасована угода — відмова, журнал не змінюється. Якщо база впала вже після запису, відповідь «✅ Закрито… відповідь не зібрано», а не «збій бази, спробуйте ще раз».
- Міст `scripts/tg_bridge.py` запускає `scripts/journal_close_tg.py` через `uv run --frozen`, текст — одним аргументом без shell; `/close` у `/help` (там же: опціон, що згорів, — `/close 12 0`; закриття з Telegram не скасувати, тож перевіряйте id; угоди демо-бота не закриваються). Відповідь `/trade` тепер підказує `/close ID ЦІНА_ВИХОДУ`.
