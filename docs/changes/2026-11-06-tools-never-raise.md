# Наскрізний тест інваріанта 1: інструмент не кидає виняток (пункт 153)

- Новий `tests/test_tools_never_raise.py`: сервер з `build_server()`, у якого кожен HTTP-транспорт (усі назви `Http`, а не лише ті, що є в `conftest`) відповідає 500 або таймаутом, а кожна ccxt-біржа кидає `ExchangeNotAvailable` / `RequestTimeout`. Через справжній MCP-клієнт викликаються всі 109 зареєстрованих інструментів з мінімальними валідними аргументами (`ARGS`); тест вимагає, щоб жоден не дав `isError` і кожен повернув конверт із булевим `ok`. Два режими (500 і таймаут), ~4 с кожен.
- Пропущених 0 (`SKIP` порожній): БД — тимчасовий SQLite у `tmp_path`, тож журнали, правила, плани й позиції теж викликаються; ключів немає, Coinalyze віддає `missing: config`. Ключі не читаються: `Settings` задано явно, не з оточення.
- Результат прогону: 73 інструменти записали збій у `missing` (`ok=false` — 70, `ok=true` із частковими даними — 3), 36 працюють без мережі (чисті розрахунки й локальна БД). Порушень 0, виправлено 0, `KNOWN_RAISERS` порожній.
- Самоперевірка: тест додає до сервера інструмент без `Builder.guard` і переконується, що його виняток ловиться; отже зелений прогін щось означає.
- Не покрито: відповіді 200 з неправильним тілом (порожній JSON, інша схема), збої самої БД, інші гілки аргументів, ніж мінімальні; `execution/` і колектори не викликаються.
- Перевірка: `make lint`; `uv run pytest -q tests/test_tools_never_raise.py tests/test_server.py` — 81 passed.
