## Коротко
- **Усі три провали (е) у B — властивість ринку, дефекту рушія немає (✗ на питання «баг рушія?» для кожного входу).** У всіх 27 унікальних рядках кандидата (6 + 3 + 19 = 28 рядків по входах; рядок 23.10 16:00 спільний для обох входів BIRB) ціна кожної ноги **точно** дорівнює закриттю 4h-бару своєї біржі (Binance USDⓈ-M / Bybit), що закрився в момент циклу: відхилення 0 у кожному рядку, поріг R2 0.1 %. Завмерлих ніг немає (R1: жодна ціна не повторюється ≥ 3 рядки, обсяг кожного бару > 0, мінімум 7.3 млн монет), одиниці однакові (R4: відношення ≤ 1.06). Тобто рушій міряє те, що показують біржі. Цей вердикт від порогів реєстрації не залежить: відхилення рівно 0 (а не «нижче 0.1 %»), повторів 0, найбільше відношення 1.05.
- **Розрив справжній, а не артефакт закриття бару.** 1m-бари за час утримання: BIRB №1 медіана −0.56 % (2 645 хв, |розрив| > 0.5 % у 54 % хвилин), BIRB №2 −1.20 % (1 205 хв, 95 %); mid книг обох ніг на відкритті / закритті з тим самим знаком і більший (−1.18 … −2.14 %), знімки книг ніг розходяться ≤ 0.29 с. Це памп BIRB 0.05 → 0.19, у якому Binance дешевший за Bybit за знаком весь час, а за розміром > 0.5 % — переважно в добу пампу (BIRB №1: добові медіани 1m −0.41 / −0.41 / −1.67 %). Два входи BIRB — один епізод (вихід і повторний вхід у циклі 23.10 16:05, рядок 23.10 16:00 спільний), тож незалежних епізодів два (BIRB, INIT), а не три.
- **INIT провалює (е) на межі й залежно від дати.** На 17.11 |медіана| 0.501 % (19 рядків) проти порогу 0.500 %; на 19.11 — 0.444 % (22 рядки), і (е) за INIT уже пройдено. Розрив INIT справжній і великий, але змінює знак: від −1.85 % (12.11 00:00) до +5.19 % (13.11 16:00), 1m-медіана +0.47 %, |розрив| > 0.5 % у 60 % хвилин. За зареєстрованим правилом підклас — «шум закриття» (1m-медіана ≤ 0.5 %), але різниця 0.47 % проти 0.50 % несуттєва (від фактичного входу — +0.498 %, за 0.002 п.п. від порогу). Поділ «стійкий / шум закриття» — лише описовий: реєстрація, не закомічена до прогону, його не захищає. Точніший опис: розрив справжній, змінює знак, а медіана лежить на порозі.
- **Наслідок для 23.11:** виправляти в рушії нічого. (е) у B лишається «не пройдено» за реєстрацією (BIRB двічі, на 19.11 — лише BIRB). Причина — вибране вікно утримання: фід пускає символ лише тоді, коли медіана розриву за ≥ 20 барів до входу ≤ 0.5 % (`carry_paper_feed.py`, рядки 389–394), як у бектесті. Тож за вікном бектесту всі три входи пройшли (е) за побудовою, а на короткому утриманні під час пампу — ні. Відкрите питання 13.11 «вікно утримання чи вся історія» лишається за власником або критиком. Пункту для розробника щодо рушія немає; відкрито два побічні пункти: 383a (P&L паперу за закриттям бару проти mid книги) і 383b (ознака пропущеного бару в скрипті).

## Метод
- БД колектора відкрито лише на читання (`mode=ro`): `cp_position`, `cp_log` (рядки `side`), `cp_cycle` (кандидати). Входи, що провалюють (е), знайдено тим самим кодом, що й у звіті чекпоінту (`checkpoint._asof`, `_carry_entries`, `_held_gap`), станом на кінець 17.11 (як у факті 17.11) і, для контексту, на кінець 19.11.
- Бари повторно отримано тим самим провайдером і тим самим ccxt-символом, що й у рушія (`rt.exchanges.ohlcv`, як `collector/market_data.py:42`; публічні, без ключів): 4h-бари обох бірж навколо утримання і 1m-бари. Тому вони не «незалежні»: R2 виключає зсув часу, кеш і незакритий бар, але не неправильний символ / контракт, спільний для рушія й скрипта. Відповідність символу підтверджує не R2, а фільтр колізії фіду на вході (≥ 20 спільних 4h-барів і |медіана a/b − 1| ≤ 0.5 %, `collector/carry_paper_feed.py:389–394`) та те, що ціни ніг рухаються разом. Кеш: `~/.cache/tradedesk-agents/carry_b_leg_gap/`.
- Вікно 1m-медіани — від відкриття бару за першим рядком (так само, як рядки (е)), тобто за 4 год до фактичного входу, до закриття; для відкритої INIT — до останнього циклу, не довше 14 діб. Реєстрація казала «за весь час утримання»; перерахунок критика з кешу від фактичного входу (цикл + 5 хв): BIRB №1 −0.60 % (57.1 % хвилин > 0.5 %), BIRB №2 −1.17 % (97.1 %), INIT +0.498 % (58.7 %). Підкласи ті самі, але INIT — за 0.002 п.п. від порогу.
- Бар рядка — той, що закрився останнім до рішення рушія (цикл + 5 хв), тобто бар із закриттям у момент циклу (`analytics/carry_leg_gap.cycle_bar_open`). Класифікація — `classify` за реєстрацією: R1 (≥ 3 однакові ціни поспіль або нульовий обсяг), R2 (> 0.1 % від закриття бару своєї біржі), R4 (> 1.5x), підклас ринку — за |1m-медіаною| 0.5 %.
- Пам'ять: пік 219 МБ.

## Застереження
- **Відхилення від правила 03.11 (порядок реєстрації).** Реєстрацію «Попередня реєстрація — пункт 383» записано в тому самому запуску, що й прогін, і окремим комітом до чисел не закомічено (`git log -S` порожній), тож порядок «правило → числа» з git не підтверджується. Крім того, до реєстрації я вже бачив медіани BIRB 0.76 / 0.69 % і факт провалу INIT (це сказано в самій реєстрації). На головний вердикт «дефект рушія?» це не впливає: він не чутливий до жодного вибраного порогу (R2 — відхилення рівно 0 у кожному рядку, R1 — жодного повтору, R4 — відношення 1.05 проти 1.5). Чутливий до порогу лише підклас ринку «стійкий / шум закриття» (INIT 0.47–0.50 % проти 0.5 %), тому його подано як описовий, не захищений реєстрацією.
- R3 (описово, на (е) не впливає): книги знято через 974–1 089 с після часу циклу (16–18 хв), а ціна моделі — закриття бару на час циклу. Тому `model_price / mid − 1` сягає +7.8 % на закритті BIRB №2 у памп. На (е) це не впливає: (е) рахує закриття барів. Не впливає і на витрати (б): там `actual_cost` береться відносно mid тієї ж книги (критик цього в коді не перевіряв). Але P&L паперу рахується за закриттям бару, на 16–18 хв раніше за книгу. Це властивість конструкції рушія, а не розбіжність між ногами: знімки книг двох ніг розходяться ≤ 0.29 с. Розрив ніг на закритті: модель −0.90 % проти mid −2.14 % (BIRB №1), −0.69 % проти −0.98 % (BIRB №2); для хеджованої пари це 0.3–1.2 п.п. номіналу, порядок витрат угоди, і стосується (в) та P&L паперу. Тут не оцінювалось; відкрито окремий пункт 383a у картці (звірити до розбору 23.11).
- Пропущений бар мовчки не дає R2: у `row_checks` / `classify` рядок без бару отримує `dev = None` без позначки. У цьому прогоні бари є для всіх рядків, на висновок не впливає; для повторного використання скрипта потрібна ознака «R2 unknown» з тестом (пункт 383b у картці).
- Підклас «шум закриття» для INIT — механічний результат правила (1m-медіана 0.47 % ≤ 0.5 %), а не висновок, що розрив INIT несправжній. Розрив INIT справжній, але змінює знак.
- Вердикт INIT залежить від дати звіту, бо позиція відкрита. 30.11 рядок (е) потрібно перерахувати звичайним `checkpoint_report.py`.
- n = 3 входи, два незалежні епізоди (обидва входи BIRB — один памп). Висновок «ринок» стосується лише цих входів, а не всіх майбутніх провалів (е). Новий провал варто проганяти тим самим скриптом.
