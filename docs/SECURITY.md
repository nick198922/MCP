# Безпека

Сервер MCP читає лише публічні дані й ордерів не ставить. Єдиний код, що торгує, — демо-трейдер `execution/` на **демо-рахунку Bybit** (ігрові гроші, [ADR 0007](adr/0007-demo-auto-execution.md)). Live-режиму в коді немає. Нижче правила, які діють для ключів і ордерів.

## Ключі

- Секрети лише в змінних оточення або менеджері секретів. `.env` у `.gitignore`, у репозиторій не потрапляє нічого з ключами.
- Для бірж створювати **окремі ключі під цей сервер**: дозвіл на торгівлю, **без права виведення коштів**, з **IP allow-list** (IP вашого сервера).
- Для аналітики (Фази 1–3) обходитися ключами «read-only» або зовсім без ключів.
- Логи й `evidence` не містять секретів: `redact()` прибирає `api_key/token/secret/signature` з тексту помилок, а аргументи з такими іменами не потрапляють у `evidence`.

## Запобіжники виконання (Фаза 4)

1. **Вимкнено за замовчуванням.** Інструменти ордерів реєструються лише за `TRADEDESK_EXECUTION=paper|testnet|live`.
2. **Двокроковий потік.** `order_propose` повертає план, перевірки ризику й одноразовий токен (діє ~60 с). `order_confirm(token)` виконує. Ніякого «купи одразу».
3. **Ліміти в `guard.yaml`:** дозволені інструменти, макс. нотіонал ордера й позиції, макс. плече, макс. денний збиток, макс. ордерів на хвилину, режим `reduce_only`.
4. **Kill-switch:** прапор у базі й інструмент `trading_halt` зупиняють нові ордери та за потреби скасовують відкриті.
5. **Журнал аудиту:** кожна пропозиція, підтвердження й відповідь біржі пишуться у незмінний журнал.
6. **Етапи:** paper → testnet → live з мінімальними лімітами → поступове підвищення.

## Недовірені дані

Назви ринків Polymarket, новини, поля токенів, будь-який текст із зовнішніх API можуть містити спробу ін'єкції. Правило: **такі дані ніколи не запускають ордер без підтвердження** і не змінюють ліміти.

## Віддалений режим

Режим `streamable-http` поки без автентифікації. До Фази 6 слухати лише `127.0.0.1` і виходити назовні через Tailscale або Cloudflare Tunnel із авторизацією. Не публікувати порт у відкритий інтернет.

## Панель через Tailscale

Панель (`scripts/dashboard.py`, без автентифікації) слухає лише `127.0.0.1:8090`. З 22.10 (власник, крок `scripts/server/23-tailscale.sh`) `tailscale serve` віддає її за HTTPS на адресі сервера в tailnet власника (`https://tradedesk.<tailnet>.ts.net/`): доступ мають лише пристрої, увійшли в його акаунт Tailscale. Funnel (публікація в інтернет), Tailscale SSH, exit node і маршрути підмереж не вмикаються. Панель лише читає; у ній є журнал реальних угод, тож новий пристрій у tailnet = доступ до нього: стежити за списком пристроїв у консолі Tailscale, 2FA на акаунті. Ім'я хоста потрапляє в публічні журнали сертифікатів (Certificate Transparency), сам вузол із інтернету недоступний. Скасувати: `tailscale serve reset`, `tailscale down`.

## Telegram-міст до Claude

`scripts/tg_bridge.py` (служба `tradedesk-tgbridge`) передає Claude на сервері лише текстові повідомлення творця групи (`TELEGRAM_OWNER_ID`) з теми «💬 Claude»; пересланих і чужих повідомлень не бере, усе записує в `tg-bridge.log`. Claude працює в окремому клоні `~/tradedesk-chat` з правами користувача `tradedesk`: без sudo, без force-push і пушу в `main` (його ще й закриває ruleset), без читання ключів, токенів і `/etc/tradedesk-mcp.env`; зміни йдуть гілками `chat/…` через PR власника. Хто заволодіє Telegram-акаунтом власника, отримає цей доступ, тому в Telegram обов'язкові хмарний пароль (двоетапна перевірка) і регулярний перегляд активних сеансів. Коли з'явиться `execution/`, місток не отримає доступу до ключів бірж: вони житимуть в окремого користувача.

## Токен GitHub для PR агентів

Лаунчер агентів і лікар самі відкривають pull request (`scripts/gh_pr.py`). Для цього на сервері лежить fine-grained токен у `~/.config/tradedesk/github.env` (0600, записує `scripts/server/11-github-token.sh` з Mac): лише репозиторій MCP, права Pull requests: read and write і Contents: read-only. Пушити, зливати чи міняти налаштування він не може; гілки й далі пушаться deploy key, а злиття в `main` лишається за власником. Агентам читання `~/.config/tradedesk/` заборонено.

## Автоматичне злиття PR агентів

Готові PR агентів зливає GitHub Actions (`.github/workflows/automerge.yml`, подія `workflow_run` після CI), а якщо GitHub цю подію не дав (завислий прогін) — сторож PR на сервері (`scripts/pr_watch.py`, кожні 15 хв, ті самі правила). Правила (`scripts/automerge.py`) завжди беруться з `main`. Зливається PR з гілки `agent/*` (зокрема `-fix-` лікаря) або `claude/*` цього репозиторію, позначений як готовий, з зеленим CI саме на його останньому коміті. **З 22.10 за рішенням власника зливаються й системні зміни** (скрипти, дозволи та інструкції агентів, `scripts/server/`, `.github/`, `pyproject.toml`/`uv.lock`, `CLAUDE.md`, цей файл, ADR, `execution/` і сигнали демо-трейдера): список системних шляхів лишився лише для звіту про злиття. Власника попереджено про ризик: агент одним PR може змінити власні дозволи чи інструкції, і ніхто цього не побачить до злиття. **Виняток — демо-трейдер (рішення власника 22.10: «ризики за Claude»):** PR, що змінює код, який ставить ордери (`execution/`, `setup_signals.py`, детектори `course_*`, таймери `tradedesk-demo-*`, ADR 0007), або те, що могло б вимкнути це утримання (`scripts/automerge.py`, `scripts/pr_watch.py`, `scripts/trader_review.py`, `.claude/trader-review.md`, `scripts/user_units_sync.sh`, `.github/`, їхні таймери), автозлиття тримає (`claude:`), доки рев'ю Claude (`scripts/trader_review.py`, Opus, кожні 15 хв, лише інструменти читання, чекліст `.claude/trader-review.md` з `main`) не схвалить саме цей коміт. «changes» — PR лишається відкритим, рев'ю йде коментарем у PR і в Telegram. Що лишається запобіжником: критик (рев'ю перед здачею), CI (тести на `api-demo.bybit.com`, відсутність ордерних викликів поза `execution/`), `ExecutionGuard` і заборона live-режиму без нового ADR (правило в `CLAUDE.md`). Незавершений крок (після ліміту прогонів) не позначається готовим і не зливається. Прапорці функцій (`deploy/features.env`) і user-таймери (`deploy/user-units/`) працюють від `tradedesk` без root; їхні запобіжники — білий список `src/tradedesk/features.py` і `scripts/user_units_sync.sh`. Злитий код потрапляє на сервер щогодини (`tradedesk-update` о :20, перезапуск MCP лише коли `main` змінився; крок 20).
