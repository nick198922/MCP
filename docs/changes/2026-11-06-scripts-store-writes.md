# Записи в БД зі `scripts/` через `Store._write()` (пункт 169, BACKLOG 6.46)

- `scripts/journal_cancel_tg.py`, `scripts/journal_close_tg.py`: умовний `UPDATE journal … AND status = 'open'` тепер у `async with store._write()` замість `store.conn.execute` + `commit()`. При помилці (`IntegrityError`, `disk I/O`) транзакцію відкочено одразу, а не лише на `aclose()`. SQL, перевірка `rowcount`, відповіді в Telegram і `progress["written"]` не змінились.
- `scripts/bybit_import.py`, `store_options`: три `UPDATE journal SET note` і `UPDATE … SET size, entry` йдуть через вкладений помічник `write()`, тобто через `st._write()`. Є одна відмінність: `size` / `entry` власного відкритого рядка тепер комітяться окремо від `journal_update_close`. Якщо закриття впаде, рядок лишиться відкритим із цими числами, а наступний імпорт (та сама мітка) запише їх ще раз і закриє рядок. На успішному шляху результат той самий.
- Тест-охоронець `test_every_store_write_goes_through_write_block` (`tests/test_store.py`) тепер сканує й усі `scripts/**/*.py`. Блоком запису вважається `async with <будь-що>._write()`. Регулярний вираз DML нечутливий до регістру й ловить `WITH … INSERT` (знахідка 1 повторного [рев'ю](../reviews/2026-11-06-store-rollback.md)), у фікстурі є рядки з малими літерами й `WITH`. Винятки перелічено в `_SCRIPT_WRITES_ALLOWED` з точною кількістю знахідок і причиною: `copy_vaults.py` (власна БД paper-книги, а не `Store`; записи йдуть у `with con:`), `hyperliquid_import.py:mark_airdrop` (синхронне `sqlite3` в одноразовій команді власника, без відкату на помилці; помилка завершує процес, а закрите з'єднання відкидає транзакцію; кандидат на `with con:`), `bybit_import.py:store_options` (вкладений `one()` виконує лише SELECT, евристика «SQL у змінній» спрацьовує хибно).
- Нові тести: `test_a_failed_write_is_rolled_back_before_the_store_closes` у `test_journal_cancel_tg.py` і `test_journal_close_tg.py`, `test_a_failed_note_update_is_rolled_back_before_the_store_closes` у `test_bybit_import.py`. Тригер `RAISE(ABORT)` на `UPDATE journal` дає `IntegrityError`. Перед `aclose()` перевіряється, що `in_transaction is False` і що друге з'єднання з `timeout=0.1` може писати. Спільна фікстура — `refused_journal_update` у `tests/conftest.py`. Мутаційна перевірка: з `_write()` без відкату (як стара логіка `execute` + `commit`) усі три тести падають (`in_transaction: True`, `database is locked`).
