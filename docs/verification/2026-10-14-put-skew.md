# Премія за путовий скью (25Δ пут) на Deribit BTC — 2026-10-14

Картка: `docs/ideas/IDEA-20261013-deribit-put-skew-premium.md` (попередня реєстрація там же).

Відтворення:
- `uv run python scripts/probe_deribit_history.py` (крок 0, ~10 с);
- `uv run python scripts/verify_put_skew.py --cache-dir ~/.cache/tradedesk-agents/put_skew`: завантаження ~15 хв, далі ~1 хв.

Логіка: `src/tradedesk/analytics/put_skew.py`, тести `tests/test_put_skew.py`. Провайдер `Deribit`, нові методи:
- `last_trades_by_currency_and_time`;
- `last_trades_by_instrument_and_time`;
- `delivery_prices`;
- `funding_rate_history`.

`rt.deribit_history` — це той самий клас на `https://history.deribit.com/api/v2`, із власним rate-limit 5 запитів/с.

## Підсумок

**Вердикт v1: ◯ `inconclusive`, тест зупинено на воротах покриття. P&L не рахувався.** Після рев'ю критика (`docs/reviews/2026-10-14-put-skew.md`) у картці зареєстровано v2, картка повернулася в `accepted`. Завантаження повних днів і P&L — наступний крок.

Крок 0 пройдено: історичні угоди опціонів з `iv` є і безкоштовні.

Попередньо зареєстрований поріг покриття не виконано:
- лише **49.6 %** днів входу (поріг ≥ 80 %) мають у вибраній ~30-денній експірації ≥ 3 путові угоди з |Δ| ∈ [0.20; 0.30] у вікні 08:00–10:00 UTC;
- 2021 — 41 %, 2022 — 39 %.

Причина не у відсутності даних, а в правилах відбору, зафіксованих мною до завантаження:
- вузьке двогодинне вікно;
- правило «експірація, найближча до 30 днів», яке часто обирає тонкий weekly замість ліквідного monthly;
- дні, коли в календарі Deribit немає жодної експірації з DTE у [21; 45].

За розвідувальним виміром покриття на 40 випадкових днях (теж без P&L) вікно 24 год до 09:00 UTC різко підвищує покриття. Тож тест можливий на безкоштовних даних після нової попередньої реєстрації (v2, див. картку).

**Форвард.** У трейдах немає `underlying_price`. Форвард кожної угоди розв'язується з її власних `price` та `iv` за конвенцією Deribit `price_btc = Black76(F)/F`. Ця конвенція узгоджується краще, ніж `Black76(F)/index`: міжквартильний розмах F/index у межах експірації становить 0.00003–0.006 проти 0.0001–0.07 (7 денних зразків). Знайдено очікуване контанго 2021 року (+2.4 % на 23 дні, +6.6 % на 79 днів) і беквордацію в червні 2022 (−0.4 %).

## Поріг покриття (зафіксовано до завантаження)

Умова для дня входу:
- у вибраній експірації (DTE, найближче до 30, у межах [21; 45]) є ≥ 3 путові угоди з |Δ| ∈ [0.20; 0.30] у вікні 08:00–10:00 UTC;
- є торгований страйк 25Δ;
- є ATM-страйк з call-Δ ∈ [0.40; 0.60].

Поріг — ≥ 80 % днів входу з 2021-04-01 по 2026-08-29.

|---|---|---|---|---|---|---|---|

| 30д, 20Δ | 53 % ✗ | 46 % | 44 % | 51 % | 60 % | 63 % | 54 % |
| 30д, 30Δ | 47 % ✗ | 40 % | 36 % | 54 % | 51 % | 55 % | 46 % |
| 10д, 25Δ | 73 % ✗ | 68 % | 65 % | 73 % | 82 % | 78 % | 68 % |
| 10д, 20Δ | 76 % ✗ | 70 % | 73 % | 76 % | 83 % | 81 % | 73 % |
| 10д, 30Δ | 68 % ✗ | 67 % | 62 % | 66 % | 77 % | 70 % | 61 % |

Причини непокриття в основній конфігурації (частка від усіх днів):

| Причина | частка днів |
|---|---|
| немає торгованої експірації з DTE у [21; 45] | 19.6 % |
| < 3 путових угод 25Δ у вибраній експірації | 29.4 % |
| ATM-страйк поза call-Δ [0.40; 0.60] | 1.4 % |

Медіана — 4 путові угоди 25Δ на день у вікні.

Порогу не досягає жодна конфігурація сітки. За попередньою реєстрацією P&L не рахувався ні для основної гіпотези, ні для варіантів. Код P&L (vega-нейтральна позиція, H1, H3, H2 з контролем DVOL, стрес-рядки, без топ-3) написано й покрито тестами. Ворота покриття в `verify_put_skew.py` зупиняють його до будь-якого розрахунку.

## Розвідувально: чи можливий тест з іншими правилами (лише покриття, без P&L)

Вибірка: 40 випадкових днів входу (seed 20261014), повні угоди за 24 год до 09:00 UTC. Кеш `~/.cache/tradedesk-agents/put_skew_fullday_sample/`.

Відтворення:

У першій версії звіту рядок «08–10, найліквідніша» мав 50 %: це умова «лише ≥ 3 путових угод». З повною умовою (разом з ATM) виходить 47.5 %, як і в перерахунку критика. Обидва рядки тепер у таблиці.

Стовпчик віку mark кількісно показує дефект схеми v1 на 24-годинному вікні: marks у середньому були 17 год давності. У v2 медіана 0.7 год, максимум ≤ 6 год за побудовою.

Приклади, чому «найближча до 30д» не працює:
- 2025-10-16: обрано тонкий weekly `7NOV25` (22 дні, 15 угод, 0 путів 25Δ), хоча monthly `28NOV25` (43 дні) мав 265 путових угод 25Δ;
- 2026-04-06: в календарі лише 18 і 53 дні, нічого в [21; 45].

Ці числа виміряно після провалу основного порогу. Вони лише обґрунтовують перереєстрацію і не є результатом. Правила v2 зафіксовано в картці («Попередня реєстрація v2»). Основне правило експірації в них календарне, «найліквідніша» — лише розвідувально.

## Наступний крок (v2, після злиття гілки з окремими комітами v1 і реєстрації v2)

1. `uv run python scripts/verify_put_skew.py --cache-dir ~/.cache/tradedesk-agents/put_skew --scheme v2 --fetch-only`: ~1.5 год, gzip-кеш `trades24/`; у звіті вказати шлях і розмір.
2. `--scheme v2 --coverage-only`: ворота ≥ 80 % на повній вибірці, розподіл віку marks.
3. Лише якщо ворота пройдено, повний прогін `--scheme v2`, потім розвідувальні `--scheme v2_age3` та `v2_liquid`. Додати перевірку F/S проти квартальних ф'ючерсів.

## Застереження

- Mark IV відновлюється оберненням `mark_price` угод. Для дня без угод на страйку IV інтерполюється за ln(K/F). Це звичайний шум, але не bid/ask котирування.
- Сітка «тенор × Δ» з таблиці покриття зафіксована до завантаження. Правила v2 з'явилися після провалу порогу v1 і перед будь-яким P&L.
- Перший прогін v1 рахувався кодом до виправлень рев'ю. Тепер він відтворюється тим самим числом (49.6 %) через `--scheme v1`, тобто `V1_BUILD` у `analytics/put_skew.py`, і поточний сирий вивід v1 нижче отримано саме так.
