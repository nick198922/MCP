## Блокери

1. **(середня) Перевірка наявності помічника в кроці 31 не зупиняє скрипт.** Рядок 23: `test -f "$REPO/scripts/restart_needed.sh" && test -f "$REPO/scripts/user_units_sync.sh"` під `set -e`. За мануалом bash, збій команди в списку `&&`, якщо це не остання команда списку, `set -e` не зупиняє. Перевірити це запуском не вдалося, bash-виклик відхилено, тож висновок лише з мануалу. Отже, якщо власник запустить крок 31 до злиття цього PR у `main`, крок встановить новий `tradedesk-update` без помічника на диску. Тоді щогодинний запуск щоразу отримує `helper failed` і **перезапускає службу щогодини навіть без злиттів**. Це гірше, ніж зараз. Виправлення: `test -f … || { echo "merge the PR with scripts/restart_needed.sh first"; exit 1; }` окремо для кожного файлу. Та сама вада є в кроці 20, рядок 15; там вона безпечна, але її варто виправити разом.
2. **(середня) Зникло випадкове самовідновлення служби.** Досі будь-яке злиття, майже щогодини, перезапускало `tradedesk-mcp`, навіть коли служба зупинилась сама. Наприклад, чистий вихід з кодом 0 при `Restart=on-failure`, ручний `systemctl stop` чи вичерпаний `StartLimit` після серії збоїв. Тепер зупинена служба лежить до першого злиття, що торкається `src/`. Під час паузи агентів це може тривати години, а колектор 24/7 — те, що власник береже. Виправлення в гілці без `--force`, до виклику помічника: `systemctl is-active --quiet tradedesk-mcp.service || ans="restart: service not active"`, і перезапускати без запитання до помічника. Плюс тест: заглушка `systemctl is-active` з кодом 3 → перезапуск.
