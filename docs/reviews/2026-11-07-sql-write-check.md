# Рев'ю: sql_schema_check — запити запису (пункт 215)

Режим C. Вердикт: **approve**.

Перевірив сам: `uv run python scripts/sql_schema_check.py`, `uv run pytest -q tests/test_sql_schema_check.py` (13 passed), `make lint` (чисто), `git diff --stat`.

## Перевірено

1. Інваріанти. Скрипт лишається read-only і працює лише з stdlib. Запити готуються `EXPLAIN` на БД у пам'яті, схема береться з міграцій, реальні БД не відкриваються. Запис не виконується, тільки готується. У `analytics/` і `src/` змін немає. Змінено лише скрипт, тест, `docs/changes`, BACKLOG і картка ідей.
2. Лічильники з опису збігаються з прогоном: 71 літерал запису, 53 статичних, 18 динамічних, ok 53, INSERT 33, UPDATE 18, DELETE 2. Сирий `grep` по `scripts` і `src/tradedesk` дає в сумі 71 рядок (1+1+4+8+1+56). SELECT: у прогоні 152 літерали, 219 ok загалом. Твердження «170 перевірено, 166 ok, 4 чужа БД» з опису відповідає: 166+4=170 — на цифри з прогону (ok 219 = 166 + 53) це сходиться.
3. Якість тесту. Він перевіряє точні номери рядків і категорії: INSERT у неіснуючу таблицю, колонку в списку INSERT, SET, WHERE, DELETE, частину SELECT у INSERT…SELECT, невідповідність кількості значень, пропуск динамічних рядків (f-string, `+`, `%`), відсів прози «update the journal and set…». Також перевіряє рядок заголовка зі лічильниками і `write_target`. Якщо зламати розпізнавання запису або маппінг «has no column named», тест упаде. Це не формальність.
4. 18 пропущених динамічних записів усі названі в описі і в виводі скрипта, причини вказані. Хибнопозитивного «кількість значень» на `'?' * n` уникнуто свідомо.

## Зауваження

1. Низька. `_WRITE_START` для UPDATE ловить будь-який рядок виду «update X set …» (проза англійською з таким збігом дасть `other error`, не збій). Це інформаційна категорія, шкоди для exit code немає. Фікс не потрібен.
2. Низька. У описі зміни фраза про «170 перевірено» стосується SELECT і не збігається за формою зі шапкою прогону («152 literals … 41 variants»), бо рахується інакше (варіанти). Лише уточнити формулювання, якщо хочеться.
3. Інформаційно. Залишається сліпа зона `self.*_COLUMNS` у `store/db.py` (10 вставок колектора). Це названо в описі як відомий ліміт, наступний крок — розгортання `self.CONST`.
