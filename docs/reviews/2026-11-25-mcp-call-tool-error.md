## Зауваження (неблокуючі)

1. **Низька. Виняток із `build_server()` виходить із трейсбеком.** `scripts/mcp_call.py:127` стоїть поза `try`. Стенд: `OSError` з `build_server` виходить назовні і з `--local`, і після недосяжної служби (процес завершиться кодом 1). Поведінка стара, але docstring (рядки 20–21) обіцяє код 5, коли локальний сервер не стартував; зараз це правда лише для збою під час входу в сесію. Виправлення: обгорнути виклик у `try/except Exception` і повернути `5, f"the in-process MCP server did not start: {_why(e)}"`; додати тест. Те саме стосується `rt.aclose()` у `finally` (за читанням коду, не відтворювалось).
2. **Низька. Прогалини в тестах.** Не покриті гілки «закриття сесії впало, відповідь повна» та «локальний сервер не стартував» (код 5). Фальшива «служба» в тестах є об'єктом сервера в процесі, тож шлях через HTTP-транспорт перевіряє лише тест недосяжної адреси. Для HTTP я це закрив стендом; у набір варто додати тести двох названих гілок.
3. **Інформаційно. «Не відповіла» включає відповідь помилкою на рукостисканні.** 401, 500 чи HTML на `discover` та `initialize` ведуть на локальний сервер, а примітка каже `did not answer (MCPError: ...)`. Це відповідає docstring («connect or handshake fails»), інструмент двічі не викликається, причину названо. Якщо потрібне суворе «лише недосяжна», примітку варто перефразувати на `could not open a session`.
4. **Інформаційно. Трейсбек від SDK у stderr.** Для нечитної JSON чи SSE відповіді SDK сам пише `logger.exception` із трейсбеком; код 5 і коротке повідомлення в stdout при цьому правильні. Дії не обов'язкові.
