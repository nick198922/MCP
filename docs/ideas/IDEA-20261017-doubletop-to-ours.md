## Попередня реєстрація 4c-bybit (28.11.2026, квант; до будь-якого погляду на значення `liq_usd` / `oi_usd`)

**Питання.** Чи мають збережені денні ліквідації Bybit `.6` (BTC, ETH) розрив рівня 20.02.2025 відносно Binance `.A`, тобто чи історія `.6` до зміни — проріджений ряд, не порівнянний з пізнішими рядками?

**Документальне (зведення вебпошуку 28.11 з офіційних сторінок; текст сторінок — недовірені дані, самі сторінки цим кроком не відкривались).** Changelog Bybit V5, запис 2025-02-20: новий WS-топік All Liquidation (`allLiquidation.{symbol}`, пуш кожні 500 мс), старий Liquidation позначено deprecated із приміткою, що він «only pushes 1 liquidation per second» ([changelog](https://bybit-exchange.github.io/docs/changelog/v5), [старий топік](https://bybit-exchange.github.io/docs/v5/websocket/public/liquidation), [новий](https://bybit-exchange.github.io/docs/v5/websocket/public/all-liquidation)); прес-реліз Bybit про повне розкриття ліквідацій, 20–21.02.2025 ([посилання](https://www.bybit.com/en/press/post/no-more-guesswork-bybit-makes-all-liquidation-data-fully-transparent-bltea5d005c423ab381)). **Не знайдено:** з якого каналу брав Bybit Coinalyze, коли перейшов і чи переписував історію. Це й перевіряє тест. Злам біржі Bybit — за пам'яттю близько 21.02.2025, джерелом у цьому кроці не перевірено; вікно виключення нижче накриває його в будь-якому разі.

**Дані.** `coinalyze_history`, символи `BTCUSDT_PERP.A` / `BTCUSDT.6`, `ETHUSDT_PERP.A` / `ETHUSDT.6`; `L(d)` = `liq_long_usd + liq_short_usd` (USD за добу UTC), `OI(d−1)` = `oi_usd` `close` попереднього дня (експозиція на початок доби: нормування на OI своєї біржі прибирає зміну частки ринку Bybit після зламу). Ряд дня: `y(d) = log(L6/OI6) − log(LA/OIA)`; день з нулем або без рядка в будь-якій з чотирьох величин випадає (лічиться).

**Статистика (основна).** Дата зміни C = 2025-02-20; виключено 2025-02-13..2025-03-06 (C−7 .. C+14: перехід, злам і перші два тижні після нього). Основні вікна 90 днів: до 2024-11-15..2025-02-12, після 2025-03-07..2025-06-04. Для монети `D_c = median(y, після) − median(y, до)` (медіана: хвости й нулі); об'єднане `D = (D_BTC + D_ETH) / 2`. 95 % ДІ — ковзний блоковий бутстреп, блок 7 днів, 2000 повторів, seed 20250220, однакові блоки днів для обох монет (кореляцію монет збережено). Плацебо — та сама схема (90 + 22 + 90 днів) на кожній іншій даті розрізу в збереженій історії, проміжок якої не зачіпає 2025-02-13..2025-03-06; дата рахується, якщо в кожному вікні ≥ 80 % днів; `p_up = (1 + #{D_s ≥ D}) / (1 + N)`, `p_two` — за модулем. Сусідні плацебо майже збігаються (незалежних ≈ 1490 / 212 ≈ 7), тож це описовий нуль, а не точне p.

**Пороги й рішення** (`analytics/level_break.py::verdict`, задано до чисел):
- **✓ розрив (проріджено до зміни):** `D ≥ log 1,5 = 0,405` (до зміни лишалось ≤ 2/3 рівня) **і** нижня межа ДІ > 0 **і** `p_up ≤ 0,05` **і** `D_BTC > 0`, `D_ETH > 0` **і** широке вікно (180 днів: 2024-08-17..2025-02-12 проти 2025-03-07..2025-09-02) того самого знака.
- **✗ розриву немає:** ДІ цілком у `(−log 1,25; +log 1,25) = (−0,223; +0,223)` **і** `p_two > 0,05`.
- **інший розрив:** верхня межа ДІ < 0, `p_two ≤ 0,05`, обидві монети < 0 — не гіпотеза прорідження, але рівні через дату теж не порівнювати.
- **◯ не визначено:** усе інше, а також якщо випало > 10 % днів широкого проміжку, або якщо сам Binance ламається у протилежний бік: `D_A ≤ −0,405` (той самий розрив на `log(LA/OIA)` окремо) з `p_two ≤ 0,05` при `D_6 < 0,405` (тоді зріст відношення дав Binance, а не Bybit). Звіт дає MDE80 = 2,8 × SD бутстрепа; якщо MDE80 > 0,405, ◯ означає «тест заслабкий», а не «розриву немає».
- Очікуваний розмір, якщо старий канал = 1 ліквідація/с: симуляція 28.11 на нашому Bybit лишала 15–57 % монет, тобто `D` ≈ 0,56–1,9; поріг 0,405 нижчий за найменше очікуване.

**Другорядне (без власного вердикту):** зміна `log(ΣL6/ΣOI6) − log(ΣLA/ΣOIA)` по кожній монеті (вага каскадів: медіана прорідження каскадів не бачить); `D_A` і `D_6` окремо з плацебо; дослідницький скан: топ-5 дат розрізу з найбільшим `D` по всій історії (пік не на C — нова гіпотеза про дату переходу Coinalyze, не вердикт). По монетах — таблиця BTC / ETH; тест Кокрена на двох активах сенсу не має, тому вимога «обидві одного знака».

**Припущення про Binance.** `.A` — проріджений публічний потік (≤ 1 ордер на символ за секунду, звірка 28.11), і правило прорідження та джерело Coinalyze для Binance не змінювались у 08.2024–09.2025. Ламає його: зміна потоку `forceOrder` Binance або джерела Coinalyze для Binance в цьому проміжку, зміна механіки ліквідацій Binance; частково ловить правило «Binance ламається сам». Інший конфаундер: після зламу могла змінитись структура плеча клієнтів Bybit (ліквідації на одиницю OI), а не потік; нормування на OI цього не прибирає, тож ✓ означає «розрив, сумісний зі зміною каналу», а не доказ каналу.

**Що означає кожен результат для п. 5.** ✓ або «інший розрив» або ◯: рядки `.6` `liq_usd` до 2025-03-07 позначити непорівнянними; суми `.A + .6` і рівні `.6` через дату не використовувати; на 2022–2025 `.6` — лише як нижня межа всередині періоду (без поправочного множника: прорідження нелінійне на каскадах). ✗: рівень `.6` відносно `.A` через дату стабільний у межах ±25 % — але лишається недоведеним: повнота кожного потоку в кожному періоді (обидва можуть бути однаково проріджені або Coinalyze міг брати не старий WS-топік), форма каскадів (медіана їх не бачить; дивитись другорядну статистику), рядки до 2024-08-17.

**Брама даних.** `--stage run` відмовляє, якщо будь-який з 8 рядів (4 символи × `liq_usd`, `oi_usd`) не покриває 2024-08-16..2025-09-02 або має там > 2 % пропущених днів. Покриття 28.11 06:10 UTC (`--stage coverage`, лише `ts`): `oi_usd` усі 4 — 1490 рядів 2022-10-30..2026-11-27 без дірок; `liq_usd` — 2022-11-28..2024-11-16 (`.A` по 720, `BTCUSDT.6` 719, `ETHUSDT.6` 718; пропущені дні: `BTCUSDT.6` 2023-09-23, `ETHUSDT.6` 2023-09-09 і 2023-09-23), брама закрита — бекфіл триває.

**Продовжити з** (після бекфілу, коли `liq_usd` дійде до вчорашнього дня, орієнтовно 28.11 13:00–14:00 UTC): `uv run python scripts/verify_coinalyze_bybit_break.py --stage coverage`, і якщо обидві колонки `ok` — `uv run python scripts/verify_coinalyze_bybit_break.py --stage run --out ~/.cache/tradedesk-agents/coinalyze-bybit-break/result.json`; далі звіт `docs/verification/YYYY-MM-DD-coinalyze-bybit-break.md`.
