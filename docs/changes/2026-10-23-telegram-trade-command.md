- Запис угоди з Telegram: `/trade BTC long 84000 size 0.1 stop 82000 target 90000 thesis …` у темі «💬 Claude» (лише власник; та сама перевірка групи, теми й `from.id`, що в мосту) пише один рядок у локальний журнал тим самим шляхом, що `journal_add` (`Store.init` + `journal_insert`, статус `open`, теги `telegram` і `option` для опціону), і відповідає правилами 1 і 8 для нової угоди (`analytics.rules_check.trade_checks`, депозит $10 000). Нової бази не створює: немає файла — відмова.
- Розбір — чиста `analytics/trade_command.py`, сувора: незнайоме слово, `84,000`, `nan`, не-ASCII цифри, стоп чи ціль не з того боку, `/trade long short …`, опціон з минулою експірацією — відмова з поясненням українською. Премія опціону — $ за 1 монету; менша за 1 приймається лише з `$` (`$0.4`), бо `0.012` — це, найімовірніше, BTC/ETH з Deribit. Суми менші за $1 у відповіді показано з трьома значущими цифрами.
- Міст `scripts/tg_bridge.py` запускає `scripts/journal_trade_tg.py` через `uv run --frozen`, текст — одним аргументом без shell; NUL у тексті — відмова; stderr скрипта при збої — у лог мосту. Переслане повідомлення з `/trade` не записується (це дані для Claude). Жодних ордерів, ліміти не змінюються.
