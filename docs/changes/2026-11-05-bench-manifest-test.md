# 2026-11-05 — тест маніфесту sha256 кешу бенчмарку carry

Пункт 76 [IDEA-20261102-standing-improvements](../ideas/IDEA-20261102-standing-improvements.md), BACKLOG 6.10.

- **`scripts/paper_bench_manifest.py` покрито** трьома тестами в `tests/test_forward_scripts.py` (кеш у `tmp_path`, без мережі й БД):
  - формат рядка `<64 hex>  <відносний шлях>`: шляхи відносні до кешу (зокрема вкладені `binance/funding/…`), логи, `.txt` і тека з назвою `*.json` пропускаються; хеші збігаються з еталоном FIPS для `abc`, з хешем порожнього файлу і з `hashlib` для файлу понад 1 МіБ (кілька блоків читання); підсумок «4 files, … MB» у виводі;
  - справжній `sha256sum -c --strict` з теки кешу проходить, а після зміни одного файлу показує `FAILED` (якщо `sha256sum` є в системі; на Linux і в CI є);
  - порядок: ті самі файли, створені в зворотному порядку в іншій теці, дають побайтно однаковий маніфест, відсортований за шляхом;
  - порожній кеш: маніфест з одного порожнього рядка, «0 files, 0.0 MB».
- **Розбіжність (код не змінено, записано в BACKLOG 6.10):** маніфест порожнього кешу `sha256sum -c` відхиляє (код 1, «no properly formatted checksum lines found»). Для бенчмарку це не заважає (кеш не порожній), але перевірка «нічого не змінилось» на порожньому кеші не пройде.
- **Лишився без тесту** `stage0_condor_forward.py` (потрібна фікстура кешу `put_skew`).
