- Картка [onchain-parity](../ideas/IDEA-20261114-onchain-parity.md), пункт 2: чотири EVM-інструменти на Etherscan API V2 з параметром `chain` (ethereum, bsc, polygon, arbitrum, optimism, base, avalanche; псевдоніми eth, bnb, matic, arb, op, avax і числовий chain id) — `onchain_balance` (баланс у нативній монеті, а з `token` — в ERC-20: `balance_raw` точним рядком у найменших одиницях + `balance` числом з урахуванням decimals), `onchain_address_txs` (`kind="normal"` — зовнішні транзакції адреси, `kind="erc20"` — перекази токенів, фільтр `token`; нові спершу, `limit` ≤ 100, `page` × `limit` ≤ 10 000), `onchain_token_info` (назва, символ, decimals, total supply з контракту через `eth_call`), `onchain_contract_source` (verified, компілятор, proxy й implementation, перелік файлів; сам код лише уривком `source_chars` ≤ 4000).
- Провайдер `providers/etherscan.py` (2 запити/с без сплеску; безкоштовний ключ дає 3/с і ділиться зі скриптами дослідження), чисті функції — `analytics/evm.py` (перевірка адреси, декодування `eth_call`, рядки транзакцій, зведення коду). Адреси перевіряються (0x + 40 hex) до запиту. Відповіді HTTP 200 зі `status: "0"` розбираються: «No transactions found» — порожня сторінка, а не помилка; ліміт → `rate_limited`, ключ → `auth`, платна мережа чи ендпоінт → `provider_tier`. Текст помилки Etherscan не повторюється (недовірений).
- Ключ: лише `ETHERSCAN_API_KEY` із середовища через `Settings`; у запит іде параметром, тому переданий `Http` як секрет (вирізається з тексту помилок), у `evidence` його нема (тест це перевіряє). Без ключа — `ok=false`, `missing` з причиною `config`, без запиту.
- Топ-холдери не зроблено: `token/topholders` і `tokenholderlist` — лише платний Etherscan API Pro (концентрацію топ-10 дає `contract_risk`).
- Зразок `tests/fixtures/etherscan_v2_docs_2026-11-19.json` — **з документації Etherscan, не живий** (агенти ключа не мають); єдиний живий запис — відповідь без ключа, знята з сервера 19.11 (`Missing/Invalid API Key`, той самий конверт `status/message/result`, і для `proxy/eth_call` теж). Тести — `tests/test_evm.py`; охоронці (`test_tools_envelope_shape`, `test_tools_wrong_type_fields`, `test_tools_provider_outage`, `test_provider_lifecycle`, `test_tools_never_raise`) отримали фейк Etherscan і тестовий ключ-заглушку.
- Після рев'ю: відповідь `proxy/eth_call` вважається відповіддю (і кешується) лише тоді, коли `result` є hex або `error` каже про revert. Інші помилки вузла («header not found») і не-hex `result` (текст ліміту) стають `backend_error` / `rate_limited` і не кешуються, тож разовий збій більше не видається на годину за «не ERC-20». Тести з увімкненим кешем: транзитна помилка, revert і порожня сторінка проти NOTOK. `onchain_balance(token=…)` попереджає, що адреса не схожа на ERC-20, коли не прочиталися ні decimals, ні symbol (без додаткових запитів).
- Відкрите: служба MCP ключа не бачить (він у `~/.config/tradedesk/onchain.env`, а служба читає лише `/etc/tradedesk-mcp.env` і має `ProtectHome=yes`), тож на сервері інструменти поки відповідають `missing: config`.
