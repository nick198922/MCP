# Рев'ю: версія формату в кеші барів carry B (пункт 448), 23.11

Вердикт: **approve**.

Перевірив сам: `git diff` (скрипт, тест, change-файл), `make lint` (чисто), `uv run pytest -q tests/test_carry_leg_gap.py` (16 passed), Grep індексів барів у `scripts/verify_carry_b_leg_gap.py` і `analytics/carry_leg_gap.py`.

## Перевірено

1. Ключ кешу містить версію. `cache_path()` додає `CACHE_VERSION = "v2"` префіксом до імені, `bars()` читає і пише лише через неї. Старий файл без префікса не збігається за іменем, тож не читається. З `--no-fetch` це дає порожній словник і «◯ no data», а не хибний «R1 zero volume». Це чесніше, ніж успадкувати нулі.
2. Невідомі open/high/low лишаються `None`. Рядок без close відкидається (умова `r[4] is not None`), тому `close` (індекс 3 у збереженому списку) завжди число.
3. Нічого не ламається:
   - `minute_gap` у скрипті бере лише `v[3]`, тобто close, який не `None`.
   - `row_checks` використовує лише `bar[3]` (з перевіркою на `None`) і `bar[4]` через `_vol`, який теж обробляє `None`.
   - JSON-кеш: `None` ↔ `null` зберігається без втрат, тест перевіряє круговий прохід.
4. Тести падали б без зміни:
   - Без версії в імені `test_bar_cache_name_carries_the_format_version` і `test_unversioned_bar_cache_is_not_read` падають: старий файл був би прочитаний.
   - `test_bars_keep_unknown_ohlc_and_volume_as_none` падає на старому коді через `0.0` замість `None`.
   - Тести без мережі: фейковий `rt.exchanges.ohlcv`.
5. Обсяг змін: лише скрипт, тест, change-файл і відмітка в картці. `registry.csv` і код у `src/` не зачеплено.

## Зауваження (не блокують)

1. Тести завантажують скрипт через `importlib` з `exec_module` на рівні модуля тесту. Якщо в майбутньому скрипт отримає побічні дії на рівні модуля (наприклад, читання `~/.cache` або аргументів), імпорт у тестах зламається. Зараз `CACHE` лише обчислює `Path`, тож безпечно.
2. Старі файли в `~/.cache/.../carry_b_leg_gap` лишаються на диску без очищення (`rm` агентам заборонено). Це задокументовано в картці. Власнику варто колись прибрати їх вручну.
3. Припущення «`bars` у `row_checks` використовують лише close і volume» не закріплено тестом на `None` у high/low. Є непрямий тест, який перевіряє `row_checks` з `None` open/high/low (`checks[0]["close_a"] == 2.0`). Для цієї зміни цього достатньо.
