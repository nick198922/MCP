- Картка [standing-improvements](../ideas/IDEA-20261102-standing-improvements.md), пункт 399 (рев'ю [2026-11-19-etherscan-onchain-tools](../reviews/2026-11-19-etherscan-onchain-tools.md), знахідка 5): провайдер Etherscan повторює запит **один раз через ~1 с**, коли ліміт запитів приходить у тілі HTTP 200 (текст «rate limit», і в модульних відповідях, і в `proxy/eth_call`). Максимум два запити на виклик; якщо ліміт повторився, поле йде в `missing` з причиною `rate_limited`, як і раніше.
- Інші відповіді NOTOK (ключ, платний план, невідома помилка) не повторюються й не кешуються; HTTP 429 і далі ретраїть лише `Http` за своїми налаштуваннями, провайдер його не повторює вдруге.
- Пауза — через інжектовану `sleep` у `Etherscan` (тести її підміняють і нічого не чекають). В описах усіх чотирьох `onchain_*` додано одне речення про цей повтор; форма інструментів не змінилась (PARITY без змін).
- Тести (`tests/test_evm.py`): ліміт, потім успіх → дані є, 2 запити, одна пауза 1 с; ліміт на кожному `eth_call` → по одному повтору на поле; ліміт двічі → `missing: rate_limited` рівно після 2 запитів; auth / provider_tier / невідомий NOTOK / HTTP 429 → один запит без паузи. Два наявні тести кешу підлаштовано під повтор.
