# 2026-11-12 · Повільні сканери в тестах: кожен файл розбирається один раз (пункт 330)

Пункт 330 [постійної картки](../ideas/IDEA-20261102-standing-improvements.md), продовження пункту 327. Змінено лише `tests/test_scripts_import_safe.py` і `tests/test_deps_check.py`. `src/`, `scripts/` і `execution/` не чіпав. Знахідки й асерти ті самі.

- **Замір:** `uv run pytest -q <файл> --durations=3` (без xdist), до → після:
  - `test_scripts_import_safe::test_scripts_import_without_side_effects`: 8.9 → 5.0 с (−44 %). Сам `scan()`: 7.8 → 4.5 с у тому самому процесі.
  - `test_deps_check`: два тести по репозиторію, 6.4 + 4.6 = 11.0 с → один на 6.2 с (−44 %).
  - `test_naive_datetime::test_no_naive_time_outside_allowed`: 7.4 с, **не змінено**. Розбір 258 файлів після префільтра забирає 4.0 з 6.9 с. Швидший обхід дерева і вимкнений GC дають разом лише ≈ 20 %, а вужчий префільтр відсіює тільки 32 файли з 258 і може щось пропустити.
- **`test_scripts_import_safe.scan`.** Раніше кожен скрипт розбирався двічі: спершу для `module_info`, потім для власної перевірки. Тепер дерево розбирається один раз. Коли `module_info` прочитав тіла функцій, `_prune` спорожнює те, чого перевірка не читає: тіла функцій (у `def` перевіряються лише декоратори й типові значення) і блок `if __name__ == "__main__":`. Обрізане дерево зберігається до перевірки. Пік пам'яті 95 → 98 МіБ. Повні дерева всіх файлів (≈ 340 МіБ) так само не тримаються.
- **Що перевірено.** `scan()` на `scripts/` збігся з версією з HEAD: 249 файлів, ті самі 5 файлів зі знахідками. Окремо прогнав кожен із 250 файлів без жодної інформації про модуль, тобто безпечні лише `SAFE_CALLS` / `SAFE_METHODS`. Повне й обрізане дерево дали ті самі 129 знахідок, розбіжностей 0. Новий тест `test_pruned_tree_gives_the_same_findings` перевіряє це на фікстурі: тіло класу, метод, `try`, `__main__`.
- **`test_deps_check`.** `test_repository_scripts_import_nothing_undeclared_unconditionally` вдруге розбирав `scripts/`, хоча `main` на репозиторії вже розібрав. Тепер його асерти стоять у `test_main_on_repository`: `undeclared == []` і медійні пакети серед умовних. Беруться вони зі звіту, який будує сам `main`: обгортка над `dc.check` лише запам'ятовує результат. Дані ті самі: джерела й локальні імена з `load_scope`, той самий pyproject. Додано асерт, що в скоупі `scripts/` стільки ж файлів, скільки повертає `load_scope`, і їх понад 200.
- `make lint` чисто. Змінені файли: 14 + 15 passed, `test_naive_datetime` — 3 passed.
