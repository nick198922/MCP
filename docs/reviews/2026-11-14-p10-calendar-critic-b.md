## Зауваження

1. **(низька) H3: ✗ проти ◯, код не збігається з текстом реєстрації.** Абзац «Ворота покриття» (не пройдено → ◯) і рядок стадії 0 («вердикт за реєстрацією вже визначено: ◯») закомічено до P&L. Тому ◯ для H3 — правильне прочитання реєстрації, а не послаблення після результатів. До того ж ✗ на n = 2, коли ворота хвоста не пройдено (бутстреп із двох точок), нічого не важив би. Але `calendar_p10.verdict` знижує до ◯ лише ✓ / ≈, а його docstring стверджує «text and code identical», що неправда. Таблиця «Вердикти» у звіті показує **✗** для H3, і лише «Підсумок» та застереження 3 пояснюють, чому прийнято ◯. **Виправлення (у кроці P5, цю реєстрацію не чіпати):** у новому `verdict` непройдені ворота покриття дають ◯ для будь-якої мітки, плюс тест на випадок «hi < 0 і coverage_ok=False → ◯»; у таблиці вердиктів друкувати остаточну мітку поруч із механічною.
2. **(низька) Вироджена статистика за малого n.** Для IS (n = 3) і рядків по роках друкується p 0.000 та CI без ширини, блоковий бутстреп H1 дає [+0.016; +0.050] (верхня межа дорівнює середньому), «без 5 найкращих» дає `+nan`. Вердикт це не зачіпає (◯ за покриттям), а застереження 5 частково про це каже. **Виправлення (у спільних хелперах наступного скрипта):** за n < 5 замість p і CI друкувати «—».
3. **(середня, на майбутнє) Форвардний критерій недостатній за потужністю.** З H1 SE = 0.294 / 2.8 ≈ 0.105 при n = 5, тобто SD R ≈ 0.235. Тоді MDE за 15 угод ≈ 2.8 × 0.235 / √15 ≈ 0.17 R > EDGE_R 0.10. Частота: ≈ 20 подій на рік × 18 % ≈ 3.6 угоди на рік, отже 15 угод — це ≈ 4 роки. Перегляд «після ≥ 15 угод» зможе лише вбити ідею за великого мінуса. **Виправлення (у форвардній картці):** записати це прямо; kill-критерій — верхня межа CI < 0 або середнє ≤ 0 після 15 угод; ✓ не обіцяти раніше ніж за ≈ 40 угод (MDE ≈ 0.10).
4. **(інфо) Попередня перевірка вимірюваності помилилася на неправильній підмножині.** Абзац «Чи вимірюється» рахував 210 / 302 по всіх суботах, а не по суботах із подією, і дійшов висновку «◯ не вимірюється не потрібен».
