# 2026-11-12 — Carry A: зупинена книга не качає історію funding усього універсуму (пункт 342)

- Джерело: пункт 342 [постійної картки](../ideas/IDEA-20261102-standing-improvements.md), BACKLOG «Форвард-папір carry», пункт A. З 11.11 нові входи A зупинено, але кожен цикл A усе ще читав історію funding Binance для всього універсуму (≈ 400 запитів за 8 год на ліміті 500/5 хв IP, спільному з колектором).
- Рушій (`collector/carry_paper_engine.py`): коли `entries_stopped` задано, просить у фіда `load(..., held_only=True)`; без зупинки виклик той самий, що й раніше.
- Фід (`collector/carry_paper_feed.py`, книга A): з `held_only` історія funding і свічки — лише для символів відкритих позицій A. Немає позицій → 0 запитів історії; є позиція → лише її символ. Списки ринків і поточний funding (кілька масових запитів) лишаються; `universe_size` — як і раніше, весь універсум, `with_data` — лише утримувані символи.
- Не змінено: книга B, правило виходу A (позиція маркується й закривається так само, як без зупинки), `paper_carry_status`, `TRADEDESK_PAPER_CARRY_A_ENTRIES_ENABLED=1` (повний універсум, як раніше).
- Тест: `tests/test_carry_paper_live.py::test_stopped_a_fetches_funding_history_for_held_symbols_only` (фейкова біржа лічить запити історії: зупинено без позицій → 0; зупинено з WIF → лише WIF, стан позиції й рішення циклу такі самі, як у книзі без зупинки; без зупинки → BTC і WIF). На старому коді перша перевірка падає (2 запити замість 0).
- Жива перевірка з сервера 12.11 (`LiveFeed`, без сховища): універсум A 356 символів, без позицій 0 запитів історії; з утримуваною BTC — один запит `binanceusdm:BTC/USDT:USDT`.
