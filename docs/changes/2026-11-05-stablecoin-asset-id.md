- Пункт 58 [standing-improvements](../ideas/IDEA-20261102-standing-improvements.md) (дрібниці рев'ю пункту 57): `stablecoin_asset` у `src/tradedesk/analytics/chain_metrics.py` тепер шукає USDT і USDC за `id` DefiLlama («1» / «2») або за `gecko_id` («tether» / «usd-coin»). Таблиця відповідностей — `STABLECOIN_IDS`. Символ більше не враховується, тож токен-двійник із символом «USDT» не підміняє Tether, навіть якщо його обіг більший. Для символу поза таблицею функція повертає `None`.
- Якщо справжнього USDT чи USDC у відповіді немає, `stablecoin_supply` кладе поле в `missing` з `data_unavailable` (ця гілка вже була в `src/tradedesk/tools/onchain.py`). Інша панель лишається, `ok=true`.
- Провайдер `src/tradedesk/providers/defillama.py` тепер зберігає поле `gecko_id` у скороченій відповіді `/stablecoins`. Без цього пошук за `gecko_id` на живих даних не працював би.
- Тести в `tests/test_stablecoin_supply.py`. Тест `only_fake` тепер очікує `None`. Новий тест перевіряє пошук за id: двійник із більшим обігом програє, `gecko_id` працює і без `id`, USDC ніколи не видається за USDT. Ще один тест перевіряє, що інструмент без справжнього Tether дає `missing` лише для `usdt`. Тест на інваріант 7 викликає інструмент, робить `rt.aclose()` і перевіряє, що клієнт `defillama:stablecoins` закрито. Повторний виклик у тій самій сесії дає `ok=true` через новий клієнт: обидва запити справді йдуть знову.
