# 2026-10-22 — радар у знімку асистента: секція `radar` для BTC і ETH

- Пункт картки [IDEA-20261018-assistant](../ideas/IDEA-20261018-assistant.md) «Радар у знімку асистента», перший зріз. Лише ринкові дані, ордерів немає; нового інструмента MCP немає, вкладки панелі не змінювались.
- Нове: чиста `analytics.radar.radar_view` (час — параметр, без I/O) і допоміжні `iv_rank`, `trailing_rv`, `forward_vols`, `pick_rows`, `normalize_row`. Секція `radar` у `collector/assistant_snapshot.py` (`build_radar`): рядки архіву `radar_surface`, денний DVOL Deribit за 375 днів і 40 денних закриттів Binance — через провайдери (`Builder.guard`), події — секція `events` знімка в її горизонті, далі сід.
- Поля для кожного активу: ціна (індекс Deribit о 19:00 UTC) зараз / тиждень тому / зміна; ATM IV 7/30/90/180 днів зараз / тиждень тому / зміна; IV Rank і перцентиль за денним DVOL за 365 днів зараз і тиждень тому; IV 30 днів проти RV30 і RV7; put skew і RR 25Δ зараз / тиждень тому / зміна; усмішка 10/25/35Δ / ATM; форвардна вола між сусідніми експіраціями з подіями у вікні та позначкою «гарячий тиждень». Одиниці — десяткові дроби.
- Без рядка архіву за потрібний день поля поверхні `null`, причина — у `missing` активу; збій біржі — у `missing` секції; виняток усередині — секція `ok=false`, знімок пишеться (інваріант 1). У `warnings` — метод, конвенція дельт скью, «низький IV Rank → купувати» нашими даними не підтверджено, події збігаються лише за датою.
- Тести: аналітичні еталони (IV Rank, RV, форвардна вола, межі вікон подій, недовірений текст), справжній зразок `tests/fixtures/radar_snapshot_inputs_2026-10-22.json` (рядки архіву 11.10 і 18.10, денний DVOL, закриття Binance; отримано з сервера 22.10) проти таблиці LIB і картки: IV Rank BTC 02.09 / 13.09 / 27.09 / 04.10 / 11.10 = 6.9 / 10.4 / 3.0 / 5.9 / 7.6 %, ATM 18.10 34.1/37.0/37.1/38.2, skew 2.65 вп, форвардна вола 30.10→06.11 42 %; знімок — щасливий шлях з архівом, збій Deribit, виняток у радарі, без сховища.
- Після рев'ю (`docs/reviews/2026-10-22-radar-snapshot.md`): запобіжник «усі секції впали → попередній файл лишається» більше не рахує секцію `radar` (вона може мати дані лише з локального архіву без мережі) — тест «мережі немає, архів є»; форвардна вола не показує вікон, що закінчились до моменту знімка (рядок архіву може бути старшим до 2 днів) — тест на рядок дводенної давнини; тест, що `radar_view` ігнорує DVOL і закриття після `now` на нефільтрованому зразку; у панелі й брифі секція підписана «радар».
- Живу перевірку зроблено з сервера 22.10 12:25 UTC на тимчасовій базі: обидва активи без `missing`, BTC 30.10→06.11 — 40.6 %, «гарячий» (вибори 03.11). На робочому сервері поверхня з'явиться після ввімкнення `radar_archive` і бекфілу.
