# 2026-11-05 — колектор трейдерів: Polymarket data-api v2 замість вимкненого v1

Пункт 79 [IDEA-20261102-standing-improvements](../ideas/IDEA-20261102-standing-improvements.md).

- **Що зламалось.** 02.11 Polymarket вимкнула data-api v1: `/v1/leaderboard`, `/positions` і `/trades` відповідають HTTP 410 «Data API v1 has been retired» (живий виклик з сервера 05.11). У живій БД останній знімок `trader_snapshot` для `polymarket` / `polymarket_crypto` — за 02.11, останній рядок `trader_positions` Polymarket — 02.11 22:22 UTC. Джоба `traders` тільки писала попередження, бо Hyperliquid записувався далі, а `collector_health` ці таблиці не перевіряє (BACKLOG 6.13 (б)).
- **`providers/polymarket.py`:** `leaderboard` тепер ходить на `/v2/leaderboard` (`time_period`, `category`, `sort_by`, `cursor`) і повертає одну сторінку як `{"rows", "next_cursor"}`. `positions` ходить на `/v2/positions` з `filter_type=CASH`, `filter_amount=100`: так приходять відкриті позиції від $100, найбільші першими. Програні розв'язані позиції з вартістю 0 відсікаються ще на боці API. Конверт v2 обов'язковий: тіло має бути словником з ключем `data` (список або null) і словником `pagination`. Голий список у стилі v1, `{}`, `{"error": …}` з HTTP 200 чи `data` без `pagination` дають `ProviderError`, а не порожню сторінку: для позицій порожня сторінка означала б «закрито все», і колектор записав би кожну збережену позицію гаманця як `closed` (виправлення після рев'ю C). `trades` лишився на v1, бо його беруть лише скрипти досліджень (BACKLOG 6.13 (а)).
- **Колектор (`collector/scheduler.py`).** Лідерборд іде курсором, доки `next_cursor` не стане null, але не більше `traders_pm_pages` сторінок по 50, як і раніше. Поля читаються зі snake_case: `user_id`, `user_name`, `volume`, `token_id`, `current_size`, `avg_price`, `current_value`, `unrealized_pnl`. Позиції, які не є `OPEN`, і позиції з `redeemable` відкидаються, як і раніше. Таблиці й колонки не змінено.
- **Ряди тягнуться далі.** `user_id` у v2 — це та сама адреса, що `proxyWallet` у v1; `token_id` — той самий токен, що `asset`; `unrealized_pnl` рахується так само, як `cashPnl` (вартість мінус вхід без комісії). Живцем 05.11: 500 акаунтів на рейтинг (10 сторінок); `pnl_all` топ-3 акаунтів збігся зі знімком 02.11 до цента; 923 з 1 308 акаунтів overall є і в знімку 02.11; у топ-1 місяця 46 відкритих позицій, 32 з них уже були в журналі v1.
- **Втрачене.** Денних знімків Polymarket за 03.11–05.11 (до оновлення коду на сервері) немає, і відновити їх не можна, бо лідерборд віддає лише поточний стан. Перший зріз «розумних грошей» 16.11 має це врахувати.
- **Тести:** `tests/test_traders.py` переведено на справжню відповідь v2 від 05.11 (`tests/fixtures/polymarket_data_v2_2026-11-05.json`, адреси вигадані). Нові тести: поля v2 і прохід курсором (мок, як і живий API, відповідає 400 на `offset`); 410 від v1 не заважає записати Hyperliquid; відповідь у формі v1 дає `ProviderError`; тіло без конверта після baseline-прогону не дає жодного `closed` для Polymarket, а Hyperliquid у тому ж прогоні записується; курсор, що ніколи не закінчується (як живий), зупиняється рівно на `traders_pm_pages` запитах на рейтинг; рядок зі `status` не `OPEN` не пишеться. Фікстура лідерборду v1 від 15.10 лишилась саме для перевірки форми v1. Фікстура позицій v1 `tests/fixtures/polymarket_positions_sample_2026-10-15.json` **застаріла**: її не читає жоден тест, лишена в репозиторії лише тому, що агенту не дозволено видаляти файли; власник може її видалити.
