### Звіт контрольної точки називає відсутню таблицю форварду (пункт 104 standing-improvements)

- Джерело: [рев'ю пункту 100](../reviews/2026-11-05-checkpoint-report-missing-tables.md), зауваження 1 («не блокує»).
- `scripts/checkpoint_report.py`: список `FORWARD_TABLES` (8 таблиць, які читають блоки звіту) звіряється з `sqlite_master`. Для кожної відсутньої таблиці в звіті є рядок «Примітка: <таблиця>: таблиці немає в БД (старіша схема чи інша БД), блок без даних». Раніше такий блок мовчки показував n = 0, як форвард без угод.
- Кондор після T0: якщо `option_leg_snapshot` немає, завантажувач не викликається. Примітка тепер «таблиці немає», а не «запит не вдався (OperationalError)».
- Якщо схему не вдалося прочитати (файл не SQLite), звіт не стверджує, що таблиць немає. Як і раніше, кожен блок пише «запит не вдався».
- Правила, пороги, вердикти, колектори, міграції й `execution/` не змінено. Заборону підглядання не порушено: для перевірки читається лише `sqlite_master`, рядків таблиць ніхто не читає.
- Тести (`tests/test_checkpoint_report.py`): охоронець пункту 100 тепер вимагає рівно одну таку примітку для видаленої таблиці, жодної для порожньої та жодного «запит не вдався». Новий тест перевіряє файл, що не є SQLite. Мутацією перевірено, що без захисту кондора тест падає.
- Живий прогін 05.11 (`--date 2026-11-05`, БД сервера, `mode=ro`): є всі 8 таблиць, приміток немає, звіт не змінився.
- Окремо не зроблено (зауваження 1, друга частина): збій запиту в одній таблиці `cp_*` і далі обнуляє весь блок carry. Так і задумано: блок carry з частиною таблиць (наприклад, без `cp_cycle`) дав би вердикт за неповними даними, а порожній блок із примітками — ні.
