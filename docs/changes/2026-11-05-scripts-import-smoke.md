# 05.11 — Димовий тест імпорту скриптів (пункт 120)

- Новий `tests/test_scripts_import.py`. Перевіряє всі 210 скриптів `scripts/*.py` верхнього рівня (без `scripts/server/`, `research/`, `mac/` і допоміжних `_*.py` / `common_helpers.py`). Мережі, БД і ключів тест не торкається.
- Статична частина (лише `ast`, скрипт не запускається). Файл має розбиратися. Кожне ім'я з `from common_helpers import …`, із сусіднього скрипта чи з `tradedesk…` має існувати; враховано й імпорти всередині функцій. Так само перевіряються звертання `cmn.X` до модуля, імпортованого як `import common_helpers as cmn`. Якщо ім'я перевизначене локально (параметр чи змінна `st`), звертання не перевіряється.
- Імпорт: 208 скриптів із захистом `if __name__ == "__main__"` імпортуються в одному дочірньому процесі. Сокети в ньому вимкнені, оточення зведене до `PATH`/`HOME` (тимчасовий)/`PYTHONPATH`. `main` не викликається.
- Зламаних скриптів знайдено 0, тож виправляти не було чого. Скрипти форварду (`condor_forward_costs.py`, `pm_gap_paper_report.py`, `paper_carry_report.py`, `checkpoint_report.py`) теж проходять.
- Винятки записано в тесті з причинами:
  - `verify_demo_trend_veto.py` і `explore_us_open_calls.py` роблять роботу на рівні модуля, тому для них лише статична перевірка;
  - `lesson_sheets.py` запускається з `--with pillow`, тож для нього допускається лише відсутній `PIL`;
  - `KNOWN_BROKEN` порожній.
- Тест падає, якщо з'являється новий скрипт без захисту `__main__` або якщо в списках винятків лишився застарілий запис. Самоперевірка на синтетичному скрипті підтверджує, що тест ловить відсутні імена, модулі й `cmn.X`, а на затіненні не спрацьовує.
- Скрипти не змінено.
