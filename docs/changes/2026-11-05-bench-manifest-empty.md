# 2026-11-05 — маніфест sha256: порожній кеш тепер помилка

Пункт 77 [IDEA-20261102-standing-improvements](../ideas/IDEA-20261102-standing-improvements.md), BACKLOG 6.10 (розбіжність пункту 76).

- **`scripts/paper_bench_manifest.py`:** якщо в кеші немає жодного `*.json` (кеш порожній, лише логи або теки немає), скрипт завершується з кодом 1 і повідомленням `cache is empty: …; manifest not written` у stderr. Маніфест не пишеться, а наявний попередній маніфест не перезаписується.
- **Чому не порожній файл:** `sha256sum -c --strict` відхиляє й порожній файл (перевірено на сервері: код 1, «no properly formatted checksum lines found»), тобто він так само зламав би перевірку. Помилка з ненульовим кодом простіша й безпечніша для розбору 30.11: порожній кеш не можна прийняти за «нічого не змінилось», а добрий маніфест не затирається.
- **Тест `test_paper_bench_manifest_empty_cache`** перевіряє код виходу й повідомлення (зокрема окремим процесом: текст у stderr, stdout порожній), те, що файл не з'явився, що попередній маніфест лишився без змін, і випадок, коли теки кешу немає. Решта тестів маніфесту без змін.
- Колектори, заморожені форварди й `execution/` не змінювалися.
