# ADR 0005 — Безпека виконання ордерів

Статус: прийнято (2026-10-10). Реалізація — Фаза 4.

1. До появи пакета `execution/` у коді немає жодного виклику, що ставить/скасовує ордери. Режим за замовчуванням — read-only.
2. Усе виконання проходить через `ExecutionGuard`: allowlist інструментів, ліміти розміру/notional/плеча, денний max-loss, kill-switch, режим `paper → testnet → live` (підвищення лише явною зміною конфігурації).
3. Двокроковий потік: `order_propose` (розрахунок, без побічних ефектів) → `order_confirm(proposal_id)` (TTL, одноразовий idempotency-ключ).
4. Дані із зовнішніх джерел (назви ринків, новини, коментарі) ніколи не можуть запускати ордер або змінювати ліміти (захист від prompt-injection).
5. Ключі бірж: без права виведення, з IP allow-list; окремі ключі для testnet і live; лише в оточенні/секрет-сховищі.
6. Append-only аудит-лог кожної пропозиції, підтвердження й відповіді біржі.
7. Перші live-ордери — лише разом із власником, на мінімальному розмірі.
