## Інструменти і ринок
USDT-перпи Binance (і Bybit, якщо нема на Binance) для монет зі списку trending CoinGecko. Шорт перпа 3-7 діб, хедж бети BTC. Ручна чи демо-угода.

## Механізм
Хто платить: роздрібні покупці, що приходять через пошук і стрічки «трендів» уже після руху: увага → покупка лотерейної монети (поведінкова література про увагу інвесторів). Арбітраж обмежений (позика токена, сквіз), тож ціна тримається вище справедливої, доки не зійде увага. Другий платник — funding лонгів (перевіряти фактичними виплатами).
Чому може тривати: щодня нова хвиля новачків, структура платформи (список trending відкритий і публічний) не змінюється.
Що ламає: продовження імпульсу, якщо trending викликано справжньою новиною (лістинг на великій біржі); тоді потрібна умова «до початку руху ще нема +50 % за 7 діб» (щоб не перетинатись із `extreme-pump-fade-short`).

**Чим відрізняється від протестованого.** `extreme-pump-fade-short` (rejected) ловить подію за ціною (+50 %/7 діб); тут подія — увага (пошук) і, зокрема, монети з помірним рухом, які ціновий фільтр не бачить. `hodler-airdrop-listing-fade-short` і `new-perp-listing-drift` — лістинги. Рішення з форварду, бо історії trending у безкоштовному API нема (перевірити документацію на крок 0).

## Гіпотеза
Подія: символ перший раз за 14 діб входить у топ-15 trending CoinGecko, має перп на Binance, ціна за 7 діб до події росте менш ніж на 50 %. Вхід: наступне закриття години.
H1 (фіксовано наперед): середня 72-год дохідність шорту (після бети BTC і витрат 0.3 % + реальний funding) ≥ +1.5 п.п. на ≥ 300 подіях.
H2: той самий знак, якщо розділити на перші й другі 50 % подій у часі.

## Дані
Немає в колекторі: список trending з CoinGecko (безкоштовний `/search/trending`, 15 монет, оновлення кожні ~10-15 хв за описом постачальника, не перевірено) — щогодинний запис накопичить історію з нуля. Ціни, funding — є (ccxt).

## Як тестувати
Журнал подій, 72-год і 7-д дохідність вперед, бета BTC через ковзаючий OLS, bootstrap по днях (кластер за днем), порівняння з випадковими монетами тієї ж ліквідності (плацебо 1 000).

## Очікувана величина і витрати
Якщо правда: 1.5-3 п.п. на подію, ~3-5 подій на тиждень з перпом → ≈ 10-20 % на капітал, виділений на шорт, до хвостів. Тест: 4 год розробника на запис + 3 год Claude на аналіз.

## Цінність (до перевірки)
Ефект ≈ +10 % на рік на шортовий капітал · імовірність ≈ 10 % (контрпунктів: pump-fade і лістинг-дрейф не підтвердилися) · вартість ≈ 7 год + 90 днів очікування · оцінка = 10 × 0.10 / 7 ≈ 0.14. Форвардна, бо без запису тестувати нічим.

## Потужність (до перегляду даних)
Очікується ~3-5 нових подій/тиждень з перпом → за 90 днів ≈ 40-65 подій, за 180 днів ≈ 100-130; щоб набрати 300 подій потрібно ≈ 15-18 місяців. SD 72-год дохідності ≈ 12 п.п. MDE при n = 130 ≈ 2.8 × 12 / √130 ≈ 2.9 п.п. > очікуваних 1.5; при n = 300 ≈ 1.9 п.п. Тому: вердикт не раніше n = 300 (або ефект ≥ 3 п.п. раніше); до цього лише `forward`. Така потужність слабка — чесна оцінка.

## Ризики
Сквіз на мікрокапах; trending як ознака реальної новини; зміна ендпоінта чи ліміти API; нестабільність списку (15 позицій, багато стейблів і мейджорів — виключити).

## Критерій «вбити»
На n ≥ 300 середня шортова дохідність після витрат ≤ 0 або CI містить 0 з верхньою межею < 1.5 п.п. → rejected. Ендпоінт став платним або зник → закрити.

## Тріаж критика
**Вердикт: forward** (2026-10-28). Механізм (увага → роздрібна покупка лотерейних монет, обмежений арбітраж) правдоподібний; дублікатів нема (`extreme-pump-fade-short` — за ціною, лістинг-картки — за подією лістингу; пошук по docs за trending/attention збігів з такою подією не дав; у `src/` ендпоінта trending нема, є лише провайдер CoinGecko). Історії списку trending у безкоштовному API нема, тож історично не перевірити: це не причина відхиляти.

- **Потужність (чесно слабка).** SD 72-год ≈ 12 п.п.: n = 130 → MDE ≈ 2.9 п.п.; n = 300 → ≈ 1.9 п.п. при очікуваних 1.5 п.п. Навіть на n = 300 ефект 1.5 п.п. нижче MDE, тому «підтвердити» можна лише ефект ≥ ~2 п.п. Подій буде менше за 3-5/тиждень, бо умова «перший раз за 14 діб + перп на Binance + без стейблів і мейджорів + не +50 %/7 д» відсікає більшість 15 позицій: реалістично 1-3/тиждень, тобто n = 300 — 2-3 роки. Тому суд переносимо на раннє «марне» правило (нижче), а не на n = 300.
- **Кореляція подій.** Монети з trending кластеризуються в дні (ринковий ралі); похибки рахувати кластерами по дню, а дохідність очищати від бети BTC, інакше n завищено.
- **Дані й ціна.** Вартість 7 год + очікування; оцінка 0.14 прийнята, імовірність 10 % — оптимістична (близькі ідеї pump-fade і лістинг-дрейф відхилені/форвард), реалістично ≈ 5 %. Запис безплатний, ризику нема.
- **Lookahead (рев'ю коду 29.10).** Рядок має ключ `ts` = початок години, а список відомий лише в `fetched_ts`: вхід — перше закриття години строго після `fetched_ts`, не після `ts`. Монети зіставляти за `coin_id` через явну мапу, не за тікером (колізії, `1000…`). Запис trending має мітку часу знімка; подія — перший знімок у топ-15; вхід — наступне закриття години після знімка, не раніше.

## Форвард
- **Тригер:** символ уперше за 14 діб у топ-15 `/search/trending` CoinGecko, має USDT-перп (Binance, інакше Bybit), не стейбл/мейджор/обгорнутий, ріст за 7 діб до знімка < 50 %.
- **План:** шорт перпа, хедж лонгом BTC-перпа на бету (або без хеджу окремою міткою). Вхід — наступне закриття години після знімка; стоп +25 % від входу; ціль нема, вихід +72 год; розмір ≤ 0.5 % капіталу, плече ≤ 2x.
- **Що записувати щоразу:** час знімка, позиція в списку, ціна/обіг/капа, 7-д дохідність до події, funding, результат на 24/72/168 год, бета-очищений результат, чи був новинний лістинг (так/ні).
- **Коли судити:** перше читання після n = 40; вердикт після n = 150, або n = 300 для малого ефекту.
- **Критерій «вбити»:** n ≥ 100 і середній бета-очищений результат шорту після витрат ≤ 0 (кластерний ДІ верхня межа < 1.5 п.п.) → rejected; ендпоінт платний чи зник → закрити; на n ≥ 150 і ДІ без нуля та ≥ +1.5 п.п. → перевірити OOS-половину (H2) і лише тоді піднімати.
