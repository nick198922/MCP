# 2026-11-23 — лікар: «stuck»-робота отримує один останній прогін під час простою, а її PR стає готовим до злиття

- **Причина простою 19–23.11 (150+ прогонів без кроку):** 18.11 гілку `agent/2026-11-18-x-btc-charlie-sample-registration` віддали власнику як «stuck». Критик її схвалив, там лише документи, а «stuck» вона через помилку оформлення в 5-му прогоні (виправлено в #1225). PR без позначки `<!-- agents: ready -->` автозлиття не бере, а координатор пропускає картку x-traders, бо її змінює відкрита гілка. Чекали власника 5 днів.
- **`scripts/nightly_agents.sh`:** якщо останній прогін завершився `idle`, «stuck»-гілка (крім `-fix-`) паркується «на зараз» і продовжується як останній прогін (`MAX_RUNS`; `continue` заборонено). Таке повернення буває лише один раз: після другого `stuck` гілка чекає власника. CONTINUE-промпт просить здати схвалену критиком роботу як є. Перевірки доставки (lint, тести, CI, класифікація automerge) не змінились.
- **`scripts/gh_pr.py`:** коли PR гілки вже відкритий без позначки, а доставка готова (`--ready`), тіло й назва PR оновлюються (PATCH), тож `pr_watch.py` його зіллє. Раніше повторна доставка повертала старий непозначений PR.
- Тести: `tests/test_gh_pr.py`, `tests/test_nightly_revive_stuck.py`.
