# 2026-11-05 · Охоронець інваріанта 1: усі провайдери недоступні

Пункт 109 [постійної картки](../ideas/IDEA-20261102-standing-improvements.md).

- Новий `tests/test_tools_provider_outage.py`. Тест бере всі інструменти з `build_server()` і будує `Runtime`, у якого кожен HTTP-транспорт падає, а кожен виклик ccxt кидає помилку. Режимів два: HTTP 500 + `ExchangeNotAvailable` і таймаут (`ReadTimeout` + `RequestTimeout`). Кожен інструмент викликається один раз із мінімальними валідними аргументами, які тест бере з `inputSchema`. Перевірки: виклик не дає MCP-помилки, відповідь є конвертом, а інструмент, що звертався до провайдера, повертає `ok=false` або непорожній `missing`.
- Справжня мережа в тесті закрита: `httpx.AsyncHTTPTransport` підмінено, і будь-який запит повз фейкові транспорти тест рахує як провал. Coinalyze отримує фіктивний ключ, щоб запит дійшов до транспорту.
- Підсумок: перевірено 109 інструментів, пропущено 0 (`SKIP` порожній), відомих порушень 0 (`KNOWN` порожній). 63 зі 109 справді звертались до провайдера, решта працює офлайн (калькулятори, локальне сховище). Виправлень у `src/` не знадобилось.
- Чутливість тесту перевірено вручну. Якщо підмінити `Builder.guard` версією без перехоплення помилки, тест знаходить 62 порушення.
- Окрема знахідка, яка до збою провайдерів не стосується, записана в BACKLOG 6.18: `plan_add` з `expires_ts` у мілісекундах падає з `ValueError` у тексті своєї ж помилки валідації (`_iso`, рік поза діапазоном).
- Тривалість: близько 7 с на обидва режими (без xdist).
